# 问渠服务端设计（wenqu-server）

本文是 `wenqu-server` 的设计基线：说明目标形态、与现有实现的边界、数据模型、接口契约与分期范围。
参照一份成熟知识库平台的设计文档体系（架构、知识库机制、文档处理、请求队列）编写，不复制其代码。

## 一、目标与非目标

**目标**：以清晰分层重建服务端，形成"知识库为检索作用域"的平台形态，支撑多用户协作与多智能体问答。

**首期（MVP 内核）**：认证 → 知识库 → 文档导入解析 → 分块向量化 → 多路检索 → 重排 → 智能体问答（SSE 流式 + 引用）。

**明确不做**（参考平台存在但本产品无此需求，且其默认关闭）：
- 隔离沙盒与虚拟路径约束（依赖独立 provisioner）
- 知识图谱（依赖图数据库与 PPR 检索）
- 外部知识源连接器（Dify / Notion）
- 多后端 worker 租约体系（参考平台为多进程分布式设计，本产品单机内网部署，用进程内任务即可）
- 对象存储分离（MinIO）——本产品沿用本地文件系统 + 数据库元数据

## 二、与现有实现的边界

现有后端（`src/`，容器名 `wen-qu`）已上线运行，两套并行、共用同一业务库，便于逐项对比验证。

**可直接复用（已验证、按新分层搬迁）**：

| 能力 | 现状 |
| --- | --- |
| 权限模型 | `share_config` version 2：`read_scope` / `manage_scope`，`access_level` = global/department/user，**管理范围必须含于读取范围**；解析顺序 superadmin → 创建者 → manage → read → NONE —— 与参考平台权限设计一致 |
| 知识库模型 | 知识库 = 文档容器 + 检索作用域 + 检索参数归属；文档 `kb_id` 归属；智能体关联知识库 |
| 检索链路 | 向量 + 关键词加权和 → 相似度阈值 → 重排 → topK；检索参数优先级 全局 < 知识库 < 智能体 |
| 认证 | JWT（HS256 手写）+ PBKDF2 口令，无第三方加密库依赖 |
| SSE 流式 | 事件类型：stage / retrieved / subagent / token / image / done |

**需要新写**：分层重组、schema 独立演进、文档导入分步流程、知识库详情页接口、检索测试接口。

## 三、分层与模块边界

```
controller/   HTTP 边界：参数校验、鉴权上下文、响应装配，不含业务
service/      用例编排：文档导入、检索、问答链路、知识库管理
repository/   持久化边界：MyBatis-Plus Mapper，SQL 只出现在这里
model/ dto/   实体与传输对象
config/       基础设施装配：模型客户端、存储、鉴权、schema 演进
common/       统一响应、异常、通用工具
```

规则：
- 路由薄，用例在 service，查询在 repository。
- 检索与问答链路只依赖 service 组合，不把具体存储细节暴露给 controller。
- 检索参数与知识库配置的读取统一走一个配置服务，避免各处各自读表。

## 四、数据模型

沿用现有库（`ai_doc_assistant`），前缀 `c_ai_`，首期不迁表、只按需补列与补表。

| 表 | 作用 | 关键列 |
| --- | --- | --- |
| `c_ai_knowledge_base` | 知识库：文档容器 + 检索作用域 + 参数归属 | `query_params`(JSON)、`is_default`、`share_config`、`created_by` |
| `c_ai_document` | 文档 | `kb_id`（归属库，空=默认库）、`status`、`chunk_count`、`share_config` |
| `c_ai_knowledge` | 知识块（含向量引用、章节路径、图片占位） | `docId`、`chunkIndex`、`titlePath`、`content` |
| `c_ai_agent` | 智能体 | `knowledge_base_ids`、`system_prompt`、`query_params`、工具三态开关 |
| `c_ai_session` / `c_ai_message` | 会话与消息 | 多轮记忆、引用与用量落库 |
| `c_ai_user` / `c_ai_department` | 用户与部门 | 可见性解析输入 |

引用设计要点：
- **默认库兜底**：`kb_id` 为空视为归入默认库；查库内文档时若含默认库需并上 `kb_id IS NULL` 的文档，否则历史文档会整体检索不到。
- **配置继承**：`query_params` 为空 = 继承上层；只允许检索/重排类键，白名单外一律丢弃并告警。
- **清空语义**：所有"清空 / 恢复继承"的更新必须显式 `set` 目标列为 `null`（框架默认更新策略会跳过 null 列，导致静默失效）。

## 五、接口契约（首期）

统一响应：`{success, code, msg, data}`。鉴权：除登录外一律 `Authorization: Bearer`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/ai/auth/login` | 登录换取令牌 |
| GET | `/api/ai/kb/list` | 知识库列表（含文档数） |
| POST/PUT/DELETE | `/api/ai/kb` `/api/ai/kb/{id}` | 知识库增删改（默认库与含文档的库禁删） |
| PUT | `/api/ai/kb/doc/{docId}` | 文档归属切换（`kbId` 空 = 回默认库） |
| POST | `/api/ai/document/upload` | 上传并建立文件记录（不解析） |
| POST | `/api/ai/document/{id}/parse` | 解析为 Markdown/纯文本 |
| POST | `/api/ai/document/{id}/index` | 分块 + 向量化 + 关键词索引 |
| GET | `/api/ai/document/list` | 文档列表（含 `kbId`） |
| POST | `/api/ai/kb/{id}/retrieve` | **检索测试**：直接返回片段与分数（不经过问答） |
| POST | `/api/ai/chat` | 问答（SSE 流式，含引用与用量） |

导入采用**分步**（上传 → 解析 → 索引），每步可回读状态确认；与参考平台的"状态可回读、解析不等于索引完成"一致。

## 六、检索链路

```
问题 → 范围解析（可见文档 ∩ 知识库文档 ∩ 智能体细选）
     → 向量召回 ‖ 关键词召回（并行）
     → 加权和融合 → 相似度阈值过滤 → 重排 → topK
     → 上下文填充（预算控制、图片占位、引用编号）
     → 流式生成（引用可追溯）
```

不变式：
- 检索参数优先级 **全局 < 知识库 < 智能体**，后者覆盖前者。
- 知识库配错 ID 得到空集合、结果为空，**不退化为全库**（避免配置错误静默放宽范围）。
- 无命中不标注"非知识库依据"、不特殊提示，交由模型自行判断（与参考平台一致）。

## 七、分期

| 期 | 内容 | 验收 |
| --- | --- | --- |
| 1（当前） | 骨架 + 认证 + 知识库 CRUD + 文档归属 + 检索测试接口 | 能建库、归文档、按库检索出片段 |
| 2 | 文档导入分步流程（上传/解析/索引）+ 分块策略预设与参数快照 | 上传文档后可回读状态为 indexed |
| 3 | 问答链路（SSE + 引用 + 用量） | 提问得到带引用的回答；跨库不串 |
| 4 | 智能体关联知识库 + 工具调用过程展示 | 配置页选库；对话页展示工具调用 |

## 八、验证要求

- 每期结束：编译通过、接口实测（真实 HTTP + 回读数据），不以"日志打印了"作为通过依据。
- 检索相关改动：用评测集对比前后分数，避免"按下葫芦起瓢"。
- 数据迁移类改动：先备份、可回退，并核对迁移后的可见范围。
