01

现状：一次站点交付，被拆成了 9 行附件

问题的根不在「文件行太高」，而在交付单位错了：系统只有单个 artifact，没有「交付包」这个概念。 于是模型只能把 9 个文件逐条陈列，界面也只能逐条渲染；用户看到的是一份文件清单，而不是一个可打开、可验收的站点。

ISSUE 01

清单淹没了结论

9 行附件在回答末尾平铺，占掉约三分之一屏。用户真正需要的「做完了没有、从哪打开」被压到最上面一行正文里，滚两下就看不见了。

ISSUE 02

同一批文件说了两遍

正文表格逐页说明 6 个页面，下面附件区又把 9 个文件各列一行。两份清单信息重叠却不互补：表格有「每页内容」，卡片只有文件名。

ISSUE 03

没有「交付包」对象

数据层只有 artifact，没有 bundle、入口、版本、验收。界面无法回答「这是一个站点还是 9 个散件」——用户只能自己拼。

ISSUE 04

没有「打开站点」

交付的是多页站点，主行动却只能是单件预览。index.html 的 CSS/页面引用是相对路径，单独预览还会断，站点根本跑不起来。

ISSUE 05

验收成本 18 次点击

9 件 ×（预览 + 下载）= 18 次点击。批量 ZIP 在「我的产物」页已有接口，聊天里的交付现场却拿不到。

ISSUE 06

过程件与交付件同权

favicon.svg、robots.txt、sitemap.xml 与 6 个页面同排同色。哪些是「打开站点的入口」，哪些是「站点配套」，用户分不出来。

ISSUE 07

交付状态缺失

目标还在跑，文件就一条条长出来；目标失败或取消后，这些文件卡仍留在回答里，没有任何「算不算数、验没验收」的标记。

ISSUE 08

移动端更糟

一行文件名加两个常驻链接，长文件名被挤成省略号，触屏热区又小；9 行清单在手机上要滑一整屏。

02

目标与原则

这次改版只解决一件事：让「目标做完了」这件事在界面上成立。文件下载仍然要做，但它是验收之后的二级动作，不是交付本身。

1

一张卡

对话里每组交付只留一张卡，任何轮次都不再逐条铺文件。

3

三个问题

卡片按顺序回答：这是什么、从哪打开、验收过没有。

0

零重复

正文只管结论与验收口径，文件清单只出现在交付卡与抽屉里。

2

两处常驻

目标条与终态卡都给「产出 N 件」入口，换轮、刷新都不丢。

P1
交付单位是包，不是文件

一个目标产出的一组文件 = 一个交付包（有名字、版本、入口、验收状态）。单个文件只是包内条目。

P2
对话里只留一张交付卡

默认展示主入口 + 验收 + 前两件文件；其余折叠成「查看全部 N 件」。不再每行挂两个常驻动作。

P3
主入口优先于下载

站点/应用先给「打开站点」；文档包先给「打开主文档」。下载是第二步，放在同一行但不做主按钮。

P4
验收先于清单

先给「页面可达 / 断链 / 移动视口」这类可核对的结论，再让用户去翻文件。未验收就说未验收。

P5
逐件动作退到 hover

预览/下载仍在，但只在行悬停（移动端常驻）出现；批量 ZIP 才是主行动。

P6
过程产物默认折叠且标灰

favicon / robots / sitemap 这类配套文件归入「站点文件」组，默认收起，不和入口页平权。

03

四个方案：从「压缩列表」到「交付包 + 验收面」

前两个方案不用动数据，第三个要补一点交付包元数据，第四个是反向方案（把交付搬离对话）。 推荐 方案 C，但按 P0 → P1 → P2 分期落地：P0 纯前端就能拿到 80% 的体验。

方案 对话内呈现 清单落点 主行动 成本 结论
A 压缩清单 行高变矮、超过 3 件折叠成「共 9 个文件」 点开仍在气泡内展开 预览第一件 低 治标：重复表达与验收缺失都还在
B 交付卡 + 抽屉 一张交付卡，折叠前两件 PC 右抽屉 / H5 底部 sheet 打开第一件 中 可用：解决了重复与清单淹没，但「站点」仍没有被当成一个包
C 交付包 + 验收面 一张交付卡：包名 / 版本 / 入口 / 验收 / 折叠清单 交付抽屉：分组清单 + 批量 ZIP + 版本 打开站点（主入口） 中高（需少量后端补口） 推荐：交付语义完整，可分三期
D 全部搬去「我的产物」 对话里不显示产物，只留一句「已交付」 离开对话去 /artifacts 翻 打开产物页 中 不推荐：断了「目标—交付」的上下文，验收变成考古
为什么不是 A：截图里真正刺眼的是「表格 + 9 行清单」这份重复，而不是行高。 为什么不是 D：目标模式的价值就是「我说目标、它交付、我在原地验收」，把人赶去另一个页面等于放弃这条链路。
04

信息架构：一个包、一张卡、一个抽屉、两处常驻入口

所有入口都指向同一个交付包实体，避免「每轮一份、刷新即丢」。对话内的卡是摘要，抽屉是事实面，目标条与终态卡是索引。

1 对话内 · 交付卡
包名 + 版本 + 验收徽标 / 主入口缩略图 + 一句话 / 验收 chips / 打开站点 + 下载 ZIP + 查看全部 / 折叠清单（入口 + 前 1 件 + 其余 N 件）
2 交付抽屉（PC 右侧 400px / H5 底部 sheet）
入口卡（打开站点）/ 验收清单 / 按角色分组文件 / 每行悬停预览·下载 / 底部 下载全部 ZIP · 保存到我的产物
3 目标条第三行
第 N 轮 · 细进度 · 产出 9 件 › · 查看过程
4 终态卡（挂在「设为目标」的问答下）
已交付 9 件 / 已验收 3 项 · 查看交付 · 重新设定目标 · 删除记录
5 数据来源
P0 用「消息 artifacts + goal turnId」在前端聚合；P1 由后端在目标视图给出 deliverables（包名 / 入口 / 版本 / 验收）；单个 artifact 仍是下载与预览的最小单位。

07

状态矩阵与文案

交付的每个状态都必须说清楚「这堆文件算不算数」。状态词只允许六个：正在产出 / 已交付 / 未验收 / 未完成 / 已取消 / 已替换。

目标状态 交付卡头部 主行动 清单 目标条 / 终态卡
RUNNING · 已产出 3 件 「正在产出 · 3 件」＋细进度 打开已产出页面（逐件预览） 只露已产出的，按生成顺序 产出 3 件（数字随 SSE 增长）
ACHIEVED · 已验收 「已交付 · 9 件」＋已验收徽标 打开站点 入口 + 前 1 件，其余折叠 产出 9 件 · 查看交付
RUNNING 但验收未跑 「已产出 · 6 件」＋未验收徽标 打开已产出页面 全量但标灰未验收 产出 6 件 · 未验收
FAILED / 中断 「部分交付 · 6 件」＋未验收（黄） 打开已产出页面 + 下载已产出 分组，缺失项显式说明 产出 6 件 · 继续目标
CANCELLED 「已取消 · 保留 6 件」＋未验收 打开已产出页面 全量；标注「目标已取消」 终态卡：保留交付 6 件
重新交付 v2 「已交付 · 9 件」＋v2 打开站点（默认最新） 可切 v1 / v2，旧版不删 产出 9 件 · v2
零产出 不出现交付卡 — — 产出 0 件（置灰，不可点）

模型侧交付话术（治「重复表达」的根）

清单由界面承担，回答正文只写验收结论；这是提示词约束，不靠前端去重。

应该这样收尾：「站点已交付：6 个页面可打开，断链 0，移动视口通过；入口 index.html。sitemap 的域名占位需替换后发布。」
不要再这样：把 6 个页面的表格 + 9 个文件的清单逐条写进回答正文。文件清单交给交付卡与抽屉，回答只说「做了什么、验了什么、还差什么」。

10

拍板项

下面七条是这份方案的决策边界；拍板后按 P0 → P1 → P2 实施。默认全部按推荐项走。

D1 · 交付单位

以「交付包」为单位，不以文件为单位

一个目标产出的一组文件归一个包：有包名、入口、版本、验收状态。单文件仍是下载与预览的最小单位。

推荐：交付包（支持整站/文档集/单文件三种形态）
备选：仍以文件为单位，只压缩列表
D2 · 对话内呈现

一张交付卡，折叠清单最多露两件

卡内顺序固定：包名与验收 → 主入口 → 操作 → 折叠清单。超过两件一律折叠，不在气泡里展开全量。

推荐：卡 + 折叠（入口与下一件）
备选：卡内全量清单（移动端会更长）
D3 · 清单落点

PC 右抽屉 / H5 底部 sheet，复用目标过程抽屉

不新开页面、不跳 /artifacts；关掉回到原位。抽屉里才给分组、批量、复制链接与定位轮次。

推荐：抽屉 / sheet
备选：新页面（会丢上下文）
D4 · 主行动

站点/应用给「打开站点」，文档集给「打开主文档」

主按钮永远指向入口，不指向下载。下载 ZIP 同级但次级；逐件动作退到 hover（移动端常驻热区）。

推荐：入口优先
备选：下载优先（适合纯素材包）
D5 · 过程件

站点配套文件归组、默认折叠、标灰

favicon / robots / sitemap 永远是「站点文件」组；展开后仍可预览下载，但不与入口页同权。

推荐：分组折叠
备选：平铺（回到截图的老问题）
D6 · 目标层

目标条与终态卡常驻「产出 N 件」

进行中数字随产出增长；终态卡给「查看交付」。不依赖某一条回答是否还在可视区。

推荐：两处入口
备选：只放对话卡
D7 · 模型话术

回答正文不逐条罗列文件，只写验收结论

清单交给界面；正文收尾只回答「做了什么、验了什么、还差什么」。这是提示词约束，不做前端去重修补。

推荐：写进目标模式的交付提示词
备选：保留表格，由前端隐藏重复清单
11

验收清单

P0 落地后逐条核对；P2 的整站预览与验收检查单独验。

  • 一个包一张卡：同一目标的 9 个文件在对话里只出现一张交付卡，不再逐行平铺。
  • 正文零重复：回答正文不出现完整文件清单；表格若保留，只说页面分工，不逐文件列名。
  • 主入口可用：「打开站点」指向包内入口；P0 阶段明确单页预览的边界提示。
  • 折叠正确：清单默认只露两件；展开后行悬停才出现预览/下载；移动端热区 ≥40px。
  • 抽屉完整：分组、验收、批量 ZIP、复制链接、定位轮次全部可用；Esc / 下滑可关。
  • 目标层常驻：目标条与终态卡都有「产出 N 件」；刷新、切换会话、重跑后仍指向当前包。
  • 状态诚实：未完成/已取消显示「未验收」，已交付显示「已验收」；不把未验收说成完成。
  • 零产出不显示：目标尚未产出时不出现空交付卡；目标条「产出 0 件」置灰不可点。
  • 无回归：非目标模式的普通问答、分享页的产物列表、/artifacts 批量下载行为不变。
  • 可访问：交付卡可用键盘走完；状态不只靠颜色区分；图标按钮有 aria-label。
拍板后我按 P0（前端可先上）→ P1（包元数据）→ P2（整站预览与验收） 实施。 P0 上线即可消除截图里的重复清单与「只能逐件下载」两个最刺眼的问题；P2 才真正兑现「交付一个站点」。
