# UI/UX 基线（2026 Q4）

> 背景：工作区页首版是**自研无蓝本**做的，验收时被指出「这看着就是会话分类」，追查后又发现 UI 上有多处脱离体系的地方
> （侧栏用了全仓唯一的原生 `<select>`、自定义类里硬编码 `8px`/`11px`）。本文档确定蓝本、记录借了什么、没借什么。

## 一、蓝本

**结构蓝本：[deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)（MIT License, Copyright (c) 2026 DeepSeek）**

选它的理由：
1. 同品类（会话 / 侧栏 / 工具卡 / 沙盒执行 / 审批），交互结构可直接对照；
2. 有成熟的**两层设计令牌**：`--dsw-static-*`（原始色阶）→ `--dsw-alias-*`（语义：label / bg-layer / border-l1..l4 / interactive / elevation）；
3. MIT：可复制、修改、商用，保留版权声明即可。

**不采用的两类蓝本**：
- **Dify**：许可证明确写明 *The interactive design of this product is protected by appearance patent*（交互设计受外观专利保护），界面不可照抄；
- **Ant Design Pro / pro-layout**：页面范式可参考，但它是整套外壳，替换成本远大于收益。

## 二、借了什么（只借结构，不搬皮）

| 借的东西 | 落点 | 说明 |
|---|---|---|
| **两层令牌**（静态值 → 语义名） | `web/src/views/app.css` 新增语义别名层 | 新增 `--app-label-primary/secondary/tertiary`、`--app-bg-layer-1/2/3`、`--app-border-l1/l2`、`--app-interactive-hover`；**全部由现有 `--app-*` 派生，配色不变、现有页面零改动** |
| **控件高度档位** | `--app-control-h-sm/-h/-lg`（26/32/38px） | 统一「多高算小/标准/大」，别再各处写死 padding |
| **语义化用色** | 工作区页（`ProjectPage.vue`） | 由 `--app-text3` 改为 `--app-label-tertiary` 等，按意图取色 |
| **焦点可见** | 检查结论：`app.css` 早已有 `:focus-visible { outline: 2px solid var(--app-accent) }`（历史审计 P1-13） | 本轮验证 Tab 可达且焦点环可见，未新增 |
| **空态带操作** | 工作区页 | 「还没有对话 → **新建一条对话**」「还没有文件 → **去对话**」，空态不再只是说明文字 |
| **首屏骨架** | 工作区页 | 首次加载无内容时显示 `a-skeleton`，不再是一片空白 |

## 三、没借什么（明确边界）

- **配色与视觉风格**：仍是问渠的蓝（`#2e6be6`），不搬 DSH 的深色/品牌色，避免看起来像 DSH 换皮；
- **组件实现**：DSH 前端是框架无关的自研渲染层（`ui-renderer` / `ui-primitives` / `ui-slots`），不是 Vue 组件，搬不进本仓库；
- **品牌资产**：不复制其 logo / 名称 / 品牌字体（Montserrat 为 OFL，商用需带许可文件）。

## 四、本轮改掉的不一致

| 问题 | 现状 |

## 七、工作区信息架构重构（2026-10-17）

首版工作区页是**五张卡竖直堆到底**：约定 / 会话+产物 / 文件 / 定时任务 / 工作流。工作区一有内容就变成一条长页，
"这个工作区里有什么"要靠滚动才知道。改成：

> **诚实标注**：下面这套 IA（概览条 / 引导卡 / 折叠设置 / 四分区标签页）是**按通用后台范式自拟的，不是抄 DSH**。
> 核对过 `packages/client/ui-workspace` 后确认：DSH 把工作区当作**侧栏里的一组会话**（add/rename/reorder/delete、
> 折叠 5 条 + Show more、定时任务时钟标记、待处理警告点），**没有"工作区详情页"**。真正可抄的是侧栏那套，见 §八。


```
页头：名称 + 类型标签 + 刷新/保存
概览条：会话 N · 产物 N · 文件 N · 自动化 N + 工作目录路径（点数字直接切到对应分区）
空工作区引导：① 写工作区约定 → ② 开一条对话 → ③ 让它产出文件（仅在真的一无所有时出现）
工作区设置（默认折叠，已配置时摘要"约定：…"；未配置时自动展开）
危险区：删除工作区（只摘归属，会话与产物保留）+ 二次确认
内容分区（标签页）：会话 / 产物 / 文件 / 自动化（定时任务 + 工作流同区）
```

### 为什么这么改

| 决策 | 理由 |
|---|---|
| 概览条可点击 | 先看数量再决定去哪，比"先滚到底再回来"少两次操作 |
| 设置默认折叠 | 约定写一次就不常改；展开后占据半屏，长期用户每次进来都被它挡 |
| 未配置时自动展开 | 第一次进来最该做的事就是写约定，不能让它藏在折叠里 |
| 自动化合并一区 | 定时任务与工作流解决的是同一件事（让它自己跑），没必要并列两卡 |
| 删除放在设置里 | 破坏性操作不该出现在侧栏筛选器旁边；放在这里离"工作区本身"最近，且有二次确认 |

### 验证证据（真机 Edge）

- 概览条：`0 会话 / 0 产物 / 0 文件 / 0 自动化` + 工作目录路径；
- 空工作区引导：三步标题「写工作区约定 / 开一条对话 / 让它产出文件」，**仅空工作区出现**；
- 设置：未写约定时**自动展开**；点击标题可折叠，折叠后显示摘要「工作区设置 / 未设置约定」；
- 分区：四个标签页 `会话 0 / 产物 0 / 文件 0 / 自动化 0`，点击可切换（验证切到"文件"后 `ant-tabs-tab-active` 为「文件 0」）；
- 删除：弹二次确认（按钮为「取 消 / 删 除」），确认后**跳回对话页**，后端返回 `{"code":400,"msg":"工作区不存在或已删除"}`；
- 窄屏 390×820：`scrollWidth = 390 = innerWidth`，**无横向溢出**；
- 控制台 **0 报错**；Java 全量测试 **81 项 0 失败**。

### 验证时踩到的两个坑（写下来免得下次再浪费时间）

1. **Ant Design 会给两个汉字的按钮插空格**：`取消` 实际文本是 `取 消`，用 `hasText: '取消'` 匹配不到。
   断言时应使用 `/取\s*消/` 这类正则，或直接点位置。
2. **`.count()` 不看可见性**：弹窗关闭后元素从 DOM 移除才会是 0；如果只是隐藏，应断言 `isVisible()`。
   我第一版断言写错，误报"取消按钮无效"，查证后确认是测试问题，不是产品问题。

## 八、侧栏按 DSH 的 workspace 模型补齐（方案 A，2026-10-17）

> **2026-10-17 后续**：本节的工作区选择器 + 时间分组已被 §十 的「会话 / 工作区」树替换；
> 这里保留的是当时「先补 add/rename/delete」的决策记录，不代表当前界面。

### 8.1 先纠正两处我此前的错判

1. **「问渠没有单行操作菜单」是错的**：侧栏行尾的「⋯」早就有菜单（重命名 / 收藏 / 导出 / 分享 / 批量 / 删除），
   我上一次没细看就当成缺口列出来了。
2. **「工作区页参照 DSH 的分区结构」也是错的**（已在 §七 更正）：DSH 的工作区是**侧栏里的一组会话**，没有工作区详情页。

### 8.2 真正抄来的三处（对照 `packages/client/ui-workspace`）

| DSH 的做法 | 问渠落地 |
|---|---|
| 一个工作区默认铺 **5 条**会话，「Show more」每次再放 5 条 | 侧栏默认 **5 条**；「显示更多 (剩余数)」每次 **+5**；本地铺满后自动拉下一页；「收起」回 5 条 |
| 有启用定时任务的会话行显示**时钟标记**，悬停列出任务 | 行内时钟图标 + tooltip（任务名 + cron + 启停状态），数据来自 `listScheduledJobs()` 按 `sessionId` 建索引 |
| 工作区可 **add / rename / 删除**（都在侧栏完成） | 工作区选择器旁的齿轮改为**下拉菜单**：新建工作区（弹窗，建完直接进工作区页写约定）/ 打开工作区页 / 重命名（弹窗）/ 删除（二次确认）；兜底容器不允许改名或删除 |

### 8.3 没抄的部分（有意）

- DSH 的「工作区 = 目录选择器绑定」模型：问渠的工作区目录由平台托管（`projects/{id}`），不暴露宿主目录选择；
- 拖动排序（reorder）：问渠工作区数量少，排序收益低，暂不做；
- 待处理交互警告点：问渠的待办在会话内呈现，侧栏暂不加第二个提示渠道。

### 8.4 真机验证证据

| 断言 | 结果 |
|---|---|
| 默认只铺 5 条 | `.sess-item` = **5** |
| 「显示更多 (182)」点击 +5 | 点击后 `.sess-item` = **10** |
| 时钟标记 | 给一条真实会话挂上启用中的定时任务后，`.sess-clock-flag` = **1** |
| 工作区菜单 | 展开为 **新建工作区 / 打开工作区页 / 重命名 / 删除工作区** 四项 |
| 重命名 | 弹窗保存后选择器显示「侧栏验收工作区-已改名」 |
| 删除 | 二次确认 → 删除后下拉只剩 全部工作区 / 兜底容器 / 没挂工作区 |
| 控制台 | **0 报错** |

### 8.5 过程中的两个实现坑

1. **命名撞车**：新写的 `doRename`（工作区重命名）与会话重命名的既有 `doRename` 重名，构建直接报
   `Identifier 'doRename' has already been declared`；改名 `doRenameProject` 解决。
2. **dev server 起错目录**：用 `npx --prefix web vite` 启动时 root 不在 `web/`，`/chat` 返回 404；
   必须在 `web/` 目录内启动。

### 8.6 补记：新建工作区入口（用户指出后补上）

第一版只做了 rename / 删除，**漏了 add** —— 建工作区只能去「我的产物」页。DSH 的 workspace 是 add/rename/delete 三件齐全的，
这是照抄时漏掉的一条。现已补：

- 菜单首项「新建工作区」+ 分隔线（`PlusOutlined` 与会话「新建对话」共用，曾因重复 import 构建失败一次）；
- 弹窗只有名称一个字段，附一句「创建后会进入它的工作区页」；
- 创建成功后：刷新工作区列表 → 选中新工作区 → **直接跳到 `/project/{id}`**（那里有"三步用起来"引导）；
- 真机验证：菜单四项齐全；建「侧栏新建验收」后 URL 变为 `/project/58fee91b…`、页面标题为该名、引导卡出现、
  侧栏下拉可选到它、控制台 0 报错。

## 九、工作区补全（2026-10-17）

- **概览条数字用 `total`**：列表接口只回首页 50 条，统计必须取 `sr.data.total`，否则 187 会显示成 50。
- **最近活动**：`recentActivity` 由已加载数据合并（会话 updateTime / 产物 createTime / 文件 mtime / 定时 lastRunAt），

- **搜索**：页头单个输入框，命中会话标题 / 产物文件名 / 文件名与路径；空态文案区分「还没有」与「没有匹配」。

- 仍保持结构蓝本（DSH 的两层 token / 控件高度档位）不变，视觉仍是问渠自己的蓝。

## 十、侧栏会话区重构：会话 / 工作区（2026-10-17）

### 10.1 为什么再改

用户指出旧侧栏（搜索框 + 「全部工作区」下拉 + 「今天 196」时间分组 + 底部「显示更多 (191)」）"UI 和 UX 太低级"，
并给出基准：顶部「任务 (0) / 暂无任务」、下面「工作区 (2)」、每个工作区下 4 条会话 + 「查看更多 (140)」。
经确认，基准里的「任务」**不是定时任务**，而是**不属于任何工作区的会话**；也可叫「会话」。

### 10.2 落地映射

| 基准 | 问渠 | 说明 |
|---|---|---|
| 任务 / 会话 (N) | 不属于任何真实工作区的会话 | 真没挂工作区（`project_id IS NULL`）+ implicit 兜底容器（后端 `__nospace__`）；兜底容器不再单列 |
| 工作区 (N) | 用户自建工作区 | 只列用户显式创建的工作区；已归档单独折叠 |
| 工作区名 + 图标 | 工作区 `displayName` + 文件夹图标 | 点工作区名进工作区页；行尾箭头折叠 |
| 工作区下 4 条 + 查看更多 (N) | 每工作区首屏 4 条 + 剩余条数 | N = 该空间总数 − 已加载；展开后可「收起」 |
| — | 顶部「新建对话」不挂工作区 | `/session/new?projectId=__none__`，后端显式置 `project_id=NULL`，落进顶部「会话」；只有工作区行 `+` / 工作区页新建才带真实 `projectId` |
| — | 搜索、批量管理、置顶/分享/时钟标记 | 原有能力全部保留 |

### 10.3 数据取数（关键决策）

- 不能只拉一页全局会话再按 `projectId` 分桶：最近 20 条可能全在兜底容器，其它工作区会显示成空的。
- 改为**每个工作区一次 `GET /sessions?projectId=…&size=4`**；计数用响应里的 `total`（全量、仅含有消息的会话）。
- 顶部「会话」用 `projectId=__nospace__`：后端把真没挂工作区 + 该用户 implicit 兜底容器并进同一个过滤（`SessionService.NO_SPACE_PROJECT` + `ProjectService.implicitIdOf`），避免前端拉两次再合并分页。
- 工作区接口不可用时退化成「全部会话」一个分组，不把整栏打死。
- 每个工作区保留首屏快照（`firstItems` / 首游标），「收起」不重新请求；「查看更多」按游标追加。
- 会话行时钟标记仍走 `/scheduled/list`，但**不再有「任务」分区**——用户明确纠正过。
- 兜底容器仍是后端的**历史兜底容器**（老会话、旧客户端、`ensureSession` 仍会落到这里），但不再是新 UI「新建对话」的落点：前端传 `__none__`，`SessionService.NO_PROJECT` 显式返回 null，后端不再兜底 implicit。
- 空会话复用时也会把 `project_id` 改成目标值（含 null），否则「领走」一条旧空会话会把它原来的工作区带进新对话。
- 侧栏不再渲染「对话」菜单：`/chat` 路由保留，作为新建/选会话的落点；`c_ai_menu` 行仍留在 RBAC 表里（承载 Chat 接口归属），只把该行 `visible` 置 0——服务端 `visibleMenusFor` 按 `visible=1` 过滤，前端不为某个路径开硬过滤例外。恢复显示走「权限管理 → 编辑菜单 → 对话 → 可见」，不需要改代码；存量库对齐用 `scripts/db/hide-chat-menu-2026-10-17.sql`，新装库由 `RbacSeedRunner.BUILTIN_MENUS` 第 6 列直接种成 0。

### 10.4 视觉

- 侧栏 200 → 232px：工作区行要放下「图标 + 名字 + ⋯ + 新建对话」。
- 分区头：11px/600、计数 `(N)` 紧随其后；工作区头 20px 圆角图标 + 12.5px/500 名字，**点名字展开/收起**（图标随状态换成打开的文件夹），右侧 `⋯` + `+`（新建对话）常显、悬停提亮。
- 会话行缩进 33px（与工作区名左缘对齐），行高 27px；「查看更多 (N)」同缩进、次级色。
- 空态左对齐缩进，不再在侧栏中央放一行灰字。
- 导航行距 7→6px、gap 2→1，为会话树让出约 40px 首屏高度（800px 窗口下能看到第一个工作区的 3 条会话）。

### 10.5 行为与坑

- 顶部「新建对话」不挂工作区（`__none__`），会话出现在顶部「会话」；工作区行右侧的 `+` 把该工作区 `projectId` 传给 `newSession()`；工作区页新建同样带 `projectId`。
- 侧栏菜单首项就是「新建对话」，不再有单独的「对话」项；`/chat` 无 sid 时「新建对话」高亮。
- 工作区页的「新建对话」原先用 `window.location.href = '/chat?projectId=…'`：整页刷新丢掉模块级落点，

## 十二、工作区页去重：同一批数据不再「数两遍、列两遍」（2026-10-17）

用户拿首屏截图点名三块红框：概览条 `8 会话 / 3 产物 / 2 文件 / 0 自动化`、「最近活动」时间线、
下方标签页 `会话 8 / 产物 3 / 文件 2 / 自动化 0`。核对代码后确认**重复有四处，其中两处是结构性的**：

| 重复 | 成因 | 处置 |
|---|---|---|
| 概览条四个数字 ≡ 标签页四个计数 | 同一批 computed 表达式在模板里写了两遍 | 概览条整体删，计数只留在标签页上 |
| 「最近活动」≡ 三个标签页的行 | `recentActivity` 纯派生（会话/产物/文件/定时按时间合并取前 8），原料就是下面的列表；且会话只拉首页 50 条 → **零新增信息 + 本身不完整** | 整块删 |
| 「产物」≡「文件」 | `deliver_artifact` 把沙盒工作目录里的文件**复制**进产物库（`SandboxTools.deliver_artifact`），同名同内容 → 同一个文件在两个 tab 各列一次 | 合成一个「文件」区：工作目录文件 ∪ 产物按文件名去重，交付过的打「已交付」角标；**后端零改动** |
| 三步引导卡第 1 步「去填写约定」 | 约定卡就显示在它上面 | 引导卡整体删，约定卡自己承担空态 |

### 骨架（改后）

```
页头：工作区名 + 默认/已归档标签 + 一句定位说明 ｜ 搜索 · 刷新 · 新建对话
① 工作区约定（常驻）  已配置 = 只读原文 +「编辑」；未配置 = 直接给输入框；保存在卡内
② 工作区设置（折叠一行）名称 · 默认助手 · 工作目录（带复制）· 归档 · 删除
③ 标签页           文件（产物并入）/ 会话 / 自动化（定时任务 + 工作流）
```

### 为什么这么排

| 决策 | 理由 |
|---|---|
| 约定升格为常驻卡，不再折叠 | §七 把它折进「工作区设置」是错的：约定是**这个工作区区别于「一堆会话」的唯一理由**，属于主路径；按折叠口径该折的是助手/名称/目录/删除 |
| 已配置时先读后编 | 长期用户不该每次进来都对着一个 textarea；读态保留换行原样，超 120 字夹三行 +「展开全文」 |
| 保存动作从页头搬进卡内 | 原来改完约定要去页头最右找「保存设置」，字段与动作分处两地，且没有任何「未保存」提示 |
| 默认落点 = 文件（有才落，无则会话） | 文件与产物是这个页的**独占视图**（侧栏只有会话）；空工作区则把「新建对话」的会话空态摆在眼前。只在首次加载决定，刷新不抢用户已切的 tab |
| 工作目录收进「工作区设置」 | `projects/<uuid>` 是内部机制，摊在首屏既无意义又泄露实现；需要时展开 + 一键复制 |
| 归档跟着退到设置里 | 页头三个动作（搜索/刷新/新建对话）已经够挤；归档是低频状态变更，侧栏工作区菜单里也有一份 |

### 顺带修掉的四个缺陷

1. **搜索漏两类**：`kw` 此前只过滤会话/产物/文件/活动，**定时任务与工作流完全没接**——搜任务名是一片空白，读起来像"我的任务没了"。现在五类都过滤。
2. **绝对日期分不出先后**：同一天里 8 条全是 `2026-10-17 13:3x`。列表时间改相对（刚刚 / N 分钟前 / N 小时前 / N 天前，超过 7 天回退绝对）；定时任务的「下次」仍用绝对时间。
3. **点了没反应**：概览条是可点卡片但**没有选中态**，点下去只切了下方的 tab，看着像坏了。删掉即消。
4. **列不对齐**：角标缺位的行会把「大小 / 时间」整列拽偏。角标改占固定宽（`.pj-badge-cell`）。

### 验证（Playwright + Edge headless 1280×800，真后端 8090 / dev 5800）

| 断言 | 结果 |
|---|---|
| 三块重复退场 | `.pj-stats` = **0**；页面无「最近活动」；无三步引导卡；页头无「保存设置」 |
| 标签页 | `文件 3 / 会话 8 / 自动化 0`（计数只出现一次） |
| 产物并入文件去重 | 后端原始数据 **产物 3 + 文件 2** → 页面 **3 行**，同名 `attendance-policy.md` 只出现一次，「已交付」角标 **2 个** |
