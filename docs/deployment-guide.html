0架构与组件总览

浏览器 │ HTTP :80 ▼ Nginx（宿主安装） ├── / 静态：/var/www/wenqu（前端 dist） └── /api/ai/* 反代：127.0.0.1:8090/ai/api/ai/*（后端） │ Docker Compose（四件套，同一容器网络） ├── app 问渠后端（Java 17，宿主仅绑 127.0.0.1:8090） ├── mysql:8.4 业务数据（仅容器网络，无宿主端口） ├── redis-stack 向量索引/广播/限流（宿主 6380 → 容器 6379） └── meilisearch 关键词引擎（可选，宿主 7700）

100 并发容量参数（8C16G 机器口径，2026-10-07 压测验收）

面向「100 人同时各有一路流式生成」的参数已在 compose 默认值收口；小机器按比例下调。压测工具： scripts/loadtest/（mock 网关 + 三阶段验收，100 独立用户实测 100/100 零拒绝， 首字 TTFB p50≈8s / p95≈13s——其中约 5s 是本机 MySQL LIKE 检索，生产切 Meilisearch 后更低）。

参数当前值说明
JVM 堆 JAVA_OPTS-Xms512m -Xmx6g16G 单机全家桶预算：app 堆 6g + MySQL≈2g + Meili≈1g + Redis≈1g；app 容器 mem_limit 8g
问答流水线 chat.pipelineThreads32（设置页可热调）队列 200；满时 fail-loud「系统繁忙」而非排队雪崩。深度思考并发高时可上调 64~128
辅助池（改写/压缩/多路检索）随 pipelineThreads 联动改写 = n/2、压缩 = n/4、多路检索 = n，无需单独配置
MySQL 连接池（Hikari）DB_POOL_MAX=40MySQL 侧 max_connections=500（compose 已配）配套
Redis 连接池（Jedis）REDIS_POOL_MAX=64等待 2s 快速失败；默认 8 连接 + 无限等待在小池满时会拖住 Tomcat
boundedElastic（工具执行）128askUser 等待 / 审批 / 沙盒等阻塞工具占用此池，每线程 ≈1MB 栈
整轮机器耗时预算 chat.sseTimeoutMs300000（设置页可调）人工等待（askUser/审批）不计入；心跳 15s 保活，nginx 需 buffering off + 超时 ≥ 预算
askUser 等待窗口 chat.askTimeoutMs600000（设置页可调）提问卡跨页面可恢复；超时不代答
同会话并发互斥同一会话同时只跑一轮，第二问明确提示「上一轮还在回答中」
多副本扩展暂不支持审批/提问/产物推送为进程内存态，多副本需先做粘性路由与跨副本回调

部署前清单

  • 服务器：4 核 4GB / 60GB SSD / 带宽 ≥ 4Mbps（2C2G 机器见附录「精简部署」）
  • 系统：Ubuntu 24.04 LTS；安全组 / 防火墙放行 22（SSH）与 80（Web）
  • 代码：待部署提交已推送到 GitHub（服务器以 git clone 拉取，部署的是 master 最新提交）
  • 可选：域名（境内服务器绑定域名需 ICP 备案；纯 IP 访问不需要）

1服务器基础环境

# 登录服务器（腾讯云轻量 Ubuntu 镜像默认用户 ubuntu）
ssh ubuntu@<公网IP>

# 时区（定时任务与统计按此时区求值，务必先设）
sudo timedatectl set-timezone Asia/Shanghai

# 系统更新
sudo apt update && sudo apt -y upgrade

# 安装 Docker / Compose 插件 / Git / Nginx
sudo apt -y install docker.io docker-compose-v2 git nginx
sudo apt -y install docker-buildx   # 可选：消除 compose 的 Bake 警告；提示无此包可跳过

# Docker 镜像加速（腾讯云内网源；不加会拉取极慢甚至超时）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }
EOF
sudo systemctl restart docker

# 当前用户加入 docker 组（免 sudo 执行 docker 命令；newgrp 立即生效，等同重新登录）
sudo usermod -aG docker $USER
newgrp docker
groups | grep docker    # 确认输出包含 docker

# swap 保险绳（防内存峰值 OOM）
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
提示若后续 docker 命令报 permission denied ... /var/run/docker.sock：说明用户组未生效，执行 sudo usermod -aG docker $USER && newgrp docker（或临时给命令加 sudo）。

2获取代码与密钥配置

git clone https://github.com/yuanke1995/WenQu.git
cd WenQu
cp .env.example .env

# 生成两个随机密钥（复制输出，填入 .env 对应行）
openssl rand -base64 48    # → AI_JWT_SECRET（登录令牌签名密钥）
openssl rand -hex 32       # → AI_MEILI_KEY（Meilisearch master key）

vim .env                   # 填好三行：DB_PASSWORD / AI_JWT_SECRET / AI_MEILI_KEY
说明
  • DB_PASSWORD：数据库 root 密码，自定强密码即可（备份 mysqldump 也用它）。
  • AI_JWT_SECRET：登录令牌签名密钥（≥32 位）。写死勿改——改动后全员需重新登录。
  • AI_MEILI_KEY：Meilisearch 容器初始化必填（≥16 字节）；应用默认关键词引擎是 MySQL LIKE，切到 meilisearch 时才实际使用。
红线切勿把 .env 提交进 git（仓库已忽略它）；模板 .env.example 才允许入库。

3构建并启动全栈（含中间件）

# 构建后端镜像（首次约 2~5 分钟；依赖走阿里云 Maven 镜像，已内置）
docker compose build app

# 启动全部服务（首次会拉取 mysql / redis-stack / meilisearch 镜像，数分钟）
docker compose up -d

# 查看状态：app / mysql / redis-stack / meilisearch 共 4 个服务
docker compose ps

中间件在这里面各自承担什么

服务部署即生效的行为
mysql容器启动时自动建库 wenqu_ai；应用启动自动建表（幂等）。看护：重启容器数据不丢（mysql-data 卷）。
redis-stack知识库向量索引的底座（检索 / 重排 / 图谱扩展都经它）；同时承担配置变更广播、接口限流、分布式锁。宿主端口映射为 6380（避开本机已有 Redis）。
meilisearch默认「待命」：应用关键词引擎默认是 MySQL LIKE（零依赖）。日后在「设置页 → 检索设置」切换引擎为 meilisearch 即启用中文分词检索，应用侧连接地址已预置好，无需改配置。
关于 Bake 警告WARN Docker Compose is configured to build using Bake, but buildx isn't installed 只是警告，不影响构建（回退普通构建器）。装 docker-buildx 即消失，或不理会。
构建慢首次构建的依赖下载已走阿里云镜像（deploy/maven-settings.xml）。若仍慢，确认代码为最新（git pull）；海外网络构建可删除该文件与 Dockerfile 中对应 COPY 行。
铁律永远不要执行 docker compose down -v——-v 会删除全部数据卷：数据库与 RSA 密钥文件一起消失（存量加密的模型 API Key 将无法解密）。

5构建前端

必须用 Node ≥22.12（或 20.19+）Ubuntu 24.04 仓库自带的 nodejs 是 v18.19.1，跑 npm run build 会直接报 TypeError [ERR_INVALID_ARG_TYPE]: The "paths[0]" argument must be of type string——根因是依赖链里的 unplugin 在模块顶层使用 import.meta.dirname（Node 20.11+ 才有），Node 18 上取值为 undefined。不要降级依赖绕开，先装对 Node。
# 安装 Node 22 LTS（NodeSource 官方源，幂等；想装 24 就加 NODE_MAJOR=24）
sudo bash scripts/setup-node.sh
#  只想体检不改东西：bash scripts/setup-node.sh --check

# 确认新开终端里 node -v 应为 v22.x
node -v

cd web
npm config set registry https://registry.npmmirror.com
npm install && npm run build

sudo mkdir -p /var/www/wenqu
sudo cp -r dist/* /var/www/wenqu/
提示也可以在本地电脑构建（同样需要 Node ≥22.12）：把 web/dist/ 上传到 /var/www/wenqu/，服务器无需安装 Node。
PATH 优先级坑若服务器上装过 nvm 里的旧 Node，PATH 会优先命中它而让系统包白装。脚本会自动检测并把 nvm 默认版本切到同代号；手动处理则执行 source ~/.nvm/nvm.sh && nvm install 22 && nvm alias default 22。

6配置 Nginx

cd ~/WenQu
sudo cp deploy/nginx.conf /etc/nginx/sites-available/wenqu
sudo ln -sf /etc/nginx/sites-available/wenqu /etc/nginx/sites-enabled/wenqu
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
路径映射原理后端 context-path 为 /ai、控制器挂 /api/ai，因此外网完整路径是 /ai/api/ai/*。Nginx 把前端调用的 /api/ai/* 前缀替换为 /ai/api/ai/*；SSE 接口（对话、分享聊天、工作流运行流）已统一关闭响应缓冲保证流式；/ai/images/*（文档图片）、/ai/artifacts/*（产物签名下载）、/ai/mcp（对外 MCP）原样直通。若你手改过配置，请保持 /ai/api/ 这个替换，否则全部接口会 404。
安全设计后端只绑 127.0.0.1:8090，外部只能经 Nginx 访问；8090 不要对外放行。

7防火墙放行

腾讯云控制台 → 轻量应用服务器 → 实例 → 防火墙 → 添加规则：TCP 80，来源 0.0.0.0/0（IPv4）。

  • 22 默认已放行（SSH）。
  • 不要放行 8090（后端仅回环）；6380 / 7700 保持不放行，外部即不可达。
  • 启用域名 + HTTPS（可选）：域名需完成 ICP 备案后，用 certbot 签发证书并改监听 443。

8首次使用

浏览器打开 http://<公网IP>/，按顺序完成：

  • ① 按引导创建管理员账号（接入 OIDC 后可改单点登录）。
  • ② 「智能体工作台 → 模型供应商」登记网关与模型（填网关地址 / API Key，按类型登记聊天、向量等模型）。
  • ③ 「个人设置」绑定个人默认聊天模型（对话页可随时切换）。
  • ④ 「知识库」新建库并绑定向量模型 → 上传文档 → 等待解析完成。
  • ⑤ 回到对话提问，句末 [N] 角标点开即见来源全文与原文图片。
无兜底设计未登记聊天模型时会 fail-loud 提示选择，不会静默回落——按 ② ③ 走完即可正常对话。

常见问题排查

现象原因与处理
permission denied ... docker.sock用户未进 docker 组：sudo usermod -aG docker $USER && newgrp docker（或临时加 sudo）
WARN ... Bake, but buildx isn't installed无害警告：装 docker-buildx，或忽略；也可用 COMPOSE_BAKE=false docker compose build app

知识库检索结果异常检查 redis-stack 是否 healthy（向量检索底座），并确认知识库已绑定向量模型
容器莫名退出 / 服务卡顿docker stats 看内存占用；确认 swap 已挂载（free -h）；2C 机器走附录「精简部署」

组件位置说明

联网搜索：三层开关（缺一层不生效）

联网搜索是应用层工具（不是中间件）：接商业 API 时服务器无需安装任何东西；只有选自建 SearXNG 方案才需多跑一个容器。启用前先理解三层开关——只开其中一层是常见误区。

层开关位置与说明
①tool.enabled设置页 →「工具调用」：工具总闸（默认关）——所有工具（含联网搜索）的总开关
②webSearch.enabled + provider + apiKey设置页 →「联网搜索」：选服务商、填凭据、打开开关（默认关）
③智能体能力开关「智能体」→ 编辑对话所用的智能体 → 打开联网搜索能力（三态：1=开 / 0=关 / 继承）
行为与安全垫搜索结果强制进引用体系（与知识库引用同源展示 [N]）；单轮搜索配额 webSearch.maxCallsPerTurn（默认 2 次）防反复搜烧 token；可开启「执行前确认」审批；游客分享链路不暴露该工具。

方案一 · 商业 API（推荐，零安装）

服务商免费额度超量价格备注
博查 Bocha 国内推荐新用户 1000 次¥0.036/次；资源包 ¥36/1000 次国内直连、0.15s 低延迟、中文效果好
Tavily1000 credits/月（持续发放）$30/月起（4000 credits）国际服务，境内服务器调用可能慢/不稳

步骤：① 到 open.bochaai.com 或 tavily.com 注册获取 API Key；② 设置页 →「联网搜索」：服务商选 bocha 或 tavily，填入 Key，打开开关；③ 按上方三层开关补开 ① 总闸与 ③ 智能体能力。

方案二 · 自建 SearXNG（完全免费，需自行维护）

cd ~/WenQu/deploy/searxng
docker compose up -d

# 取「宿主在问渠容器网络里的网关 IP」——下一步设置页的服务地址要用它
docker network inspect wenqu_default --format '{{(index .IPAM.Config 0).Gateway}}'

步骤：① 服务器上执行上面命令起容器（约 200~300MB 内存，4GB 机器可直接加装）；② 设置页 →「联网搜索」：服务商选 generic，服务地址填 http://<网关IP>:8888，Key 留空，打开开关；③ 再按三层开关补开 ① 总闸与 ③ 智能体能力。

容器场景关键坑服务地址不能写 127.0.0.1——问渠后端跑在容器里，127.0.0.1 指容器自身回环；要用上面查到的网关 IP（通常 172.x.0.1）或服务器内网 IP。8888 无需在腾讯云防火墙放行（容器走 docker 网桥内部访问）。
取舍SearXNG 免费但搜索源会被反爬、质量有波动、需自行维护；有免费额度的商业 API 更适合起步。两者在设置页随时可切换，SearXNG 适合作为「不想注册任何账号」的备选。

D · 2C2G 精简部署

  • 跳过 Meilisearch：删除 compose 中 meilisearch: 服务段，以及 app.depends_on 里的 meilisearch 条目（只删服务段不够，depends_on 仍会拉起它）；默认引擎即 MySQL LIKE，无需改配置。
  • .env 增加 JAVA_OPTS=-Xms128m -Xmx512m。
  • MySQL 命令追加调小参数：--innodb-buffer-pool-size=192M --performance-schema=OFF。
  • 保留 2GB swap；期望内存 ≈ 1.4–1.6GB，适合个人使用与演示。
