检索评估：从「参数试跑表单」到「检索质量实验台」

把评估集、参数对比、答案质量与自动体检串成一条「发现问题 → 提出假设 → 跑实验 → 应用 → 回归」的闭环。 视觉沿用现有 --app-* token 与 ant-design-vue，不引入新框架；先解决「看不见、留不住、比不了」三件事。

现状 1 页平铺 · 0 张趋势图 · 结果不落库 目标 首屏判断 + 实验化对比 改动 前端重排 + 4 张表 / 6 组接口 兼容 浅色 / 深色 / 1080 宽 / 只读角色
设计主张：评估页不是「参数填表页」，而是检索质量的实验台。每一次运行都必须能回答： 基线是什么？改了什么？哪几题变好、哪几题变差？能不能应用到线上？

3

4

6

7
答案评测与坏题联动。可只测检索落空/低分题；调用次数与费用前置，避免每次固定测前 N 条。
8
运行历史可回看。每次运行落库，支持趋势、基线、跨次对比与导出，刷新页面不再丢结果。
02

现状诊断：六个具体问题

基于当前 EvaluationPage.vue、RetrievalEvaluationService.java 与截图。问题不在「没有能力」， 而在能力没有被组织成可判断、可复用、可追溯的工作流。

01

首屏是配置，不是结论

页面第一眼是 K 值、权重、阈值和参数组；「怎么用（三步）」默认折叠，真正的第一步「生成评估集」藏在右上角。截图为 0 条用例时，体检/运行按钮灰置，用户没有下一步可点。

02

关键状态被吞掉

后端已返回 timedOutGroups（超时组）、staleExpected（失效期望标签）、paramsStale（参数漂移）与全失效跳过数，当前页面均未渲染。用户会把「少跑了一组」或「标签失效」误读成质量变化。

03

结果留不住，历史比不了

对比结果只存在组件 ref 里，刷新即失；自动体检只保留最近一期 eval.lastReport；答案评测历史存在 config 键里且只有 10 期。没有趋势、基线、跨次逐题对比。

04

评估集不可管理，存储也脆弱

评估集是本地文件 data/eval/retrieval-eval.json，只能整体重生成或手改 JSON。仓库内已有 25 条评估集，截图却显示 0 条——工作目录/容器/多实例不同就会「消失」。没有题目列表、增删改、导入导出、人工确认与标签修复。

05

实验设计缺失

参数组只是并列表单：看不到「与当前配置差在哪」，不能复制/停用；没有历史基线，也没有「改善/退化」的逐题差量。更关键的是上限不一致：生成允许 500 条，运行却硬限 100 条且前端不传 caseIds，超过 100 条直接报错。

06

分析浅、闭环断

逐题明细藏在两层折叠里，没有搜索、失败优先或跨组对比；期望块只显示 ID，无法判断标签对错。答案评测与检索评测分成两张卡、各取前 N 条；自动体检结论只在看板出现，页面与告警之间没有处置入口。

03

设计原则

四条原则决定后面的所有取舍。

◔

先结论，后参数

先用健康度、环比和待处理项回答「现在好不好」，再把参数编辑器放到第二层。没有结论的配置页只会让人反复试错。

⇄

实验而非表单

固定基线、一次只改一组变量、给出逐题差量与结论。参数组不是「填数字」，而是可复制、可停用、可比对的实验对象。

▾

失败优先

默认先看落空、低相关和退化题，而不是平均值。平均值掩盖长尾，评估的价值在于定位「哪几题坏了」。

⌁

证据可追溯

每次运行都绑定评估集版本、参数指纹、触发方式与逐题结果。能被回看、对比、导出，才配叫「基线」。

04

信息架构：前后对比

页签从「没有页签」变成五个明确工作面；配置与结果不再互相遮挡。

05

分批交付

1阶段一（P0，纯前端为主）：五页签、总览健康度、隐藏状态、评估集只读表、实验卡与逐题差量、答案评测坏题联动、空态引导。可直接复用现有接口点亮。
2阶段二（P1，持久化）：4 张表 + 运行历史/趋势/跨次对比 + 异步运行与取消 + 评估集 CRUD/导入导出 + 旧 JSON 导入。
3阶段三（P2，增强）：置信区间、分群指标、评估集质量分、定时实验与通知、灰度应用与回滚、多租户评估集。

验收口径

✓空态下首次进入，10 秒内能看到「生成评估集」并可一键执行；体检路径不超过 3 次点击。
✓超时组、失效期望块、跳过用例、参数漂移四类状态 100% 在界面可见，不再依赖日志。
✓任意一次运行可回看、可设基线、可与另一次运行做逐题对比并导出。
✓评估集 500 条、8 组参数时，运行不再因前端不传 caseIds 直接报「超过 100 条」。
✓只读角色看不到生成/运行/应用/编辑；所有写操作有二次确认。

风险与边界

弱监督偏差：评估集来自「当时引用的块」，不等于唯一正确答案。界面必须持续提示，并提供人工确认与「允许同文档任一块命中」的选项。
小样本波动：25 条上的 ±0.02 可能只是噪声。P2 前先用「改善/退化题数」辅助判断，避免只看均分。
评判模型漂移：忠实度/相关性会随模型版本变化。运行记录必须快照评判模型与提示词版本。
重排成本：勾选重排会真实调用外部服务。实验前展示预计调用次数与费用，默认不勾选。
历史数据量：逐题结果保留 90 天或最近 200 次运行，超期归档，避免表无限增长。
