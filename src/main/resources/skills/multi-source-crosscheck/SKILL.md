# 多来源交叉核对

## 适用场景

- 检索到的**多份资料对同一问题说法不一致**（版本不同、适用对象不同、年代不同）
- 需要**跨资料汇总 / 对比**（多个来源的数据拼成一张结论、同一指标在不同文档里的数值差异）
- 资料本身是**规则/口径**类内容（制度、计价标准、审批权限、有效期），而用户问的是「我这种情况适用哪个」

单纯命中一份资料的问答**不需要**本技能，走常规作答即可。

## 核心原则

**分歧本身就是要交付的信息。** 静默挑一个说，等于替用户做了决定；而用户拿到的答案看不出有另一个说法存在——这是最难被发现的一类错误。

## 怎么做

1. 先判断几个来源是不是**真的矛盾**，还是各有适用条件（不同版本 / 不同部门 / 不同产品线 / 不同时期）
2. 能用适用条件解释 ⇒ **并列呈现**，写清各自适用于谁，不要合并成一句
3. 无法用条件解释、就是冲突 ⇒ **明确点出冲突**，两个说法都给出并各标引用
4. 有明确生效时间或版本号的 ⇒ 以**最新且适用**的为准，但把旧说法作为背景提一句
5. 汇总类问题逐项标注来源，不同来源的同一指标**不要合并成一个数字**

## 输出形态

冲突时：

> 两种说法在资料里并存，取决于适用对象：
> - 说法 A（适用于 2025 年前的旧版本）：……[1]
> - 说法 B（现行版本）：……[2]
>
> 你描述的情况按 B 适用。

口径类问题：

> 按**《X 管理办法》第 3 条**（2026-01-01 起施行）：……[2]
> 注意：旧版《X 办法》规定为……[1]，已废止。

## 禁止

- 不要把互相矛盾的说法揉成一句自洽的话——那等于凭空造了一个谁也没说过的结论
- 不要因为某个来源"看起来更权威"就隐去另一个；权威性判断可以给出，事实分歧必须呈现
- 不要在汇总表里把不同来源的数值混在一列
- 不要把"资料 A 说 X"写成"就是 X"（来源归属必须保留）
