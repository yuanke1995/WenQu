# 对接与集成

> 本篇面向**需要把问渠接入自有系统的开发者**：四个出口分别怎么调用、凭据放在哪里、失败时的返回形态。
> 平台使用者视角的内容在「MCP 与开放能力」；本篇补充**接口层**的契约。

## 出口选择

| 要做什么 | 用哪个出口 | 凭据 |
|---|---|---|
| 让 Claude Desktop / Cursor 等 MCP 客户端使用问渠的全部能力 | **平台级 MCP 入口** `/ai/mcp` | API Key |
| 让 MCP 客户端只看到**某一个**智能体（工具名、提示词、权限都是它） | **智能体 MCP 端点** `/ai/mcp/{token}` | 分享 token |
| 自有系统（后端脚本、业务系统、定时任务）触发一条流程并获取结果 | **工作流开放接口** `/api/ai/v1/workflows/{id}/run` | API Key |
| 只调用一次问答、不需要 MCP 协议 | **问答接口** `/api/ai/chat` | API Key |

前三个都是 HTTP 调用，没有 SDK、没有本地进程，也不需要把问渠装到调用方的机器上。

## 共同前提（三条，缺一即无法接通）

1. **凭据**：在「API 密钥」页创建 Key。**明文只在创建时显示一次**，之后列表中只有前缀。
   名称与有效期可随时在该 Key 的「编辑」中修改：到期后调用即失效，改为长期即恢复。
2. **总开关**：管理员须在「系统设置 → MCP 服务（双向）」打开「对外提供 MCP 端点」。
   该开关**同时约束**平台级入口与每个智能体的端点（两处入口均先校验）。
3. **Origin**：只有**浏览器型**客户端（网页中的 fetch、浏览器插件）才会带 `Origin` 头，
   此时必须把前端域名填进「MCP 服务（双向）→ 允许的 Origin」（逗号分隔、**需带 scheme**，如 `https://ai.example.com`）；
   留空只允许本机回环。**Claude Desktop / Cursor 这类本地进程客户端不带 `Origin`，不受此限制。**

## 一、平台级 MCP 入口

```
POST {站点地址}/ai/mcp
Authorization: Bearer sk-xxxxxxxx…        ← 也可用 X-Api-Key: sk-xxxxxxxx…
Content-Type: application/json
```

传输为 **Streamable HTTP、无状态**：一次请求对应一个 JSON-RPC 消息，不需要先 `initialize` 建立会话，
也不需要 SSE 长连接。使用 `POST`（这是客户端的默认与推荐形态）；该路径同时挂了 `GET`，
但不要依赖它——请求-响应语义下 `GET` 没有实际用途。

### 配置片段

```json
{
  "mcpServers": {
    "wenqu": {
      "url": "https://ai.example.com/ai/mcp",
      "headers": { "Authorization": "Bearer sk-你的Key" }
    }
  }
}
```

粘贴到 Cursor 的 `.cursor/mcp.json` 或 Claude Desktop 的配置中即可。地址与片段也可在
「API 密钥」页的「如何使用」中一键复制（那里显示的是当前站点地址，无需自行拼接）。

### 暴露的工具

| 工具 | 参数 | 说明 |
|---|---|---|
| `wenqu_search_knowledge` | `query`（必填）、`topK`（1~5，默认 5）、`kbId`（可选） | 在**调用者可见**的库中检索片段。结果已经过相关性阈值过滤，未命中时明确说明，不返回空结果 |
| `wenqu_ask` | `question`（必填）、`agentId`（可选）、`sessionId`（可选） | 完整问答（检索+作答）。传回上次的 `sessionId` 可续接上下文 |
| `wenqu_list_knowledge_bases` | 无 | 可见知识库的 id 与名称 |
| `wenqu_list_agents` | 无 | 可用智能体；**已开放独立 MCP 端点的会多一个 `mcpEndpoint` 字段** |

可见范围与「Key 创建者在网页上看到的内容」严格一致，不是另一套权限。

### 回答里带来源

`wenqu_ask` 的返回**除正文外还带来源清单**：

- 文本内容末尾附一份可读来源清单，`[N]` 与正文角标一一对应：

  ```
  来源：
  [1] 知识库 · 智报平台操作手册v3.0.docx · 组件 · 相关度 0.949
  [2] 联网 · blog.csdn.net https://… · 相关度 0.816
  ```

- 结构化输出里同时给一份机器可读的 `sources`：

  ```json
  {
    "sessionId": "…",
    "sources": [
      { "ref": 1, "origin": "TOOL", "fileName": "智报平台操作手册v3.0.docx",
        "title": "组件", "score": 0.949 },
      { "ref": 2, "origin": "WEB", "siteName": "blog.csdn.net",
        "url": "https://…", "title": "…", "score": 0.816 }
    ]
  }
  ```

`origin` 取值：`TOOL`（库内文档）／`WEB`（联网）／`MCP`（外部 MCP 工具返回）。
**只返回文档名、章节标题、站点与相关度，知识块全文与块内图片不外发**——那些属于库内内容。
单次最多列出 20 条，超出时在文本中写明「另有 N 条来源未列出」，不静默截断。

## 二、智能体 MCP 端点

```
POST {站点地址}/ai/mcp/{token}
```

- 地址在智能体卡片的「公开发布 → MCP 端点」中，连同 `mcp.json` 一起可复制。
- **`token` 即凭据**，不需要再带 Key；它同时是分享链接 `/s/{token}` 的凭据。
  停用分享或关掉「开放 MCP 端点」→ 端点立即失效。
- 工具名形如 `ask-{智能体名}`，入参 `question`（必填）与 `sessionId`（可选），返回同上。
- 需要先在智能体上打开「开放 MCP 端点」，而它依赖公开分享——「开启 MCP 端点但未开启分享」会被直接拒绝。
- 游客能力收窄：**沙盒 / 产物 / 技能执行 / 个人 MCP 不对外暴露**，检索按发布者的可见范围执行。

## 三、工作流开放接口

```
POST {站点地址}/api/ai/v1/workflows/{id}/run
X-Api-Key: sk-xxxxxxxx…
Content-Type: application/json

{ "inputs": { "key": "value" } }
```

- 执行的是**已发布版本**的 DSL，草稿改动不影响线上行为。
- 以下几处行为是刻意设计，接入前需知悉：
  - 运行结果为 `status=failed` 时**不返回 500**，而是正常返回本次 run（含 `error` 与节点级 `nodeTraces`），失败节点可定位；
  - 工作流对该身份不可见 → **404**（不泄露存在性）；
  - 未发布 → **400**；
  - **含人工审核节点的工作流一律 400 拒绝**——外部调用方没有审批交互面。
- 补查/回溯用 `GET /api/ai/v1/workflows/{id}/run/{runId}`（触发方与归属一致才可见）。

## 四、问答接口

```
POST {站点地址}/api/ai/chat
X-Api-Key: sk-xxxxxxxx…
```

SSE 流式；权限固定为问答链路（问答 / 会话 / 反馈 / 引用溯源），**管理端点一律拒绝**，
即使持有 Key 也不可访问。

## 五、限频与超时

- **限频**：外部调用与网页问答**共用「问答」配额**，按 IP 优先（同一端点被多客户端共享时互不影响），
  取不到 IP 时按 Key / token 计。被限频时返回明确文案，不会静默丢弃。
- **超时**：「MCP 服务（双向）→ 等待超时」默认 **180 秒**，最小 30 秒。
  注意 MCP 的 `tools/call` 是请求-响应语义、**没有进度反馈**——复杂问题要么调大该值，
  要么在调用方把问题拆小。客户端自身的超时通常比该值更短，通常先触发的是它。
- 每次外部调用都记一行「MCP 调用审计」（渠道 / 工具 / 凭据指代 / 归属 / IP / 耗时 / 成功与否），
  在「API 密钥」页可查。

## 六、排查：无法接通时按此顺序检查

| 现象 | 先查什么 |
|---|---|
| 401 / 提示 Key 无效 | 平台级入口专用。Key 是否停用或过期；**是否打开了该 Key 的「MCP」开关**（该项未开启时返回同样的提示） |
| 403 且提到 Origin | 调用方带 `Origin` 但域名不在允许列表中。填进「允许的 Origin」（带 scheme），或确认客户端是否为浏览器型（本地进程客户端不应出现该错误） |
| 404（智能体端点） | 刻意的：**分享不存在 / 已停用 / 未开启 MCP 端点 / token 无效，一律 404**，不区分原因、不泄露存在性。按此顺序自查 |
| 404（工作流） | 该工作流对该身份不可见——不泄露存在性，属预期 |
| 400（工作流） | 未发布，或该工作流含人工审核节点（外部调用方没有审批交互面，一律拒绝） |
| 端点整体不通 | 管理员总开关「对外提供 MCP 端点」是否开启——它同时管平台级与智能体端点 |
| 调用了但没有回答 | 查看「MCP 调用审计」中对应行的成功/失败与耗时；超时同样在审计中留痕 |
| 客户端里看不到工具 | 平台级有 4 个固定工具；智能体端点只有 1 个（`ask-…`）。用 `wenqu_list_agents` 查看哪些智能体另有独立端点 |
