# 团队与权限

## RBAC 两级管控

- **角色-菜单**：控制侧栏入口与页内 Tab。内置菜单为：对话、智能体、市场、知识库、我的产物、使用统计（以上默认对所有登录用户绑定），成员管理、数据看板、检索评估、权限管理、系统设置（管理员级）。「智能体」名下六个 Tab（模型供应商 / 智能体 / 技能 Skills / MCP 外部工具 / 工作流 / 定时任务）与「权限管理」名下的「认证源」Tab（统一管理 OIDC / SAML / SCIM / LDAP）都可单独授权
- **角色-接口**：端点白名单，后端 fail-closed——普通用户仅开放日常链路，管理端点返回 403；接口清单由应用启动时自动扫描登记，可按菜单归属分组，勾选菜单即一并授权其名下接口
- **权限配置界面**为单棵树（菜单 + 名下接口）：搜索、级联勾选，并直接告警「检测到 N 个接口未授权」；管理员级角色只读
- **菜单可单独隐藏**（「权限管理 → 菜单」每行的「可见」开关，不用进编辑弹窗）：隐藏只影响它是否出现在侧栏，不影响谁能用，随时可打开。例如「对话」这一项默认在数据层隐藏——入口由侧栏顶部「新建对话」承载，而这一行必须保留以承载问答接口的菜单归属；恢复显示只需打开该开关。隐藏带子菜单的父项前会列出子项去向：页内 Tab 因失去宿主而不可用，其余子项升到侧栏顶级继续显示
- **内置菜单随版本自动补齐**：新增内置菜单不需要手工 SQL，默认对普通角色不可见，需在「权限管理」中为角色勾选（fail-closed）；管理员在权限页解绑的绑定不会被启动逻辑恢复
- **个人侧栏布局**：菜单顺序与显隐可由每个人在侧栏编辑态（点 logo 行或长按 0.5 秒）拖拽调整，并支持恢复默认——这只改变呈现，不改变权限判定

## 内置角色

| 角色 | 权限 |
|------|------|
| `superadmin` | 全部权限，受「最后一名超管保护」 |
| `admin` | 管理端全量 |
| `user` | 问答与个人资源（对话、市场、知识库、我的产物、使用统计，以及智能体工作台六个 Tab） |

管理员判定 = `admin` / `superadmin` 或角色自带 `admin_flag`。可新建自定义角色（编码小写字母开头、建后不可修改），并为其绑定菜单与接口。

## 多角色

一个账号可同时持有多个角色，**权限按角色集并集判定**——任何一个角色允许的事都可做。角色的来源有两档：

- **手动授予（manual）**：管理员在成员管理里勾选，属于人工指定
- **认证源授予（idp）**：由 SCIM 组映射、LDAP 组映射或外部建号默认角色自动授予，跟随目录变动自动回收

两档互不覆盖：IdP 侧的角色变动只增删 idp 行，管理员手动授的角色不受目录同步影响；删除组映射规则时只回收该规则授出的 idp 角色。界面上展示的「主角色」只是首个管理员级角色（否则首个）的展示名，仅用于头像旁的标签与令牌声明，**不参与鉴权**。

管理员级账号（admin / superadmin / 自定义 admin_flag 角色）受**最后一名保护**：禁用、删除或降权最后一名管理员级账号会被拒绝（含 SCIM/IdP 侧推送），防止系统失去管理入口。

## 成员与部门

「成员管理」两个页签：**用户**（搜索昵称 / 登录账号、按部门与角色筛选、新建用户、编辑、重置密码、启禁用、删除）与**部门**（树形层级、新建 / 编辑 / 删除，父部门留空即顶级）。禁用某成员后该账号不再具备部门与管理员身份权益。

用户列表的**角色列**展示该账号的全部角色（多个以标签并列），编辑表单中角色为多选，保存即全量替换手动角色。**身份来源列**展示账号在各认证源的绑定（外部标识）；已绑定的来源可在行内逐源解绑——解绑后须重新走对应认证源登录才能再绑。删除成员会一并清掉其全部角色与身份绑定。

部门同时是共享范围的一档：资源可共享给指定部门。LDAP 目录同步的部门映射也会落在这里。

## 多租户

一个平台可以同时服务多个互不相干的客户。**租户是行级归属**：每条业务数据都带一个租户标识，
读写时由框架统一在 SQL 上加上「只看本租户」的条件——不是每台租户起一套服务，也不是各开一个库。

- **单租户部署不需要任何设置**：平台自己就是一个租户（`default`），存量数据全部归它，行为与没有租户时完全一致。
- **开通新租户**：「成员管理 → 租户管理」里填标识与显示名。新租户是**空的**：把成员的「所属租户」改过来，
  他们才开始在这个租户里各用各的数据（会话、知识库、工作区、产物、用量与配额都隔开）。
- **客户自助申请开通**：公开页 `/apply`（免登录）填机构名称、联系人、邮箱与用途说明。提交只生成一条待审申请，
  平台管理员在「成员管理 → 租户管理 → 开通申请」里批准或驳回——批准才会真的开租户，
  并顺手建出首位管理员账号（标识 `<租户>-admin`），初始口令**只在批准那一刻显示一次**，之后谁也查不到。
  之所以不自动放行：开通意味着建出一个能看见本机构全部数据的管理员账号，这一道闸必须是人。
  申请入口按来源 IP 限流（每分钟 5 次），同一机构或同一邮箱有待审单时不让重复提交。
- **改归属只改账号**：他已产出的会话、知识库、工作流留在原租户。要把资源并过去，走显式的资源转移，
  不藏在改归属里——「谁的文件归谁」不该是一次点击就无声改写的隐式行为。
- **谁能跨租户看**：只有平台级（`superadmin`）看得到全部租户——成员名单、认证源清单、审计事件、
  费用报表的「按租户结算」；其它数据列表仍按本人租户过滤。租户自己的管理员只管本租户，
  他打开费用页只会看到本租户的数字，不会摆一张只有一行的「按租户」表。
- **登录账号标识是平台级唯一的**（`uid`，不是显示名）：磁盘上的记忆目录、沙盒工作区与登录令牌里只带它，
  两个租户各起一个同名账号就会互相踩对方的文件。所以别的租户已经用过这个标识时，建号会当场被拒并说清原因。
  显示名（昵称）不需要唯一，各租户里都可以有「张三」。
- **认证源归某个租户**：「权限管理 → 认证源」的弹窗里有「所属租户」（只有一个租户时不出现这一项）。
  SSO / SCIM / LDAP 自动建出来的成员，落在**认证源自己的租户**里，不是操作者或默认租户。
  给认证源换归属时，它的账号绑定、组映射规则、组成员与同步日志一起跟过去。
  只有平台级能把认证源开到别家租户；平台级也因此在认证源页看得到全部租户的认证源。
- **限流按租户分池**：同一个办公网出口 IP 后面可能同时站着两家客户，不分池就是一家的流量能刷挂另一家的额度。
  免登录分享页的访客没有租户上下文可分，仍走共享池。
- **内容安全词表按租户各一份**：新租户开通时自带两条只告警的个人信息示例（与首启动同一批），
  拦截词表由各家管理员在「权限管理 → 内容安全」里自己定。平台没有一份强加给所有租户的底线词表——
  要收口只能逐租户配置，这是刻意的：合规口径属于客户，不由平台替客户决定。
- **审计可按租户出清单**：审计页与 CSV 导出都支持指定租户（含租户列），跨租户审阅仅平台级可用。
- **没有删除租户**：那等于按归属批量删光这个客户的全部数据，不该是一个按钮。要下线就**停用**——
  挡登录、留数据，随时可恢复。默认租户不能停用。停的不只是这个人的密码登录：这家租户名下的
  单点登录与 SCIM 推送、目录同步一起停摆（IdP 再推也建不出号，SCIM 侧收到 403）。启停在这一台上一按就生效，
  其它副本最迟一分钟内跟上。停用期间数据一律保留，别家租户的用量与费用也不受牵连。
- **仍是平台级共享的部分**（刻意如此）：模型供应商与模型库、平台参数、菜单与角色定义、
  图片描述缓存、技能市场。也就是说各租户连的是同一套网关与同一份价格表，用量、配额与词表各算各的。
- 后台任务（解析队列、超时回收、留存清理等）本就要遍历所有租户的行，它们不套这层过滤；
  因此**在这些线程里"给某个成员看"的查询必须显式声明在哪个租户里做**，不能指望这道闸替它兜。

## 资源可见性

所有资源（知识库 / 文档 / 智能体 / 工作流 / API Key / 技能 / MCP 服务 / 凭据）的数据按创建者隔离：

- **创建者** → 可管理（不受角色上限约束）
- **他人** → 仅按资源显式配置的共享范围可见；普通用户对他人登记的知识库**封顶只读**
- **共享范围未配置 = 私有**；已配置按声明的 scope（**全局 / 指定部门 / 指定用户**）判定，管理范围不得宽于阅读范围
- **管理员与普通用户同口径**：只看创建者与显式共享范围，范围内可见可管
- **检索可见性两级判定**：文档可见 = 所属库允许 **且** 文档自身允许（未配置 = 跟随库）
- **个人默认库「问渠」**：各成员的私有库，仅本人可见可用，不可删除
- **官方内置库**：《问渠使用手册》创建者为 `system`，共享范围为全员只读——所有人可检索、可读，任何人都不可修改
- 市场条目的安装走「复制为自己的资产」，作者与安装者之间不共享数据行

## 认证方式

- **本地账号**：PBKDF2 密码哈希 + 连续失败锁定（默认 5 次、锁定 15 分钟），密码最短 6 位
- **统一认证源**：企业身份源在「权限管理 → 认证源」页签（平台级，管理员）统一登记与管理，支持四类：**OIDC / SAML**（登录认证）、**SCIM / LDAP**（账号供给与同步）。每行一个认证源，可独立启停；`clientSecret`、`bindPassword`、`spPrivateKey`、SCIM Bearer 等敏感字段 RSA 加密入库、回显只给掩码，保存时遇到掩码值不覆盖原值
- **登录**：登录页列出所有**已启用**的 OIDC / SAML 认证源，点选后跳转对应 IdP 完成认证。首次登录按建号规则处理：`(认证源, 外部标识)` 复合唯一——同一外部身份永远落到同一个账号，不会因重复登录生成多号
- **外部建号规则**（每源可配）：默认角色（授予为 idp 档）、是否自动建档、部门映射。外部建档的账号**不设密码**，只能走对应认证源登录
- **OIDC**：标准授权码流程，支持企业微信 / 飞书 / Keycloak / 自建等。issuer、clientId / clientSecret、重定向地址、scopes、身份映射（用户名 / 姓名 / 部门 claim）逐项配置；前后端分离部署时必填 `frontendBaseUrl`
- **SAML 2.0**：填 IdP 元数据地址（`metadataUrl`）或手填 `idpEntityId / idpSsoUrl / idpCertificate`；可选配置 SP 证书对（成对，用于 AuthnRequest 签名与加密断言解密——ADFS 要求签名请求时必配）。支持用户名 / 姓名 / 部门属性映射
- **SCIM 2.0（入站）**：供 Entra / Okta 等 IdP 把用户与组**推送**进来。每个 SCIM 认证源有一枚独立 Bearer Token（机器凭据，与登录令牌无关），IdP 侧配置到对应端点即可；凭据不对一律 401。推送语义：建号不设密码；IdP 侧停用 / 删除 = 本地**禁用**（可恢复，绑定保留）；组成员入组 / 出组即时联动组映射的角色授予与回收
- **LDAP（目录同步）**：填目录地址、Bind 凭据与 Base DN，支持 AD（memberOf 属性）与 OpenLDAP（组反查）两种组形态。按源配置的同步间隔**定时 diff**：远端有本地无 → 建号；显示名变更 → 更新；远端消失（离职）→ **自动禁用**（可恢复）。页签内可测试连接、手动立即同步、查看同步日志
- **组映射规则**：把外部组名映射到角色 / 部门（SCIM 推组与 LDAP 同步共用）。多条规则命中时按 **priority 取唯一胜者**，同优先级按组名稳定裁决；规则删除时回收它授出的 idp 角色，管理员手动授的角色永不被自动回收
- 登录令牌为 JWT（`AI_JWT_SECRET` 签名，多副本必须同一个值；改值等于全员重新登录），有效期默认 168 小时
- 敏感数据（供应商密钥、凭据、认证源参数、MCP 请求头）以 JWE 信封加密存库（RSA-OAEP-256 包裹 AES-GCM），密钥版本记在密文里，支持不换停机轮换

## 配额与预算

管理员在「数据看板 → 费用」页签的「配额与预算」里给不同档位设上限，到点就闸住新的模型调用：

- **三档作用域各自独立**：本租户预算、部门配额、成员配额。本租户预算管的是同一租户内所有人加起来的总量
  （只有一个租户时，它就是整个平台的上限）。一个人可以同时被三道闸管着，
  被拦下时提示会点名是哪一道闸、本周期已用多少、上限多少、什么时候恢复；成员自己能在
  「使用统计」页的「我的配额」看到约束到自己的那几档与进度。
- **两个周期**：按自然日或自然月，到点自动归零；上限填 0 或留空＝那一维不限。
- **两种口径**：token 上限（所有已计与未计模型都算）与费用上限（元，只累计**已登记单价**的模型——
  没配单价的模型不进金额口径，token 口径照算）。至少要填一个。
- **两种处置**：`熔断`＝到额后新问答直接拒绝；`只告警`＝照常跑但给管理员发一条触顶通报。
  新上的策略建议先「只告警」跑一个周期，确认拦得对再改熔断。
- **拦的是谁主动发起的调用**：对话、子智能体分支、工作流。历史压缩、记忆提炼、引用自检这类
  辅助调用不拦——掐断它们不会省钱，只会让上下文撑爆、这一轮反而更贵。
- 每次触顶都会给管理员发一条站内通报（同一档同一周期同一个人只发一次，不会刷屏）。

## 审计与防护

- 管理操作打 `[AUDIT]` 审计日志（上传、删除、导入等）
- 问答与上传按用户（无身份按 IP）Redis 固定窗口限频，超限返回 429；Redis 不可用时**降级为本进程令牌桶并照样拒绝超额**（不会因限流后端抖动而全线不限流；此时跨副本合计会比配置值宽，每副本各限一份）
- 费用与配额的账都只有一本：`推理用量台账` 记录每次模型调用的输入/输出 token（供应商真实 usage 优先；被叫停或断开的按实际下发内容估算并标记 `估算`），费用与配额进度都按这份台账 × 现行单价现算
- 外部调用（MCP 端点、工作流开放接口、问答接口）统一进 MCP 调用审计与用量记账
- 上传魔数校验、产物文件名白名单净化、隐藏名称拒绝写入；图片、产物与工作区文件走 HMAC 签名 URL
- 模型 API Key、MCP 请求头与工作流凭据加密入库 + 掩码回显；密钥文件不入库、不打进构建产物
- 对外 API Key 权限固定为问答链路，持有 Key 也无法访问管理端点

## 内容安全

生成式 AI 服务要能回答「违规内容有没有被拦、拦了哪些、谁拦的」。平台在问答链路上放了两道闸，
**规则清单在「权限管理 → 内容安全」维护，闸门参数在「系统设置 → 内容安全」调**。

- **输入闸**在发送那一刻判这句提问：命中「拦下」就不发起这一轮（一次模型调用都不花），
  回复当场点名是哪条规则拦的，改说法即可继续问。运行中插话走同一道闸。
- **出口闸**在模型出字的那一刻判：正文与思考过程各自逐段判定，命中即在该处收尾——
  回答留下命中点之前的部分，末尾追加一句「已在该处截断（规则：××）」，并随正文一起落库。
  已流到屏幕上的字收不回，所以新规则建议先选「只告警」跑一段，在审计里看清命中面再改「拦下」。
- **规则是数据不是代码**：拦什么字属于各机构自己的合规口径，平台不内置任何拦截词表。
  每条规则含名称、类目、作用侧（只判提问 / 只判回答 / 两侧都判）、方式（关键词或正则）、
  命中动作（拦下 / 只告警）、排序与依据；判定按排序升序，先命中的那条说话。
  首次启动登记两条**只告警**的个人信息模式（身份证号、16-19 位连续卡号），它们不拦任何东西，
  只让审计里看得见这类泄露发生过——也用来验证出口闸确实在判。
- **试跑**：管理页可贴一段文本 + 选侧别，立刻看到会命中哪几条、各自怎么处置，不用真发一句话去猜。
  正则写错不会静默失效——坏正则清单直接摊在页面上（这条规则被跳过）。
- **外部检查服务是追加的第二层**：内置规则永远先跑；接了外部服务（通用 HTTP 协议，
  可对接商业内容安全接口或自建检查模型）后，提问侧默认一起判，回答侧默认不判
  （按段等结果会拖慢出字）。外部服务连不上时按内置规则的结论继续，并在审计留一行失败记录——
  检查器宕机不该让整个问答陪葬，但也不能悄悄失去这层保险。
- **每一次拦截都进审计**：「权限管理 → 审计事件」里按人、按会话、按规则查，动作名分别是
  `内容安全拦截`（提问被拒）、`内容安全截断`（回答被截）、`内容安全放行告警`（只告警规则命中）、
  `内容安全外部服务失败`，详情含规则名、类目与命中片段。
- 跨副本改规则最多晚 15 秒生效；压缩摘要、记忆提炼、引用自检这类辅助调用不判
  （它们的产物不直接给用户看，掐断只会让上下文更糟）。
