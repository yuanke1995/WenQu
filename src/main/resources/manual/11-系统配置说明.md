# 系统配置说明

行为参数统一在「系统设置」页维护（存 `c_ai_config`，保存即生效）。部署连接不放进设置页：数据库与 Redis 走 `DB_*` / `REDIS_*`，沙盒连接走 `SANDBOX_*`，外部 OCR 服务走 `OCR_*`，框架工作区与密钥路径走环境变量或 yml。两类配置的边界见下。

## 配置语义

- 设置项 schema 的唯一来源是 `config-schema.json`：后端据此校验并下发前端渲染设置页，**schema 缺失即启动失败**。提交项中存在 schema 未定义的键时整笔拒绝保存，而不是先写入可识别的项再报成功
- **139 项参数**分布在 20 个配置面板、左侧 **15 个导航项**（`联网搜索`、`技能` 并入「工具调用」页签，`上下文`、`文档解析`、`图片描述` 并入「检索设置」页签，导航不单列），导航项上标着该组的「默认可见 / 总数」
- 全平台**默认可见 67 项**，其余 72 项是**工程参数**——默认收起，在面板头「工程参数」开关处铺开后照常可改
- 另有 54 项**内部键**只在代码默认值中登记、不进设置页（如断线重连开关、每分钟限流次数、沙盒 provisioner 连接与输出上限、OCR 服务地址等），避免把运维细节摊给使用者
- 每项标注层级：**必需（6 项）/ 调优（61 项）/ 工程排障（72 项）**；设置页默认折叠低层项，悬停参数旁的 `?` 可查看该参数的作用说明
- **敏感项按后缀判定**（`.apiKey` / `.clientSecret` / `.token`）：加密入库，页面不回显明文；编辑时输入框留空即沿用已存值，「恢复分组默认」会跳过敏感项
- 多副本部署时动态配置经 Redis pub/sub 广播即时生效，另有 5 分钟兜底轮询补齐订阅断线期间错过的变更
- 改动后由页头「保存配置（N 项改动）」一次性提交；「恢复本组默认」把该组恢复为出厂默认值（定时任务、调试设置两组不提供整组恢复）

## 配置的四种归属

| 归属 | 内容 |
|------|------|
| 平台全局 | 设置页里除个人专属项以外的全部参数 |
| 个人覆盖 | 「个人设置」中的**默认聊天模型**与**自动提炼记忆**开关（不占设置页）；`/api/ai/user/settings` 是 schema 标记 personal 字段的覆盖通道，当前没有此类字段 |
| 个人专属 | 个人 MCP 服务、个人供应商、个人技能、工作流凭据按登记人归属 |
| 资源级绑定 | 知识库的向量 / 视觉 / OCR / 重排 / 图谱抽取模型与解析、检索参数；文档的图片理解模型；智能体的人设、资料范围、能力开关、权限档位、工具确认模式、步数上限、目标模式开关；会话的模型 |

## 一项配置此刻由谁决定

同一个参数同时活在**三处清单**里：字段定义（`config-schema.json`）、代码默认值、配置表里的行。
三处对不上时不会报错，只会以「界面写着 A、实际跑的是 B」的面目出现，所以平台把这件事做成可查的：

- **启动对账**：每次启动把三处的差集点一次名，全对上一行 INFO（`[Config][对账] … 三处一致（活跃键 N 个）`），
  有错位则 WARN 直接列出是哪几个键、哪一类错位。部署后先看这一行，比事后逐条试参数便宜得多。
- **设置页徽标**：只在「生效值不是来自配置表」或「配置表里那行的值用不了」时，参数名旁才出现一枚徽标——
  - `出厂默认`：配置表里没有这一行，此刻跑的是代码默认值；在这里改一次就会写入配置表。
  - `值有问题`：这一行的值当前版本用不了，**生效的就是库里这个值**，与界面写的不一样；重新填一次并保存即可修正。
    两种来源：① 值超出字段定义的范围（通常来自直接改库或历史迁移）；② 密钥项存的是套了两层的旧密文（早期加密方案改造时
    把旧密文当明文又加密了一次），解不出真实密钥——界面上表现成「密钥不对 / 服务不可达」，重填该项即可。
  - `个人覆盖` / `评估覆盖`：这一项正被成员个人设置或检索评估的参数对比临时改写，全局值暂时不生效。
  正常状态（值来自配置表）不打任何徽标，界面上不会多出一排噪音。
- **管理端诊断接口**：`GET /api/ai/config/trace` 不带参数回对账汇总；带 `keys=a,b` 逐键回生效值、
  是哪一层在说话、出厂默认、配置表里有没有行、这行值合不合定义；带 `uid=` 另回该成员的个人覆盖值
  （回答「为什么他看到的和别人不一样」）。敏感项只回掩码，这个接口不是读密钥的第二条路。

## 15 个导航项一览

| 导航项 | 关键内容 |
|------|----------|
| **对话模型**（4/12 项） | 回答行为（引用一致性自检、工具说明精简）、聊天档挂载 MCP、文件意图异步升级工作区。「超时与等待」一节有**耐心档位**：标准 / 长任务 / 无人值守 三档一键写齐回答超时、审批等待、提问等待、计划批准等待四个值，铺开工程参数后可逐项微调；同节的**模型无响应上限**（一次模型调用停住多久算这条流断了，它管「卡住」不管「跑得久」，所以不在档位里）与**接续窗口**也在工程参数里。**消息图片与提问长度是平台固定口径**：单条消息最多 20 张图、单张 50MB、提问正文最长 20 万字，不在本页。**模型与网关不在本页**——登记在「智能体 → 模型供应商」 |
| **检索设置（RAG）**（4 页签） | **检索**（12/13：关键词引擎类型与连接、启动时对账、融合权重、向量与关键词召回上限、两道阈值、低分保底策略与保底最低分。重排已下放知识库：模型与触发下限/窗口在知识库检索设置里配，选了才重排）、**上下文**（1/1：知识块填充上限）、**文档解析**（9/10：分块大小与重叠、结构感知切分与边界阈值、标题层级、问答对增强与每块条数、PDF 解析引擎、父子分块；图片访问鉴权收在工程参数里。新建库预填，各库可在知识库设置覆盖；单文档上传上限固定 256MB，超限截断入库）、**图片描述**（1/1：识别提示词；模型归各知识库解析设置） |
| **工具调用**（3 页签） | **总开关与子工具**（8/8：问渠工具总开关、沙盒 API 与工作流节点、沙盒脚本与单次脚本子调用上限、权限档位默认值与平台最高档位、平台停用工具名单、分支执行方式；页底是按族分组的只读工具名册）、**联网搜索**（5/6：总开关、服务商与 Key、单轮搜索次数上限、纳入执行审批；服务地址收在工程参数里）、**技能**（1/2：平台停用清单从当前可用技能中多选；允许远程安装的域名收在工程参数里；页底是按来源分组并标出停用状态的技能名册） |
| **HTTP 工具**（2 项） | 总开关、允许调用内网地址（OpenAPI 导入的宿主 API 工具集） |
| **工作流工具**（1 项） | 总开关（已发布工作流挂载为对话工具） |
| **智能体轮终回调**（1 项） | 重试次数上限（webhook 出站） |
| **开放 API**（1 项） | 跨域白名单（外部项目嵌入） |
| **接口限流**（1 项） | 限流总开关（打开后按用户限频、无身份按 IP，超限返回 429）；每分钟次数为内部键，不在本页 |
| **内容安全**（2/9 项，3 节） | 默认可见的是**两道闸总开关**与**外部检查服务**的选择（服务商 local / generic）；服务地址与 Key、提问侧 / 回答侧是否调用、连思考过程一起判、提问被拒的回复与回答被截断的标注都在工程参数里。**拦什么字不在这里**——规则清单在「权限管理 → 内容安全」 |
| **定时任务**（3/36 项，4 页签） | **参数配置**只放不属于任何定时任务的通用参数：检索图扩展上限；铺开工程参数后还有智能体评测、轮次与目标通知、会话事件账本、推送到浏览器（Web Push）等总闸。**运行状态**是调度中心的实时快照（每个任务的间隔、上次执行与结果，可暂停与立即触发）——任务自己的专属参数都在那里就地调整：间隔列改节拍（清理 / 回收共用一个节拍），展开行改各任务的保留期、并发、超时、采样条数与执行预算。**执行日志**分页列出有信息量的执行；**索引与健康**看索引一致性与服务健康 |
| **通知外发（邮件）**（0/10 项） | 邮件服务（SMTP 主机、端口、传输安全、认证账号与口令、发件人地址与显示名、前端基址）与允许外发的类型白名单都在工程参数层，默认收起；页内提供投递台账 |
| **沙盒**（6/7 项） | 命令超时、空闲回收、每用户沙盒租约上限、无工作区会话按用户共享沙盒、启动预热用户数、会话目录走本机执行器；会话目录根（执行器工作根下的相对路径）收在工程参数里。连接地址 / 令牌 / 回调地址 / 虚拟根走环境变量 |
| **MCP 服务（双向）**（3 项） | 对外提供端点开关、允许的 Origin（空 = 仅本机回环）、问答链路 MCP 连接等待 |
| **调试设置**（0/5 项） | 检索调试入口（同时管回答区的归属徽标、路由提示与降级提示显隐）与框架工作区目录、Redis 前缀、归档目录、聊天档临时目录——全部是工程参数，默认收起。引用一致性自检建议生产保持开启 |
| **目标模式**（4 项，2 节） | **推进与轮次**（自动推进轮数上限）、**预算与恢复**（Token 预算、时长预算、工具调用预算）；四项硬预算**填 0 = 该项不限制**，出厂即不限制 |

> 统一认证源不在系统设置里：在「权限管理 → 认证源」页签维护（管理员），四类——OIDC / SAML（登录认证）、SCIM / LDAP（账号供给与目录同步），每源独立启停；`clientSecret`、`bindPassword`、`spPrivateKey`、SCIM Bearer 等敏感字段 RSA 加密入库、不回显明文，编辑时留空即沿用已存值。成员管理页可按账号逐源解绑身份。详见《团队与权限》的「认证方式」。

> 深度思考不设全局面板：思考强度在对话页按模型选择（见《对话与问答》）。上下文窗口没有档位选择，恒取模型登记上限；历史压缩由框架按模型窗口自动触发，没有开关。

## 个人设置的内容

分五组：**个人资料**（头像上传与 emoji 图标、昵称）、**默认模型**（聊天模型，选完即存、无保存按钮）、**我的记忆**（自动提炼开关、`MEMORY.md` 查看编辑与清空、按天查看与删除日账、按上限裁剪、全部清除）、**分享管理**（本人生效中的会话分享，含访问次数、预览、换链接、停止与清除记录）、**账号安全**（修改密码，改成功后需重新登录）。

默认聊天模型仅在会话未选定模型时生效（如新会话的第一问）；会话选定模型后（手动选择，或每轮结束时记录该轮实际生效的模型），后续轮次沿用会话的模型，修改个人默认不影响已有会话。

**平台侧的固定口径**：相关建议固定 3 条；新会话空态不展示示例问题卡；没挑助手时由工作区或平台的默认智能体作答；技能的平台停用只有管理员能执行（对全平台停）；工具执行上限只有系统设置里的**平台上限**，个人没有自己那份。

**模型类没有个人默认槽位**：向量 / 视觉 / OCR 模型归知识库绑定（向量空间与库索引一一对应），重排归知识库绑定（选了才重排），问答对生成与 GraphRAG 抽取跟随「库主」的个人默认聊天模型（GraphRAG 优先用库级绑定的抽取模型），记忆提炼复用本轮会话模型。「平台内置向量化模型」是管理员登记的全平台键（使用平台自己的 Key），作为全体用户记忆语义能力的兜底，不是个人项。

## 生效时机（需留意的例外）

- **需重解析或新上传才生效**：分块大小、重叠、结构感知切分、标题层级、问答对与父子分块、PDF 解析引擎等解析参数——它们只影响之后的解析，存量文档需手动重解析
- **全部设置项保存即生效**：没有需要重启才生效的旋钮——解析并发、工作流并发上限与排队容量、沙盒热池预热数量等改动都按新值即时运行
- **不放进设置页的部署属性**：引擎工作区目录、Redis 前缀、会话日志归档目录、聊天临时目录、会话目录根——它们由环境变量或配置表决定，设置页底部只读展示当前值。换目录等于换一批数据，存量不会跟着迁移，所以不给它一个就地改写的输入框
- **停用或删除供应商 / 模型不会自动改动选过它的地方**：知识库的向量 / 图谱 / 重排 / 解析模型、文档的图片理解模型、定时任务与工作流节点里选的模型、个人默认模型、系统配置槽位、公开分享链接的游客模型、历史会话记住的模型，都可能还指着它
- **停用后去哪改**：停用成功时当场列出还在使用它的位置，逐条点「去修改」直接打开能改它的那个框（知识库配置弹窗、任务 / 工作流编辑器、公开发布弹窗、系统设置对应参数），并把要改的那一项高亮；关掉弹窗后供应商卡片上仍留着「停用后仍有 N 处在用它的模型 · 查看引用」，随时回得来，清单里的「历史会话」支持一次清除这些会话的选择。对话页与个人设置会把不能用的那一项在原地标红并写出原因，问答时自动改用可用的那个并留一条说明
- **切换向量模型**必然触发该库全量重嵌入（与知识块数成正比，万级块可达数十分钟），期间向量检索降级关键词路；重嵌入只在知识库编辑里换绑模型时按库触发，没有平台级重嵌入口，建议避开业务高峰
