# 工作流

可视化工作流把「检索、生成、分支、调用、审核」编排成可重复运行的流程。DSL（JSON）是唯一真源：画布只是编辑器，引擎只按 DSL 执行；结构校验 fail-loud（节点数上限 100、连线数上限 300，条件 / 人工审核 / 循环三类节点的分支出边必须连线）。

入口在「智能体 → 工作流」；工作流的归属可以选一个工作区，之后它会出现在该工作区页的「自动化」栏。

## 13 类节点

左侧节点面板按用途分组：

| 分组 | 节点 | 说明与输出 |
|------|------|------------|
| 流程 | **开始** | 声明本轮入参，入参键供下游引用（固定 `{{start.参数名}}`） |
| 流程 | **结束** | 映射最终出参；`answer` 出参可作为 chatflow 的回答 |
| 模型 | **LLM 调用** | 把 prompt 发给对话模型（模型引用过判权），token 流式透传；输出 `answer` |
| 模型 | **子智能体** | 委派某个智能体按它自己的配置作答，复用完整问答管线，临时会话执行完即删除；输出 `answer` |
| 数据 | **知识检索** | 按知识库范围召回片段，受库与文档的可见性判定约束；输出 `chunks` / `text` / `count` |
| 数据 | **HTTP 请求** | 调用外部接口，逐跳 SSRF 内网校验、2MB 读取上限；输出 `status` / `body` / `contentType` |
| 数据 | **代码执行** | Python / Node 在 Docker 沙盒内执行，非 0 退出码 fail-loud；输出 `output` / `exitCode` |
| 数据 | **模板转换** | 把多路上游输出拼成一段文本；输出 `text` |
| 控制 | **条件分支** | SpEL 安全求值（禁 `T()` 与构造器）按表达式命中分支；输出 `route` |
| 控制 | **人工审核** | 流程挂起 → 审批卡裁决 → 按快照续跑，已完成节点短路回放、零重复消耗；批准与拒绝各走一支；输出 `route` |
| 控制 | **循环** | 按分支回跳重跑，`maxLoops` 编译期与运行期双闸；输出 `route` / `loopCount` |
| 生态 | **技能** | 把所选技能的正文注入下游 LLM 上下文；输出 `text` / `skills` |
| 生态 | **MCP 工具** | 调用名下一个 MCP 服务里的某个工具；输出 `result` / `server` / `tool` |

变量引用统一写法 `{{节点id.输出键}}`。HTTP 节点的 Header 值可写 `{{credential:凭据名称}}`，运行时按**运行发起人**解密填入。

## 凭据管理

工作流凭据是个人资产：值加密落库、出参脱敏，只在运行时解密使用。可在画布工具条的「凭据」弹窗新建与删除，也可在 HTTP 节点属性里点「管理凭据」就地维护。

## 画布编辑器

- 节点面板拖拽或点击添加、右键节点 / 连线 / 画布的快捷菜单、连线校验（禁自环、禁非法回跳、条件出边选分支）、网格吸附与小地图、缩放控件
- 右侧属性抽屉分「属性 / 运行输出」两页；属性页顶部是该节点的作用说明与入参、输出键
- **画布内调试**：填入参 → 同步运行 → 逐节点 trace 回放染色（成功 / 失败 / 待审核 / 进行中 + 耗时）→ 点节点看输入输出与 token

## 运行与版本

- **发布与版本**：草稿可继续修改，**发布**把当前 DSL 冻结为一版；回滚是以历史 DSL 再发一版（版本号递增，历史不改写）。运行读已发布快照，未发布或已下线的工作流不执行
- **每次运行锁定当时的 DSL 快照**，改画布不影响已经跑过的 run
- **运行历史**为独立整页：run 列表 + 节点级 trace 回放 + 待审批运行就地裁决；运行过程中可订阅实时进度流（SSE）
- **批量操作**：批量发布、下线、导出与删除

## 触发方式

| 方式 | 说明 |
|------|------|
| 画布手动运行 | 调试与试跑 |
| **定时触发** | 5 段 cron + 时区，只跑已发布版本；支持「立即运行一次」 |
| **运行终态回调** | 配置回调地址与签名密钥，运行结束时以 `X-Wenqu-Signature: sha256=…`（对请求体做 HMAC-SHA256）通知；回调超时 10 秒，失败只告警、不影响运行结果；地址不得指向内网 |
| **API 触发** | `POST /api/ai/v1/workflows/{id}/run`，持 API Key（`X-Api-Key` 头）触发**已发布**版本；含人工审核节点的工作流一律拒绝 API 触发；按 runId 可查运行结果 |
| **chatflow 绑定** | 智能体的运行方式选「工作流」并绑定已发布版本后，对话由工作流驱动，结束节点 `answer` 即回答，LLM 节点 token 流式透传 |

## 运行治理

单次运行的最大图步数（默认 50，超限 fail-loud）、运行超时（默认 10 分钟）、子智能体节点等待超时、并发上限与排队容量、运行记录保留期（默认 30 天）与人工审核超时回收间隔都在「系统设置 → 定时任务 → 工作流运行治理」中调整；并发与排队两项改动需重启。挂起超过节点等待时限的人工审核 run 会被自动落 timeout 终态。

## 模板与迁移

- **模板库**：平台内置可运行的工作流 DSL（检索问答 / 并行多视角 / 审核流水线），点「使用模板」即以此为基础新建
- **导出与导入**：导出为 `{name, description, dsl}` JSON，可跨环境导入；导入同时兼容包含多条物品的 `{items:[…]}` 形式与裸 DSL
- **市场分发**：把工作流上架到市场，同事安装即复制为自己的草稿（见《技能与沙盒》的「市场」一节）
