# 技能包与沙盒

## 技能包（Skills）

技能是「目录 + SKILL.md」形式的可插拔能力：一段写好的做法说明，模型按它执行。技能的创建与修改由助手完成，读取侧保证可查——技能正文逐字带入本轮提问，其内容在界面上可见。

三类来源，同名时后一类覆盖前一类：

| 标在清单上的名字 | 从哪来 | 谁能改 |
|---|---|---|
| 内置 | 随版本分发，全体用户可用 | 不可修改（需管理员改这一版的内容） |
| 我的 | 当前用户名下的技能目录 | 在对话中让助手修改 |
| 工作区 | 助手在对话中沉淀下来的做法，存放在沙盒工作区 | 在对话中让助手修改或删除 |

- 每轮问答，模型先获得「有哪些技能、各自适用什么」的清单，需要时才读取正文（先列目录再读全文，不一次性占满上下文）
- 在输入框「+」→ 引用资料 → 技能页签中指定若干条技能时，该轮直接带上这几条的正文，即要求按该做法执行
- **查看正文**：输入框「+」→ 引用资料 → 技能页签 → 该行右侧的「查看正文」；智能体配置页选择「指定」技能后，下方「已选正文」可直接点开。这里显示的内容与模型实际获得的内容一致
- **停用某条**：只有管理员可停用，且对全平台生效——在 系统设置 → 工具调用 → 技能 页签中多选。被停用的技能从下一问起不进入模型清单；需要临时使用一次，可在输入框中指定带上
- 「工作区」来源只可查看、不可指定，也不受「停用」影响——它随会话存在，需要处理请在对话中说明
- 沉淀技能需要沙盒可用；智能体的权限档位为「只读调研」时，助手不能新建也不能改写技能

按用户隔离：个人名下的技能只对本人生效。

## 市场（好东西的分享与分发）

市场是团队内部的资产分发入口：技能、应用模板（智能体）、工作流三类物品，上架一次、同事一键安装。入口在侧栏「市场」。

- **安装即复制**：安装把上架时的快照完整复制成安装者自己的资产——技能进自己的技能目录、应用模板 fork 成自己的智能体、工作流复制成自己的草稿。作者此后改版、下架、删除，都不影响已装副本
- **上架**：市场页的「上架」弹窗里选类型（技能 / 应用模板 / 工作流），或技能页自己技能卡片上的「上架」直达。同一物品重复上架等于更新同一条（快照覆盖、重新上架）；内置技能随版本分发人人都有，无需上架
- **版本号与「有更新」**：上架时可填版本号（留空记为 1），仅用于展示。「有更新」徽标按快照内容自动判定：重新上架后内容有变化，装过的人就会看到提示；只改市场卡片上的简介/标签则不会误报。技能点「更新」覆盖重装一份；应用模板/工作流点「装新版」是再复制一份新的（旧副本由自己处置）
- **应用模板（智能体）**：上架配置快照（人设/知识范围/工具开关/技能与 MCP 引用），绑定了工作流时连同工作流一起带上。别人安装 = fork 成他的智能体，引用按安装人权限自动裁剪并逐项提示：不可读的知识库剔除（全数剔除时检索回落默认知识库）、未登记的同名 MCP 剔除、缺装的技能保留引用并提示（去技能市场装上即生效）；附带的工作流复制为已发布副本并自动重链。子智能体委派关系不随模板走
- **工作流**：上架当前画布的 DSL；安装 = 复制一份成为自己的草稿。工作流页另有导出/导入（与市场同一份 {name, description, dsl} 格式），可跨环境迁移
- **官方条目**：内置工作流模板（检索问答/并行多视角/审核流水线）以「平台官方」名义在市场提供，开箱即装；官方条目不可删除，不需要时管理员可下架
- **详情页**：安装前可查看详细介绍与内容全文（技能=SKILL.md，应用模板/工作流=完整配置 JSON），也可下载物品包留档
- **四个页签**：技能 / 应用模板 / 工作流按类型浏览，「我的上架」跨类型只列自己的，用于管理——下架后列表不再展示、安装被拒，已装副本不受影响；删除连物品包与安装记录一起删。页签上的数字是各自条数（与搜索条件一起变），刷新/回退仍停在原页签，带 `?tab=mine` 的地址可直接发给同事
- 技能安装走与上传 zip 相同的校验链（路径穿越、体积、条目数全部校验）；同名冲突时需确认覆盖（覆盖会整包替换旧技能及其附属文件）

## 沙盒隔离执行

模型经 Function Calling 在隔离 Linux 容器内获得 8 个工具（开启「沙盒脚本」后再加 1 个，见下）：

| 界面上的名字 | 说明 |
|------|------|
| 执行沙盒命令 | 执行 shell 命令，**输出实时流式回传**（执行过程中持续输出） |
| 读取沙盒文件 / 写入沙盒文件 | 读文件 / 写文件（无则新建、有则整体替换；局部修改用「编辑沙盒文件」） |
| 编辑沙盒文件 | 精确替换修改 |
| 列出沙盒目录 | 浏览目录 |
| 检索沙盒内容 | 按关键词跨多个文件检索 |
| 按模式查找文件 | 按文件名模式查找，例如「所有 .md」 |
| 交付产物 | 把文件交付为「我的产物」 |

### 沙盒脚本（批量执行同类操作）

开启 `tool.runcode.enabled`（默认关）后，模型还能使用第 9 个工具 **run_code**：由它写一段脚本在沙盒中执行，脚本内部可继续调用本轮已挂载的工具。两种语言可选——Python（默认）与 JavaScript（Node）：Python 里写 `import wenqu_tools as wq`，JavaScript 里写 `const wq = require('./wenqu_tools')`。模块由系统按**本轮实际挂载的工具**当场生成，本轮未挂载的工具，模块中就没有对应函数。

- **适用场景**：「把这 30 份文档逐一汇总」「每个库都查一遍再对比」这类批量操作。不用脚本时是一串来回调用，且会触及单轮工具步数上限；用脚本时由一段程序批量发起，只把打印结果带回对话。
- **不是旁路**：脚本内的每次调用与模型直接调用走同一套管控——本轮未挂载的工具脚本同样调不到；写到沙盒目录外仍被拒绝；点「停止本轮」后脚本剩余的调用全部中断（运行凭据当场作废）。
- **只有打印内容会回到对话**（print / console.log，函数返回值不回传），因此脚本应只打印结论与关键数字。需要保留的文件仍要通过「交付产物」交付。
- 点开「执行脚本」工具卡可查看**本次运行发起了哪些调用**——每个调用的名称、耗时与结果首行。这些调用不各自成卡：一次发起几十个调用会在过程区堆成一片，也看不出它们属于同一次运行。
- **执行中为实时状态**：卡片标题旁显示「子调用 N 次 · 在途 K」，展开可见脚本自身的输出逐行追加、本轮额度已用量（如「本轮额度 12/50」）、并发上限，以及本次交回的文件数。分多段执行时，每张卡只统计**该段**自己的调用
- **失败形态分别标注**：追踪超时（脚本可能仍在沙盒中执行）、沙盒未连通（非脚本问题）、退出码非 0 会直接标在卡片上；正常结束但无任何打印输出时，同样提示只有打印内容才会回传
- 额度分两处：脚本自身受「单次脚本子调用上限」约束（系统设置 → 工具调用），不占用模型的单轮工具步数——一次发起几十个调用不会耗尽后续步骤的额度。另有脚本运行上限、单次调用超时、脚本内并发上限三项在同处。
- 前提是回调地址配置为**容器可访问**的本服务地址。该项不在设置页里，走环境变量 `SANDBOX_CALLBACK_BASE_URL`（本机部署默认 `http://host.docker.internal:8090/ai`；生产跨网络时需换成容器侧可达的地址）。未配置时脚本内调不到任何工具，并直接提示「回调地址未配置」。
- 「工具执行确认=执行前确认」时不提供该工具：一次发起会产生同等数量的确认卡，用户在第一张卡上无法预见后续动作。需要脚本时请先选择自动执行。
- **脚本内可并发发起的是取数与计算类调用**：知识库检索、联网搜索、计算、日期换算；模块中有哪些函数取决于本轮实际挂载了哪些工具。**沙盒的文件读写、列目录、查找文件与交付产物不在脚本模块内**（这几项由模型直接调用），**脚本内再执行命令行也不提供**——实测该路径存在结果无法回传的情况，表现为脚本停在某次调用上直到超时。需要执行命令时由模型使用「执行沙盒命令」工具，同样有实时输出

- **作用域挂在会话上**：容器与沙盒目录都以会话为界——同一会话的文件跨轮保留（容器回收重建后仍在），不同会话互相不可见；会话空闲（默认 60 分钟）自动回收容器
- 命令超时/输出上限/keepalive 均可配；瞬时故障自动重试
- 对话右栏的**沙盒文件**卡列出该会话沙盒目录的内容：按目录折叠成一棵树（同级按最近改动在前），目录行显示本层连同子目录的文件数与合计大小，文件行显示自身大小，悬停在名字上可见整条相对路径。点目录行可收起。每条文件有三个动作：**打开**（可预览的类型在新标签页打开）、**下载**、**存为产物**（存入「我的产物」，与模型主动交付的条目一致）。一次只列最近修改的一批文件，未列全时卡底写明「另有 N 个文件没列出」。该列表读取的是服务器上的目录，**容器回收后仍可列出**——文件一直保留在服务器上
- 它覆盖的是「交付产物」未发生的情况：助手把文件写入沙盒但未交付（最常见的是本轮到达推理步数上限被截断，收尾步骤未执行）时，这些文件依然可见。反之，助手**主动交付**过的文件同时出现在「产物」卡和这里，不需要二选一
- 产物在「我的产物」页（/artifacts）汇总：预览（一整屏，网页可切视口宽度、Markdown/代码/表格就地排版；Excel 与压缩包不提供）、下载（签名 URL）、移动到其他工作区、删除；交付文件按扩展名白名单净化，单个 ≤1MB（「存为产物」走同一条路，受同样两道限制）

> 沙盒开关 `tool.sandbox.enabled` 默认关；启用需部署 sandbox provisioner 并在系统设置「沙盒」面板配好连接与访问令牌（令牌须与 provisioner 侧一致且 ≥32 字符）。

## 权限档位

「智能体 → 工具与能力」里的**权限档位**决定该智能体可改动的范围（留空=跟随平台默认档）：

| 档位 | 实际表现 |
|------|----------|
| 只读调研 | 可读取沙盒已有文件、列目录；**不执行命令、不写文件**——这两类工具不暴露给模型，而不是调用后被拒绝；调用外部工具每次均需确认 |
| 常规（默认） | 可执行命令、可在沙盒目录内读写文件；写到沙盒目录外会被拒绝 |
| 全自主 | 不限制写入范围，也不逐项确认 |

- 只需移除个别工具时：「智能体 → 能力 → 禁用指定工具」按名字勾选，其余照旧。它与「指定内置工具」方向相反——白名单要把使用的每个工具逐个勾选（平台新增工具时该名单不会自动跟上），这里只写需要去掉的那几个。被禁用的工具同样不进入模型的工具表。
- 档位与「工具执行确认」分别管两件事：档位决定**可做什么**，确认决定**执行前是否请求确认**。两者都设置时，以智能体自己的「工具执行确认」为准。
- 管理员在系统设置「工具调用 → 权限档位」可设**平台上限**：上限设为「只读调研」后，全部智能体的命令执行与沙盒写入一起消失；选了高于上限档位的智能体按上限执行，并在回答的过程面板里说明被收紧。同处还有一项**平台停用工具名单**：从下拉里选本平台已注册的工具（可搜中文名或工具名；外部 MCP 工具按用户动态接入、没有静态名册，可直接输入名字），选中的对全平台都不提供——范围比关闭整个工具族更精确，也不需要逐个智能体设置。

## 内置工具

计算器（递归下降表达式求值，仅四则/幂/括号，**不执行任意代码**）、日期、知识检索（命中块进引用流）、产物交付、技能读取。工具由系统设置的**问渠工具总开关**（`tool.enabled`，默认开）统一启用，各工具族不再有独立开关；沙盒与沙盒脚本是例外，各自默认关闭（`tool.sandbox.enabled` / `tool.runcode.enabled`）。

## 联网搜索

模型可调用联网搜索获取公网网页资料（**默认关**，管理员在「系统设置 → 工具调用 → 联网搜索」页签开启；服务商支持 Tavily / 博查 / 自建 SearXNG）：

- **结果进引用体系**：搜索返回的网页与知识库来源共用同一套 `[N]` 编号，回答里标注后可在引用面板点开看站点、摘要与外链
- **按本轮问题做相关性过滤**：返回结果按本轮问题（多轮为指代消解后的检索查询）重排，低于「检索设置 → 最低相关分」的不列为引用、不交给模型——服务商自带的相关度分（如位置衰减）不具相关性含义，不参与判定。重排不可用时会明确提示「本轮搜索结果未经相关性过滤」：保留未过滤的结果，而不是因一次瞬时故障导致完全无结果
- **配额与审批**：单轮搜索次数可配（限制反复搜索带来的 token 消耗）；可纳入「执行前确认」审批；游客分享链路不暴露联网搜索
