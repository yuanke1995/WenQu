# 技能与沙盒

## 技能包（Skills）

技能是「目录 + `SKILL.md`」形式的可插拔能力：一段写好的做法说明，模型按它执行。技能的创建与修改可由助手完成，读取侧保证可查——技能正文逐字带入本轮提问时，其内容在界面上可见。

三类来源，同名时后一类覆盖前一类：

| 界面上的分组 | 从哪来 | 谁能改 |
|---|---|---|
| **内置技能** | 随安装包分发，全体用户可用 | 不可修改，只可停用（需管理员） |
| **我的技能** | 当前用户名下的技能目录 | 本人编辑，或在对话中让助手修改 |
| **工作区技能** | 助手在对话中沉淀下来的做法，存放在沙盒工作区 | 只读；需要处理请在对话中说明 |

- 每轮问答，模型先获得「有哪些技能、各自适用什么」的清单，需要时才读取正文（先列目录再读全文，不一次性占满上下文）
- 在输入框「+」→ 引用资料 → 技能页签中指定若干条技能时，该轮直接带上这几条的正文，即要求按该做法执行
- **查看正文**：技能页与引用面板的每行都有「查看正文」；智能体配置里选择「指定」技能后，下方「已选正文」可直接点开。这里显示的内容与模型实际获得的内容一致
- **停用**分两级：**个人停用**只影响自己（技能页每行的启停开关）；**平台停用**由管理员在「系统设置 → 工具调用 → 技能」中多选执行、对全平台生效。被停用的技能从下一问起不进入模型清单，需要临时使用一次可在输入框中指定带上
- 「工作区技能」只可查看、不可指定，也不受停用影响——它随会话存在
- 沉淀技能需要沙盒可用；智能体的权限档位为「只读调研」时，助手不能新建也不能改写技能
- 按用户隔离：个人名下的技能只对本人生效

### 安装与分发

- **新建技能**：填技能名（中英文 / 数字 / 下划线 / 连字符，1~64 字，建后不可改）、描述（必填，模型靠这句判断要不要读取）与正文，frontmatter 由系统补全
- **上传 zip**：`SKILL.md` 位于根目录或唯一的外层目录，可带 `references/`、`scripts/` 等附属文件；逐条目校验路径穿越、体积与条目数；同名时需确认覆盖（覆盖会整包替换旧技能及其附属文件）
- **从 URL 安装**：只允许从管理员在「系统设置 → 工具调用 → 技能 → 允许远程安装的域名」中登记的域名拉取，地址须指向 `SKILL.md` 原文；逐跳校验公网可达，未登记时该入口不可用
- 技能卡可**下载**（zip）与**上架到市场**；正文读取上限 20000 字

## 市场

市场是团队内部的资产分发入口：技能、应用模板（智能体）、工作流三类物品，上架一次、同事一键安装。入口在侧栏「市场」。

- **安装即复制**：安装把上架时的快照完整复制成安装者自己的资产——技能进自己的技能目录、应用模板 fork 成自己的智能体、工作流复制成自己的草稿。作者此后改版、下架、删除，都不影响已装副本
- **上架**：市场页的「上架」弹窗里选类型（技能 / 应用模板 / 工作流）与具体条目，填一句话简介（必填）、详细介绍、标签与版本号（留空记为 1，仅用于展示）。技能页每行的「上架」直达同一弹窗。同一物品重复上架等于更新同一条（快照覆盖）
- **「有更新」判定**：按快照内容自动判定——重新上架后内容有变化，装过的人就会看到提示；只改市场卡片上的简介或标签不会误报。技能点「更新」覆盖重装一份；应用模板与工作流点「装新版」是再复制一份新的（旧副本由自己处置）
- **应用模板（智能体）**：上架配置快照（人设 / 知识范围 / 工具开关 / 技能与 MCP 引用），绑定了工作流时连同工作流一起带上。别人安装时引用按安装人权限自动裁剪并逐项提示：不可读的知识库剔除（全数剔除时检索回落默认知识库）、未登记的同名 MCP 剔除、缺装的技能保留引用并提示（去技能市场装上即生效）；附带的工作流复制为已发布副本并自动重链。子智能体委派关系不随模板走
- **工作流**：上架当前画布的 DSL；安装即复制为自己的草稿。工作流页另有导出与导入（与市场同一份 `{name, description, dsl}` 格式），可跨环境迁移
- **官方条目**：内置工作流模板（检索问答 / 并行多视角 / 审核流水线）以「平台官方」名义在市场提供，开箱即装；官方条目不可删除，不需要时可由管理员下架
- **详情页**：安装前可查看详细介绍与内容全文（技能即 `SKILL.md`，应用模板与工作流为完整配置 JSON），也可下载物品包留档
- **四个页签**：技能 / 应用模板 / 工作流按类型浏览，「我的上架」跨类型只列自己的，用于管理——下架后列表不再展示、新的安装被拒绝，已装副本不受影响；删除会连物品包与安装记录一起删。页签上的数字是各自条数（与搜索条件一起变化），刷新或回退仍停在原页签，带 `?tab=mine` 的地址可直接发给同事

## 沙盒隔离执行

模型在隔离 Linux 容器内执行命令与读写文件。界面上的工具名称如下：

| 界面上的名字 | 说明 |
|------|------|
| 执行沙盒命令 | 执行 shell 命令，**输出实时流式回传**（执行过程中持续输出） |
| 读取沙盒文件 / 写入沙盒文件 | 读文件 / 写文件（无则新建、有则整体替换；局部修改用「编辑沙盒文件」） |
| 编辑沙盒文件 | 精确替换文件中的某段内容 |
| 列出沙盒目录 | 浏览目录 |
| 检索沙盒内容 | 按关键词跨多个文件检索 |
| 按模式查找文件 | 按文件名模式查找，例如「所有 .md」 |
| 交付产物 | 把文件交付为产物，进入「我的产物」与回答末尾的产物卡 |

技能与记忆也有对应的工具：**读取技能正文**、**管理我的技能**、**创建技能草案**、**检索长期记忆**、**读取记忆内容**、**写入长期记忆**，以及 **检索 / 列出 / 读取历史会话**。这些工具按智能体的能力开关挂载，未挂载时不出现在模型的工具表里；界面统一显示中文名称，不出现英文裸名。

### 沙盒脚本（批量执行同类操作）

开启「工具调用 → 沙盒脚本」（默认关）后，模型还能使用 **执行脚本** 工具：写一段脚本在沙盒中执行，脚本内部可继续调用本轮已挂载的工具。两种语言可选——Python（默认）与 JavaScript（Node）：Python 里写 `import wenqu_tools as wq`，JavaScript 里写 `const wq = require('./wenqu_tools')`。模块由系统按**本轮实际挂载的工具**当场生成，本轮未挂载的工具，模块中就没有对应函数。

- **适用场景**：「把这 30 份文档逐一汇总」「每个库都查一遍再对比」这类批量操作。不用脚本时是一串来回调用，且会触及单轮工具步数上限；用脚本时由一段程序批量发起，只把打印结果带回对话
- **不是旁路**：脚本内的每次调用与模型直接调用走同一套管控——本轮未挂载的工具脚本同样调不到；写到沙盒目录外仍被拒绝；点「停止本轮」后脚本剩余的调用全部中断（运行凭据当场作废）
- **只有打印内容会回到对话**（print / console.log，函数返回值不回传），因此脚本应只打印结论与关键数字。需要保留的文件仍要通过「交付产物」交付
- 点开「执行脚本」工具卡可查看**本次运行发起了哪些调用**——每个调用的名称、耗时与结果首行。这些调用不各自成卡：一次发起几十个调用会在过程区堆成一片，也看不出它们属于同一次运行
- **执行中为实时状态**：卡片标题旁显示「子调用 N 次 · 在途 K」，展开可见脚本自身的输出逐行追加、本轮额度已用量（如「本轮额度 12/50」）、并发上限，以及本次交回的文件数。分多段执行时，每张卡只统计**该段**自己的调用
- **失败形态分别标注**：追踪超时（脚本可能仍在沙盒中执行）、沙盒未连通（非脚本问题）、退出码非 0 会直接标在卡片上；正常结束但无任何打印输出时，同样提示只有打印内容才会回传
- **额度分两处**：脚本自身受「单次脚本子调用上限」约束（系统设置 → 工具调用），不占用模型的单轮工具步数——一次发起几十个调用不会耗尽后续步骤的额度。另有脚本运行上限、单次调用超时、脚本内并发上限三项在同处
- 前提是回调地址配置为**容器可访问**的本服务地址。该项不在设置页里，走环境变量 `SANDBOX_CALLBACK_BASE_URL`（本机部署默认 `http://host.docker.internal:8090/ai`；生产跨网络时需换成容器侧可达的地址）。未配置时脚本内调不到任何工具，并直接提示「回调地址未配置」
- 「工具执行确认 = 执行前确认」时不提供该工具：一次发起会产生同等数量的确认卡，用户在第一张卡上无法预见后续动作。需要脚本时请先选择自动执行
- **脚本内可并发发起的是取数与计算类调用**：知识库检索、联网搜索、计算、日期换算；模块中有哪些函数取决于本轮实际挂载了哪些工具。**沙盒的文件读写、列目录、查找文件与交付产物不在脚本模块内**（这几项由模型直接调用），**脚本内再执行命令行也不提供**——该路径存在结果无法回传的情况，表现为脚本停在某次调用上直到超时。需要执行命令时由模型使用「执行沙盒命令」工具，同样有实时输出

### 作用域、限额与文件

- **作用域挂在会话上**：容器与沙盒目录都以会话为界——同一会话的文件跨轮保留（容器回收重建后仍在），不同会话互相不可见；会话空闲（默认 60 分钟）自动回收容器。工作区开启「共用目录」时，本区对话共用该工作区目录
- 命令超时（默认 180 秒）、输出上限与回收间隔均可配；瞬时故障自动重试
- 命令到点未结束只是不再等待，进程仍会存活——这类进程在对话右栏的「后台进程」卡上可见并可停止（连同其子进程）。见《对话与问答》
- 对话右栏的**沙盒文件**卡列出该会话沙盒目录的内容：按目录折叠成一棵树（同级按最近改动在前），目录行显示本层连同子目录的文件数与合计大小，文件行显示自身大小，悬停在名字上可见整条相对路径，点目录行可收起。每条文件有三个动作：**打开**（可预览的类型进预览台）、**下载**、**存为产物**（存入「我的产物」，与模型主动交付的条目一致）。一次只列最近修改的一批文件，未列全时卡底写明「另有 N 个文件没列出」。该列表读取的是服务器上的目录，**容器回收后仍可列出**
- 它覆盖的是「交付产物」未发生的情况：助手把文件写入沙盒但未交付（最常见的是本轮到达推理步数上限被截断，收尾步骤未执行）时，这些文件依然可见。反之，助手**主动交付**过的文件同时出现在「产物」卡和这里
- 产物在「我的产物」页（`/artifacts`）汇总：预览（一整屏，网页可切视口宽度、Markdown / 代码 / 表格就地排版；Excel 与压缩包不提供）、下载（签名 URL）、移动到其他工作区、删除；交付文件按扩展名白名单净化，单个 ≤1MB（「存为产物」走同一条路，受同样两道限制），超期由清理任务按保留期（默认 90 天）删除

> 沙盒开关 `tool.sandbox.enabled` 默认关；启用需部署 sandbox provisioner 并在系统设置「沙盒」面板配好连接与访问令牌（令牌须与 provisioner 侧一致且 ≥32 字符）。

## 权限档位

「智能体 → 高级设置」里的**权限档位**决定该智能体可改动的范围（留空 = 跟随平台默认档）：

| 档位 | 实际表现 |
|------|----------|
| **只读调研** | 可读取沙盒已有文件、列目录；**不执行命令、不写文件**——这两类工具不暴露给模型，而不是调用后被拒绝；调用外部工具每次均需确认 |
| **常规**（默认） | 可执行命令、可在沙盒目录内读写文件；写到沙盒目录外会被拒绝 |
| **全自主** | 不限制写入范围，也不逐项确认 |

- 只需移除个别工具时：「智能体 → 高级设置 → 工具黑名单」按名字勾选，其余照旧。它与「指定内置工具」方向相反——白名单要把使用的每个工具逐个勾选（平台新增工具时该名单不会自动跟上），这里只写需要去掉的那几个。被禁用的工具同样不进入模型的工具表
- 档位与「工具执行确认」分别管两件事：档位决定**可做什么**，确认决定**执行前是否请求确认**。两者都设置时，以智能体自己的「工具执行确认」为准
- 管理员在系统设置「工具调用 → 权限档位」可设**平台上限**：上限设为「只读调研」后，全部智能体的命令执行与沙盒写入一起消失；选了高于上限档位的智能体按上限执行，并在回答的过程面板里说明被收紧
- 同处还有一项**平台停用工具名单**：从下拉里选本平台已注册的工具（可搜中文名或工具名；外部 MCP 工具按用户动态接入、没有静态名册，可直接输入名字），选中的对全平台都不提供——范围比关闭整个工具族更精确，也不需要逐个智能体设置

## 内置工具

工具族共八类：**内置高频工具**（算术计算——递归下降表达式求值，仅四则 / 幂 / 括号，**不执行任意代码**；当前时间；日期差）、**知识库精确检索**（命中块进引用流）、**产物交付**、**技能**、**任务清单**、**联网搜索**、**沙盒执行**、**MCP 外部工具**。

工具由系统设置的**问渠工具总开关**（`tool.enabled`，默认开）统一启用，各工具族不再有独立开关；沙盒与沙盒脚本是例外，各自默认关闭。「系统设置 → 工具调用 → 总开关与子工具」页底部提供只读的工具名册（按族分组）与技能名册（按来源分组并标出停用状态）。

## 联网搜索

模型可调用联网搜索获取公网网页资料（**默认关**，管理员在「系统设置 → 工具调用 → 联网搜索」页签开启；服务商支持 Tavily / 博查 / 自建 SearXNG）：

- **结果进引用体系**：搜索返回的网页与知识库来源共用同一套 `[N]` 编号，回答里标注后可在引用面板点开看站点、摘要与外链
- **按本轮问题做相关性过滤**：返回结果按本轮问题（多轮为指代消解后的检索查询）重排，低于「检索设置 → 最低相关分」的不列为引用、不交给模型——服务商自带的相关度分（如位置衰减）不具相关性含义，不参与判定。重排不可用时会明确提示「本轮搜索结果未经相关性过滤」：保留未过滤的结果，而不是因一次瞬时故障导致完全无结果
- **配额与审批**：单轮搜索次数可配（限制反复搜索带来的 token 消耗）；可纳入「执行前确认」审批；游客分享链路不暴露联网搜索
