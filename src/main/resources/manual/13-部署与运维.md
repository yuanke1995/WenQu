# 部署与运维（管理员）

## 环境变量

```bash
# 必填（缺失启动失败 fail-fast）
export DB_PASSWORD=xxx

# 基础设施（有默认值，按环境调整）
export DB_HOST=127.0.0.1  DB_PORT=3306  DB_NAME=wenqu_ai  DB_USERNAME=root
export REDIS_HOST=127.0.0.1  REDIS_PORT=6379  REDIS_PASSWORD=  REDIS_DB=0
export AI_IMAGES_DIR=./data           # 数据根目录（源文件 / 图片 / 产物 / 密钥）

# 框架工作区与技能目录（仅 env/yml）
export AI_AGENTSCOPE_STATE_DIR=./user-data/agentscope   # 个人记忆 MEMORY.md 与日账、plans、会话事件日志归档
export WENQU_SKILLS_USERS_DIR=./user-data/skills-users  # 用户自装技能的宿主目录
export LOG_DIR=./data/logs            # 应用日志目录（容器部署需指向挂载卷内，否则容器重建后丢失）

# 安全
export AI_JWT_SECRET=xxx             # 必填，≥32 位随机串；多副本必须一致（非 local profile 缺失即启动失败）
export AI_SECRETS_DIR=./data/secret   # 密钥目录（默认 {AI_IMAGES_DIR}/secret）：放版本化 PEM 私钥 rsa/vN.key

# 仅 env/yml（不进设置页）
export AI_MEILI_KEY=xxx              # Meilisearch master key
export AI_MEILI_INDEX=wenqu-chunks   # 关键词索引名（永不入库）
export SPRINGDOC_ENABLED=false       # Swagger 开关（默认关）

# 沙盒 / OCR 连接（不进设置页）
export SANDBOX_PROVISIONER_URL=http://127.0.0.1:8002
export SANDBOX_PROVISIONER_TOKEN=    # 与 provisioner 侧一致，≥32 字符
export SANDBOX_CALLBACK_BASE_URL=http://host.docker.internal:8090/ai   # 沙盒脚本回程地址，须容器可达
export SANDBOX_VIRTUAL_PATH_PREFIX=/home/gem/user-data
export OCR_PP_STRUCTURE_URI=  OCR_MINERU_URI=  OCR_MINERU_BACKEND=pipeline  OCR_TIMEOUT_MS=600000
```

启动：`mvn spring-boot:run` 或 `java -jar target/wenqu.jar`；Docker Compose 自包含（redis-stack + meilisearch + MySQL）：`docker compose up -d`。后端监听 `http://localhost:8090/ai`，健康检查 `/ai/actuator/health`。

表结构由启动自动执行 `schema.sql` 创建（57 张 `c_ai_*` 表，幂等）；存量库缺列缺索引由 `SchemaMigrator` 启动期自动补齐。

## Redis 是硬依赖

框架引擎的会话状态——对话上下文、待办、断线续跑游标——**始终存储在 Redis**，没有本地文件兜底。

- Redis 连不上时**应用启动直接失败**（不降级运行，也不只影响聊天功能）。配好 `REDIS_HOST / REDIS_PORT / REDIS_PASSWORD` 再启动
- Docker Compose 已含 `redis-stack` 且以 `service_healthy` 作为 app 的启动前置条件
- 键前缀 `chat.agentscopeRedisPrefix`（默认 `agentscope:session:`）避免与其它应用混用命名空间
- 跨副本协调（记忆提炼节流、合并水位）走同一套 Redis
- 存储在磁盘上、且需要共享的是**个人记忆文件**（`MEMORY.md` 与日账）——位置是 `AI_AGENTSCOPE_STATE_DIR`（默认 `user-data/agentscope`）。容器部署需把它指向挂载卷内，多副本还要挂成共享卷

## 多副本部署要求（摘要）

1. 数据目录必须共享（`AI_IMAGES_DIR` 指向共享存储；跨主机挂 NFS / 对象存储），框架工作区同理
2. 静态配置（env / yml）各副本一致，`AI_JWT_SECRET` 尤其必须一致（各副本随机生成会各签各验，登录随机 401）；容器部署按 `SPRING_PROFILES_ACTIVE=prod` 起，缺该密钥会直接启动失败而不是带随机密钥上线；动态配置经 Redis 广播
   - **智能体等人的卡片在任意副本都能答**：确认卡 / 提问卡 / 计划卡落到哪台都行，答复会转给持有这一轮的副本执行；
     同一条会话同时只允许一个「跟到收尾」的循环，跨副本也只会落一条回答；
   - **正在生成的回答可以跨副本接着看**：观众连到哪个副本都行——快照从跑出这一轮的副本取，增量经 Redis 转发；
     在任意副本点「停止」都会转给那一轮的宿主副本执行。宿主进程重启时那一段增量不补，按已落库的历史回显
3. 解析队列有界；总并发 = 副本数 × `parse.concurrency`，embedding 与视觉模型调用是共享瓶颈
4. 删除在任意副本生效，其他副本上的解析任务由 DB 兜底秒级停止并清理
5. 向量模型换绑全副本串行（Redis 分布式锁），锁持有期间向量检索自动降级关键词路
6. 多副本上线前把启动自愈类内部键 `keyword.reconcileOnStartup`、`parse.recoverStuckOnStartup` 置 false（启动对账收敛为单点）
7. **密钥目录必须共享**（默认 `{AI_IMAGES_DIR}/secret`，可用 `AI_SECRETS_DIR` 覆盖）：敏感数据用目录里 `rsa/vN.key` 的 PEM 私钥加密，各副本挂同一目录，否则 A 副本加密的凭据在 B 副本解不开。轮换见下节
8. `chat.sessionLogArchive.enabled` 默认开（保留 90 天 + 每日清理随默认值出厂）：归档目录必须指向共享卷，否则各副本各存一份、按会话无法合并
9. 目标模式与定时任务都靠 DB 条件更新取执行权（目标用租约、任务先推进 `next_run_at`），不需要额外中间件

## Kubernetes 部署与灰度发布

`deploy/helm/wenqu/` 是一份 Helm chart（后端与前端同源，一个 Deployment 就够，不需要单独部署 web）。
键的取值与理由写在 `values.yaml` 的注释里，这里只说三条会咬人的：

- **多副本必须共享存储**：产物、上传、个人记忆、用户自装技能都落盘。各副本各挂一块 `ReadWriteOnce` 卷，
  症状是同一份文件时而能打开时而 404。副本合计 > 1 而访问模式不是 `ReadWriteMany` 时，
  chart 在渲染阶段就直接拒绝（宁可装不上，也不要装成随机坏）。
- **`AI_JWT_SECRET` 与 `DB_PASSWORD` 没有默认值**：不给就不渲染，因为缺了它们后端会带随机密钥上线，
  多副本下等于登录随机 401。生产建议 `secrets.create=false` + `secrets.existingSecret` 指向外部管理的 Secret。
- **SSE 不能被缓冲、也不能被 60 秒读超时掐断**：ingress 注解里已写死 `proxy-buffering=off` 与一小时的读写超时，
  自己套一层网关时这两项要照抄。

灰度发布（`canary.enabled=true` + `canary.imageTag=<新>`）：稳定版与灰度版两个 Deployment、两条 Service，
Ingress 按权重或按请求头分流。先开 `canary.header` 让内部流量确定性地进灰度版验证，再放权重。
**灰度期两版共用同一套库与盘**，所以只放向后兼容的变更；带不兼容结构变更的版本要先全量备份再停机升级。
推进、全量切换与回滚的具体命令在 `helm get notes` 输出里（装完就打印），也在 `deploy/helm/wenqu/README.md`。

## 备份与按租户恢复

多租户部署里「只恢复某一家客户」是真实需求，而整库回滚会把别家一起倒回去。
`scripts/dr/tenant-dr.py` 按租户出包与回灌：

```bash
python3 scripts/dr/tenant-dr.py list                              # 有哪些租户、各多少成员
python3 scripts/dr/tenant-dr.py inventory --tenant acme           # 这个租户在库里与盘上的全部落点
python3 scripts/dr/tenant-dr.py backup   --tenant acme --out /backup/wenqu
python3 scripts/dr/tenant-dr.py backup   --all   --out /backup/wenqu   # 整库（盘上文件请备份卷）
python3 scripts/dr/tenant-dr.py restore  --from <包目录> --into-db wenqu_restore
python3 scripts/dr/tenant-dr.py verify   --from <包目录>
```

- 备份包含三部分：`structure/ddl.sql`（来源库的建表结构）、`db/<表>.sql`（该租户名下的行）、
  `files/*.tar.gz`（该租户成员的盘上目录）。结构单独放一个目录是刻意的——它带 `DROP TABLE`，
  和逐表数据文件混在一起按名字排序恢复，会把刚灌进去的行抹平。
- **目录映射由应用报，不由脚本算**：盘上路径按成员切分、名字规则写在后端各服务里，脚本抄一份必然漂移，
  所以备份时后端必须在线（`GET /api/ai/tenant/{id}/inventory`，仅平台级管理员可调）。
- 备份包自带结构，恢复不依赖仓库里的 `schema.sql`：库里可能存在退役设计留下的列（实体已不映射），
  只按 `schema.sql` 建表会让带完整列名的 `INSERT` 找不到列。
- 恢复后要做两件事：**知识库重新索引**（向量索引不在备份里，Redis 里的那份按库重建）；
  限流与配额的周期计数是临时值，重启后按用量台账重算，不需要人工补。
- 只解文件不动库：`restore --from <包> --skip-db --files-to <目录>`；同机灾难恢复用 `--files-in-place`
  （会覆盖原路径下的同名文件，需要 `--yes`）。

## 密钥与轮换

- **登录令牌签名密钥**：`AI_JWT_SECRET`（≥32 位随机串，`openssl rand -base64 48`）。各副本必须同一个值；
  换值等于全员重新登录。本地开发（`local` profile）可以不填，每次启动临时生成并告警。
- **敏感数据加密密钥**：密钥目录（`AI_SECRETS_DIR`，默认 `{AI_IMAGES_DIR}/secret`）下的 `rsa/vN.key`，
  一版本一个文件，文件名里的数字就是版本；新写入用版本号最大的那把，历史密文按自己记录的版本取钥解密。
  首次启动目录里没有密钥会自动生成 `rsa/v1.key` 并告警——多副本务必挂同一目录，别各生成一把。
- **轮换**（不停机、不中断已加密数据的读取）：
  1. 生成一把新私钥放进去：`openssl genrsa 2048 | openssl pkcs8 -topk8 -nocrypt > {密钥目录}/rsa/v2.key`
  2. 重启各副本（必须挂同一目录，否则新副本拿不到 v2）
  3. 启动日志出现 `[Rotation] 存量密文重封到当前密钥 v2：N 行`——此后所有密文都用 v2
  4. 确认无误后删掉 `rsa/v1.key`（上一版的密钥文件），再重启一次
- **`[Rotation] ... 解不开而保留原值 N 行`** 意味着密钥目录不是共享的那一份或旧密钥被提前撤了：
  补回对应版本的密钥文件再重启即可，这些数据不会被改坏（重封只在确实解得开时才改写）。

## 会话事件日志

框架引擎每轮把过程写成事件存入会话日志：正文之外的内容只记录在这里——工具入参与结果、思考段、待办与裁决时刻、插话、压缩留痕。日志本体落在宿主 `~/.wenqu/agent-journal/agents/…/sessions/…/{会话号}/`。

引擎每开始一轮都要读取该会话的事件链，代价随事件条数增长，长任务会话会在「发出提问」与「输出第一个字」之间出现一段明显等待。为此设置了换代阈值：

- `chat.agentscopeJournalRotateEvents`（默认 12000，0 = 关闭换代）：一条会话累计到该事件数时，在「上一轮已收口、本轮未开始」的静默点换代——导出当前上下文，把旧一代整目录搬到 `~/.wenqu/agent-journal/rotated/…/{时间戳}/`，新一代以一条 baseline 开始。换代前会先按框架游标把旧一代补写进归档，不留未归档事件。存在写者租约、未结算的执行或待裁决卡片时不执行换代，下一轮再试
- `chat.agentscopeJournalRotateKeepDays`（默认 30，0 = 不清理）：被搬走的旧代次保留天数，由「会话日志归档清理」任务按目录修改时间删除
- 换代只影响框架自带的历史检索能力（可读到本代之后的原始事件）。用户可见的历史不受影响：消息正文在数据库，逐轮过程在会话事件账本，全量明细在归档

### 归档

`chat.sessionLogArchive.enabled` 默认开，事件按会话导出成 JSONL 归档：

- 位置：`{chat.sessionLogArchive.dir}`，留空则为 `{chat.agentscopeStateDir}/session-archive/{归属号}/{会话号}.jsonl`（目录名是 URL-safe Base64，不含可读会话号）
- 一行一条事件，字段固定：`seq / at / eventId / type / runId / turnId / required / payload`；`payload` 是内嵌的原 JSON（不是转义字符串），可用 `jq` 或 grep 直接读取
- 增量与断点由框架管理：每条会话存一份导出水位，只补发水位之后的事件；进程崩溃后从原水位重投（至少一次语义，重投的是事件而非执行），归档不会因重启而从零重写
- 保留期 `chat.sessionLogArchive.keepDays`（按文件最后写入时间判定，0 = 不清理），清理间隔 `chat.sessionLogArchive.cleanupIntervalMs`
- 归档**只写文件**：界面不提供下载，由运维按文件读取；子智能体分支是另一条会话，单独归档一份
- 会话事件账本本体在数据库中，保留期由 `cleanup.sessionEventRetentionDays`（默认 30 天）控制；「回答 → 更多 → 看这一轮的过程」读的就是它

## 后台定时任务

全部周期任务集中在调度中心：单 daemon 线程 10 秒节拍轮询，间隔实时读配置（改配置即时生效、≤0 暂停），任务体提交线程池、防重叠。运行状态快照与手动触发在「系统设置 → 定时任务 → 运行状态」，执行日志在同页第三个页签。

| 任务 | 默认间隔 |
|------|----------|
| 关键词索引精确对账 | 1h |
| 聊天图片目录清理 | 1d |
| 聊天附件超期清理 | 1h |
| 工具外溢原文清理 | 1h |
| 检索评估自动体检 | 1d |
| 配置缓存兜底刷新 | 5min |
| 过期会话与消息清理 | 1d（保留期默认 30 天） |
| 产物超期清理 | 1d（保留 90 天） |
| 会话日志归档清理 | 1d（保留期默认 90 天；同时清理换代搬走的旧代次） |
| 定时智能体任务扫描 | 30s |
| 文档解析队列扫描 | 5s |
| 网页源定时刷新 | 60s |
| 沙盒空闲回收 | 10min（空闲 60 分钟回收） |
| 工作流审批超时回收 | 60s |
| 工作流运行记录清理 | 1d（保留 30 天） |
| 工作流定时触发扫描 | 30s |
| Trace 线上采样 | 1d |
| 调度执行日志清理 | 1d（保留 7 天） |
| 站内通知清理 | 1d（保留 30 天） |

**目标模式调度器**独立于上述节拍：按 `chat.goal.tickMs`（默认 2 秒）批量认领到期的目标轮次，用数据库租约（默认 300 秒）保证同一目标只有一个副本在执行；心跳超过 `heartbeatStaleSeconds` 判失活，在 `staleGraceSeconds` 宽限后自动恢复或转「已暂停」。并发执行线程数 `chat.goal.workers`（默认 4）改动需重启。

## 默认关闭项（安全边界）

问渠工具总开关默认开（基础工具开箱即用）；**沙盒、沙盒脚本、联网搜索与 MCP 服务端默认关**，需在设置页显式开启。技能无需开关——内置技能随安装包分发，可用范围由智能体的能力开关与停用清单决定；MCP 客户端无全局开关（每人自建）。个别高风险工具的范围按智能体的权限档位与逐工具黑名单收敛，管理员另可设平台上限与平台停用名单。

## 沙盒

- provisioner：`bash deploy/sandbox-provisioner/run.sh docker-up`（127.0.0.1:8002；首次构建约 12GB 镜像）
- 应用侧用环境变量配连接：`SANDBOX_PROVISIONER_URL`、`SANDBOX_PROVISIONER_TOKEN`、`SANDBOX_CALLBACK_BASE_URL`、`SANDBOX_VIRTUAL_PATH_PREFIX`；token 须与 provisioner 侧一致且 ≥32 字符（不足则 fail-closed 拒绝启用；校验推迟到首次使用，未启用沙盒的部署不因缺 token 起不来）
- 沙盒运行时依赖必须烧进镜像（容器内无 sudo）：用 `sandbox-image/Dockerfile` 派生镜像并在 `.env` 设 `SANDBOX_IMAGE`
- 沙盒持久卷按会话隔离：`user-data/shared/{uid}/workspace/sessions/{会话id}/`，重建容器后文件不丢；工作区开启共用目录时挂该工作区目录

## 模型兼容

- 部分网关模型返回 DashScope 原生格式（`{"text":...}`）无法解析，需使用返回标准 OpenAI 格式的模型
- base-url 不含 `/v1`（后端自动补）
- 切换向量模型会触发该库全量重嵌入（与知识块数成正比），期间向量检索降级关键词路，应避免在业务高峰操作；重嵌入与并发解析同时进行时可能丢块，任务末尾的索引对账会告警，需在空闲时手动补跑

## 升级与回退

- 版本升级后由管理员在帮助中心点「同步官方手册」写入知识库；同步逐块调用向量模型，内容未变化的篇目自动跳过
- 前端产物发布位置与 compose 更新步骤见 `deploy/deployment-guide.html`（环境变量清单、密钥生成、备份还原、升级与回滚、常见故障排查）
