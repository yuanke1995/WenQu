# 部署与运维（管理员）

## 环境变量

```bash
# 必填（缺失启动失败 fail-fast）
export DB_PASSWORD=xxx

# 基础设施（有默认值，按环境调整）
export DB_HOST=127.0.0.1  DB_PORT=3306  DB_NAME=wenqu_ai  DB_USERNAME=root
export REDIS_HOST=127.0.0.1  REDIS_PORT=6379  REDIS_PASSWORD=  REDIS_DB=0
export AI_IMAGES_DIR=./data          # 数据根目录（源文件/图片/产物/密钥）
export AI_AGENTSCOPE_STATE_DIR=./data/agentscope   # 框架工作区（个人记忆 MEMORY.md/memory/、技能、plans）
export LOG_DIR=./data/logs            # 应用日志目录（容器部署需指向挂载卷内，否则容器重建后丢失）

# 安全
export AI_JWT_SECRET=xxx             # ≥32 位随机串；留空每次启动随机生成（重启后旧令牌失效）；多副本必须一致

# 仅 env/yml（不进设置页）
export AI_MEILI_KEY=xxx              # Meilisearch master key
export AI_MEILI_INDEX=wenqu-chunks
export SPRINGDOC_ENABLED=false       # Swagger 开关（默认关）
```

启动：`mvn spring-boot:run` 或 `java -jar target/wenqu.jar`；Docker Compose 自包含（redis-stack + meilisearch + MySQL）：`docker compose up -d`。后端监听 `http://localhost:8090/ai`，健康检查 `/ai/actuator/health`。

表结构由启动自动执行 `schema.sql` 创建（幂等）；存量库缺列缺索引由 `SchemaMigrator` 启动期自动补齐。

## Redis 是硬依赖

框架引擎（AgentScope）的会话状态——对话上下文、待办、断线续跑游标——**始终存储在 Redis**，没有本地文件兜底。

- Redis 连不上时**应用启动直接失败**（不会降级运行，也不会只影响聊天功能）。配好 `REDIS_HOST / REDIS_PORT / REDIS_PASSWORD` 再启动。
- Docker Compose 已含 `redis-stack` 且以 `service_healthy` 作为 app 的启动前置条件，无需额外操作。
- 键前缀 `chat.agentscopeRedisPrefix`（默认 `agentscope:session:`）避免与其它应用混用命名空间。
- 跨副本协调（记忆 flush 节流、consolidation watermark）走同一套 Redis。
- 存储在磁盘上、且需要共享的是**个人记忆文件**（`MEMORY.md`、日账）——位置是 `AI_AGENTSCOPE_STATE_DIR`（默认 `{AI_IMAGES_DIR}/agentscope`）。容器部署需把它指向挂载卷内，多副本还要挂成共享卷。

## 多副本部署要求（摘要）

1. 数据目录必须共享（`AI_IMAGES_DIR` 指向共享存储；跨主机挂 NFS/对象存储）
2. 静态配置（env/yml）各副本一致，`AI_JWT_SECRET` 尤其必须一致；动态配置经 Redis 广播
3. 解析队列有界；总并发 = 副本数 × parse.concurrency，embedding/视觉是共享瓶颈
4. 删除在任意实例生效，其他实例解析任务由 DB 兜底秒级停止清理
5. 向量模型热切换全实例串行（Redis 分布式锁），锁持有期间向量检索自动降级关键词路
6. 多副本上线前把 `keyword.reconcileOnStartup` 与 `parse.recoverStuckOnStartup` 置 false（启动对账收敛为单点）
7. RSA 密钥文件必须共享（默认 `{AI_IMAGES_DIR}/secret/config-rsa.key`，可 `AI_CONFIG_RSA_KEY` 覆盖）
8. `chat.sessionLogArchive.enabled` 默认开（保留 90 天 + 每日清理随默认值出厂）：多副本必须把归档目录指向共享卷，否则各副本各自存一份、按会话无法合并

## 会话事件日志归档

框架引擎每轮把过程写成事件存入会话日志（正文之外的内容只记录在这里：工具入参与结果、思考段、待办与裁决时刻、压缩留痕）。`chat.sessionLogArchive.enabled` 默认开，这些事件按会话导出成 JSONL 归档：

- 位置：`{chat.sessionLogArchive.dir}`，留空则为 `{chat.agentscopeStateDir}/session-archive/{归属号}/{会话号}.jsonl`（目录名是 URL-safe Base64，不含可读会话号）
- 一行一条事件，字段固定：`seq / at / eventId / type / runId / turnId / required / payload`；`payload` 是内嵌的原 JSON（不是转义字符串），可用 `jq` 或 grep 直接读取
- 增量与断点由框架管理：每条会话存一份导出水位，只补发水位之后的事件；进程崩溃后从原水位重投（至少一次语义，重投的是事件而非执行），因此归档不会因重启而从零重写
- 保留期 `chat.sessionLogArchive.keepDays`（按文件最后写入时间判定，0 = 不清理），清理任务间隔 `chat.sessionLogArchive.cleanupIntervalMs`
- 归档**只写文件**：界面不提供下载，由运维按文件读取；子智能体分支是另一条会话，单独归档一份
- 默认开启：保留策略随默认值出厂（90 天 + 每日清理），磁盘占用有界；正文之外的过程明细只存在于这里，不归档则容器重建后丢失。不需要写文件时显式关闭

## 会话事件日志换代

日志本体（不是归档）落在宿主 `~/.wenqu/agent-journal/agents/…/sessions/…/{会话号}/`，框架每开始一轮都要把这条会话的整条事件链从头读取数遍，**代价随事件条数平方增长**。本机实测一条长任务会话：3.5 千条约 1 秒、1.4 万条约 5 秒、9.2 万条时仅最贵的一次读取就需要 40 秒——这段时间发生在模型输出第一个字之前，界面上表现为状态行「正在溯源，用时 1 分 32 秒」而正文区没有任何内容。因此设置了上限：

- `chat.agentscopeJournalRotateEvents`（默认 12000，0 = 关闭换代）：一条会话累计到该事件数时，在「上一轮已收口、本轮未开始」之间换代——导出当前上下文 → 旧一代整目录搬到 `~/.wenqu/agent-journal/rotated/…/{时间戳}/` → 新一代以一条 baseline 开始。换代前先按框架游标把旧一代补写进归档，不留未归档的事件
- 换代只在静默点执行：存在写者租约、未结算的执行或待裁决卡片时框架会拒绝换代；被拒则本轮不换、下一轮再试，不会中断正在执行的会话
- `chat.agentscopeJournalRotateKeepDays`（默认 30，0 = 不清理）：被搬走的旧代次保留天数，由「会话日志归档清理」那条任务按目录修改时间删除。**长期留存的是上面那份归档 JSONL**，旧代次只覆盖「刚换代完就需要回看原始事件」的那几天
- 换代的影响：框架自带的 `session_history` / `session_search` 只能读取到本代之后的原始事件。用户可见的历史不受影响——消息正文在数据库、逐轮过程在事件账本、全量明细在归档
- 多副本注意：该日志本就写在宿主机本地（切换副本即丢失进行中的历史），换代与清理都在同一台机器上执行，不引入新的共享要求；但 `rotated/` 也在同一目录下，挂卷时需连同 `agent-journal` 一起挂，否则换代搬走的旧代次会随容器一起丢失

## 后台定时任务

全部集中在 ScheduleCenter：单 daemon 线程 10s 节拍轮询，间隔实时读配置（改配置即时生效、≤0 暂停），任务体提交线程池、防重叠。

| 任务 | 默认间隔 |
|------|----------|
| 关键词索引精确对账 | 1h |
| 聊天图片目录清理 | 1d |
| 检索评估自动体检 | 1d |
| 配置缓存兜底刷新 | 5min |
| 过期会话/消息清理 | 1d（保留期默认 30 天） |
| 产物超期清理 | 1d（保留 90 天） |
| 会话日志归档清理 | 1d（保留期 `chat.sessionLogArchive.keepDays`，默认 90 天） |
| 定时智能体任务 | 30s |
| 网页源定时刷新 | 60s |
| 沙盒空闲回收 | 10min（空闲 60 分钟回收） |

## 默认关闭项（安全边界）

工具（含沙盒）默认开启，个别高风险工具按智能体的权限档位与逐工具黑名单收敛；技能无需开关——内置技能随版本分发，可用范围由智能体的「技能范围」决定；MCP 客户端无全局开关（每用户自建）；MCP 服务端 `mcp.server.enabled` 默认关，需在设置页显式开启。

## 沙盒

- provisioner：`bash deploy/sandbox-provisioner/run.sh docker-up`（127.0.0.1:8002；首次构建约 12GB 镜像）
- 应用侧用环境变量配连接：`SANDBOX_PROVISIONER_URL`、`SANDBOX_PROVISIONER_TOKEN`、`SANDBOX_CALLBACK_BASE_URL`、`SANDBOX_VIRTUAL_PATH_PREFIX`；token 须与 provisioner 侧一致且 ≥32 字符（不足 fail-closed 拒绝启用；校验推迟到首次使用）
- 沙盒运行时依赖必须烧进镜像（容器内无 sudo）：用 `sandbox-image/Dockerfile` 派生镜像并在 `.env` 设 `SANDBOX_IMAGE`
- 沙盒持久卷按会话隔离：`user-data/shared/{uid}/workspace/sessions/{会话id}/`，重建容器后文件不丢

## 模型兼容

- 部分网关模型返回 DashScope 原生格式（`{"text":...}`）无法解析，需用返回标准 OpenAI 格式的模型
- base-url 不含 `/v1`（后端自动补）
- 切换向量模型会触发全量重嵌入，应避免在业务高峰操作；重嵌入与并发解析同时进行时可能丢块，任务末尾的索引对账会告警，需在空闲时手动补跑
