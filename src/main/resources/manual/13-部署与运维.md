# 部署与运维（管理员）

## 环境变量

```bash
# 必填（缺失启动失败 fail-fast）
export DB_PASSWORD=xxx

# 基础设施（有默认值，按环境调整）
export DB_HOST=127.0.0.1  DB_PORT=3306  DB_NAME=wenqu_ai  DB_USERNAME=root
export REDIS_HOST=127.0.0.1  REDIS_PORT=6379  REDIS_PASSWORD=  REDIS_DB=0
export AI_IMAGES_DIR=./data          # 数据根目录（源文件/图片/产物/密钥）
export AI_AGENTSCOPE_STATE_DIR=./data/agentscope   # 框架工作区（个人记忆 MEMORY.md/memory/、技能、plans）
export LOG_DIR=./data/logs            # 应用日志目录（容器部署请指到挂载卷内，否则重建即丢）

# 安全
export AI_JWT_SECRET=xxx             # ≥32 位随机串；留空每次启动随机生成（重启后旧令牌失效）；多副本必须一致

# 仅 env/yml（不进设置页）
export AI_MEILI_KEY=xxx              # Meilisearch master key
export AI_MEILI_INDEX=wenqu-chunks
export SPRINGDOC_ENABLED=false       # Swagger 开关（默认关）
```

启动：`mvn spring-boot:run` 或 `java -jar target/wenqu.jar`；Docker Compose 自包含（redis-stack + meilisearch + MySQL）：`docker compose up -d`。后端监听 `http://localhost:8090/ai`，健康检查 `/ai/actuator/health`。

表结构由启动自动执行 `schema.sql` 创建（幂等）；存量库缺列缺索引由 `SchemaMigrator` 启动期自动补齐。

## Redis 是硬依赖

框架引擎（AgentScope）的会话状态——对话上下文、待办、断线续跑游标——**恒存 Redis**，没有本地文件兜底：本地文件方案已退役，因为它在容器重建时会一起消失，多轮对话会退化成每轮独立问答（上一轮刚给过的数据，下一轮模型说没见过——2026-10-21 线上事故即由此而来）。

因此：

- Redis 连不上，**应用启动直接失败**（不是降级、不是只影响聊天）。`REDIS_HOST / REDIS_PORT / REDIS_PASSWORD` 配好再启动。
- Docker Compose 已含 `redis-stack` 且以 `service_healthy` 作为 app 的启动前置条件，无需额外操作。
- 键前缀 `chat.agentscopeRedisPrefix`（默认 `agentscope:session:`）避免与其它应用混用命名空间。
- 跨副本协调（记忆 flush 节流、consolidation watermark）也走同一套 Redis，没有「退回单副本」的分支。
- 仍需落在磁盘、且必须共享的是**个人记忆文件**（`MEMORY.md`、日账）——它们在 `AI_AGENTSCOPE_STATE_DIR`（默认 `{AI_IMAGES_DIR}/agentscope`）。容器部署请把它指到挂载卷内，否则重建即丢记忆；多副本还要挂成共享卷。

## 多副本部署要求（摘要）

1. 数据目录必须共享（`AI_IMAGES_DIR` 指向共享存储；跨主机挂 NFS/对象存储）
2. 静态配置（env/yml）各副本一致，`AI_JWT_SECRET` 尤其必须一致；动态配置经 Redis 广播
3. 解析队列有界；总并发 = 副本数 × parse.concurrency，embedding/视觉是共享瓶颈
4. 删除在任意实例生效，其他实例解析任务由 DB 兜底秒级停止清理
5. 向量模型热切换全实例串行（Redis 分布式锁），锁持有期间向量检索自动降级关键词路
6. 多副本上线前把 `keyword.reconcileOnStartup` 与 `parse.recoverStuckOnStartup` 置 false（启动对账收敛为单点）
7. RSA 密钥文件必须共享（默认 `{AI_IMAGES_DIR}/secret/config-rsa.key`，可 `AI_CONFIG_RSA_KEY` 覆盖）
8. 要留「那一轮到底发生了什么」就开 `chat.sessionLogArchive.enabled`（见下节）：多副本必须把归档目录指到共享卷，否则各副本各摊一份、按会话拼不回来

## 会话事件日志归档

框架引擎每轮把过程写成一条条事件存进会话日志（正文之外的东西只在这里：工具入参与结果、思考段、待办与裁决时刻、压缩留痕）。打开 `chat.sessionLogArchive.enabled` 后，这些事件会按会话摊成 JSONL 归档：

- 位置：`{chat.sessionLogArchive.dir}`，留空则为 `{chat.agentscopeStateDir}/session-archive/{归属号}/{会话号}.jsonl`（目录名是 URL-safe Base64，不含可读会话号）
- 一行一条事件，字段固定：`seq / at / eventId / type / runId / turnId / required / payload`；`payload` 是原 JSON 内嵌（不是转义字符串），直接 `jq` 或 grep 就能读
- 增量与断点由框架自己管：每条会话存一份导出水位，只补发水位之后的事件，进程崩了从原水位重投（至少一次，重投的是事件不是执行），所以归档不会因为重启而从零重抄
- 保留期 `chat.sessionLogArchive.keepDays`（按文件最后写入时间判，0 = 不清理），清理任务间隔 `chat.sessionLogArchive.cleanupIntervalMs`
- 归档**只落盘**：界面不提供下载，读它由运维按文件取；子智能体那一支是另一条会话，各自摊一份，不搭父轮的车
- 默认关：这是逐事件追加写盘，配好保留期与备份目录再常开

## 后台定时任务

全部集中在 ScheduleCenter：单 daemon 线程 10s 节拍轮询，间隔实时读配置（改配置即时生效、≤0 暂停），任务体提交线程池、防重叠。

| 任务 | 默认间隔 |
|------|----------|
| 关键词索引精确对账 | 1h |
| 聊天图片目录清理 | 1d |
| 检索评估自动体检 | 1d |
| 配置缓存兜底刷新 | 5min |
| 过期会话/消息清理 | 1d（保留期默认 30 天） |
| 产物超期清理 | 1d（保留 90 天） |
| 会话日志归档清理 | 1d（保留期 `chat.sessionLogArchive.keepDays`，默认 90 天） |
| 定时智能体任务 | 30s |
| 网页源定时刷新 | 60s |
| 沙盒空闲回收 | 10min（空闲 60 分钟回收） |

## 默认关闭项（安全边界）

工具（含沙盒）默认开，个别高风险工具按智能体的权限档位与逐工具黑名单收；技能无需开关——内置技能随版本分发，能用哪些由智能体的「技能范围」决定；MCP 客户端无全局开关（每用户自建）；MCP 服务端 `mcp.server.enabled` 默认关，需在设置页显式开启。

## 沙盒

- provisioner：`bash deploy/sandbox-provisioner/run.sh docker-up`（127.0.0.1:8002；首次构建约 12GB 镜像）
- 应用侧用环境变量配连接：`SANDBOX_PROVISIONER_URL`、`SANDBOX_PROVISIONER_TOKEN`、`SANDBOX_CALLBACK_BASE_URL`、`SANDBOX_VIRTUAL_PATH_PREFIX`；token 须与 provisioner 侧一致且 ≥32 字符（不足 fail-closed 拒绝启用；校验推迟到首次使用）
- 沙盒运行时依赖必须烧进镜像（容器内无 sudo）：用 `sandbox-image/Dockerfile` 派生镜像并在 `.env` 设 `SANDBOX_IMAGE`
- 沙盒持久卷按会话隔离：`user-data/shared/{uid}/workspace/sessions/{会话id}/`，重建容器后文件不丢

## 模型兼容

- 部分网关模型返回 DashScope 原生格式（`{"text":...}`）无法解析，需用返回标准 OpenAI 格式的模型
- base-url 不含 `/v1`（后端自动补）
- 切换向量模型 = 全量重嵌入，避免业务高峰；重嵌入与并发解析撞车可能丢块，任务末尾索引对账会告警，空闲时手动补跑
