4关键流程
四条主路径覆盖 90% 使用场景；每一步都对应到已存在的工具/接口。
1开启 → 委派 → 协作 → 收敛
开启团队胶囊→ lead agent_spawn 派 3 人→ team_task_* 拆任务 / 加依赖→ team_send 追加要求→ 成员回报 → lead 综合→ 收起团队 drain
2追问一位成员
正文汇报卡「向它追问」→ 成员卡就地展开输入→ 在线 steer / 离线唤醒→ 回报进「成员消息」卡
3叫停 / 全部停止
成员卡「叫停」只停本轮→ 排队消息保留→ 状态 STOPPED→ 根「全部停止」drain 整树
4离线唤醒 / 断线重连
离线成员收消息→ 落 team_message + next_run_at→ 冷恢复注入未读→ 刷新/换设备按真源重建

设计说明与落地口径

  • 不强塞新菜单：团队是「这一轮协作的形态」，入口贴着正在聊的会话——顶栏胶囊 + 右栏团队 Tab；成员要读长内容才给整页回显；任务图信息密度高，用「展开画布」进大图。
  • 状态词单一真源：成员 member_state（RUNNING/WAITING/IDLE/STOPPED/OFFLINE）、任务 c_ai_team_task.state（PENDING/READY/IN_PROGRESS/COMPLETED/FAILED/CANCELLED）。前端映射集中到一个 teamStatus.js，不再各写一套。
  • 实时优先、轮询兜底：订阅 team_member / team_message / team_task 事件；轮询降为 15s 兜底。每条消息带 msgId + 游标去重。
  • 默认关闭零回归：关闭团队 → 不挂 team_* 工具、不显示面板、分支回 temp 语义；旧会话逐字不变。开关只写会话行，不新增系统配置。
  • 权限不越界：消息/中断要求发送者是目标祖先或根；成员运行在真实 uid 下，继承租户/RBAC；guest / API Key 轮不挂团队工具；成员权限启动时固定。
  • 落地顺序：P1 先补「面板输入区 / 实时订阅 / 任务 DAG 画布 / 任务时间线 / 汇报卡动作」，P2 再做「顶栏胶囊 / 消息图片文件 / 未读通知 / 状态收口 / 边界态 / drain 确认」。详见方案文档 §6–§7。
