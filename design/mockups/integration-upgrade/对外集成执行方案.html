01

一页看懂

四条结论先摆在前面。后面的工作包、图表和验收项，都是这四条的可执行展开。

① 不扩能力面，也能显著降难度

  • 已开的 v1 面覆盖 问答 / 检索 / 知识库 / 工作流 / webhook / MCP，够接"确定性能力"。
  • 真正卡住集成方的是：不知道怎么选、不知道 Key 能干什么、没有能跑的样例。
  • 所以 B 期先做发布、文档、样例、自检——不新增业务端点也能见效。

② C 是骨架，不是第三期

  • L0 / L1 / L2 三层能力都已具备，缺的是选型口径、可复制样例和兼容承诺。
  • 把 C 的目录塞进 B 的文档站，再用 A 期把 L1 的"实验性"标签摘掉。
  • 不为 C 单开一个迭代——否则就是写三份会漂移的文档。

③ A 期只做一个原语

  • POST /v1/agents/{id}/runs + SSE 事件 + 审批 / 产物 / 插话 / 停止。
  • 实现是投影：复用现有 native 会话与断线接流，不复制引擎。
  • v1 chat/completions 保持无状态文本面；长任务与人在回路走 runs。

④ 每一条"已通"都要有证据

  • 验证在 8096 对照实例与干净容器里做，不碰 IDEA 里跑的实例。
  • 断线续传看 seq 连续，webhook 看验签与幂等，SDK 看离开仓库也能装。
  • 接入漏斗指标上线后取真数，方案里不预设目标数字。

四个真缺口

缺口 1  发布渠道

  • 两套 SDK 只存在于仓库，版本 0.1.0；外部项目装不到，只能拷源码。
  • 私网客户更麻烦：即使发布到公网 registry，也未必拉得到。

缺口 2  可运行样例

  • 没有任何"宿主系统"样例：代理拓扑、webhook 验签、断线续传都要自己悟。
  • 文档里的代码片段无法一键验证，容易随代码漂移。

缺口 3  自检与选型

  • 没有 Key 自检端点：集成方不知道自己这把 Key 有哪些 scope、代表谁。
  • 三种接入形态没有同屏对比，客服场景和流程场景容易被推荐同一种。

缺口 4  过程原语

  • 审批、计划、产物、插话、停止只存在于原生对话链路，对外没有稳定入口。
  • v1 chat 是收集型单块下发，不是逐 token 真增量；长任务也没有 run 语义。
口径提醒："已开放的端点"不等于"已开放的智能体"。OpenAI 兼容面是文本问答， 检索/工作流是确定性能力，两者之间的智能体运行过程目前没有对外原语——这正是 A 期要补的那一块。

一张图看三层在链路里的位置

选型问三句：
① 只想在自己的页面上放一个问答入口？ → L0（分享 token，零代码）
② 要嵌进自家前端，而且要展示审批、产物、计划过程？ → L1（业务后端代理，浏览器零凭据）
③ 由业务系统后端调用，或要把结果通过回调送回业务？ → L2（API Key + webhook）
④ 既要前端体验又要后端事件？ → L1 + L2，两者共用同一个后端，Key 仍然只在服务端。
承诺分级怎么写："正式" = 只增不删 + 变更日志 + 至少两个 minor 的废弃期； "实验性" = 字段可改，接口变更提前在文档站公告。维护面 ×3 是反对三层全部正式承诺的理由， 也是 L1 先挂标、A 后再摘标的原因。

A 期：把运行过程收敛成一个原语

不复制引擎，只做投影：现有 native 会话已经具备事件、快照、断线接流、审批、产物； A 期把它们投影成一个稳定的 v1 契约，让 L1 可以摘掉"实验性"。

原则一：投影，不重写

  • 复用现有 run 存储与 /chat/resume 的快照 + 增量。
  • 引擎侧只补"没有的能力"，不另起一条执行链。

原则二：事件只增不删

  • 事件类型由 native 协议取稳定子集，附映射表。
  • 新增事件不需要升级 SDK：未知类型走兜底回调。

原则三：续传是一等公民

  • seq 单调；Last-Event-ID 续传。
  • 保留期外返回快照，SDK 自动降级重拉。

端点草案

方法路径用途要点
POST/v1/agents/{agentId}/runs创建一次运行Idempotency-Key；默认无状态，显式 sessionId 才持久
GET/v1/runs/{id}状态 / 输出 / 用量 / 错误与事件 run.done 同口径，便于轮询兜底
GET/v1/runs/{id}/eventsSSE 事件流Last-Event-ID；seq 连续
POST/v1/runs/{id}/steer运行中插话归属校验沿用现有发起人口径
POST/v1/runs/{id}/stop停止本轮幂等；已结束返 200 + 终态
POST/v1/runs/{id}/approvals审批 / 驳回 / 修订decision 枚举；超时收敛为 run.error(approval_timeout)
GET/v1/runs/{id}/artifacts产物清单只回可下载项，鉴权随 Key 代表账号
HOOKrun.finished出站回调（已有投递表扩展）HMAC + runId 幂等键，重投不产生第二条业务记录

一次带审批的运行，时序长这样

与 v1 chat 的边界：chat/completions 继续做"无状态、文本、单块下发"的兼容面； 真正的逐 token 增量、长任务、人在回路只承诺在 runs 上。不把 thinking 默认对外， 需要时由智能体配置显式开启。审批超时沿用平台现有审批口径，超时统一收敛成 run.error。

A 期验收（每一条都在 8096 验证栈实测）

链路

  • 建 run → token 增量 → approval.required → 提交审批 → artifact.created → run.done。
  • 运行中插话与停止各测一次，终态与 GET run 一致。

韧性

  • 杀掉客户端 5 分钟后用 Last-Event-ID 续传：seq 连续、无重复、无丢失。
  • webhook 接收器验签通过；同一 run 重投不产生第二条业务记录。

风险与对策

按"会不会让承诺失效"排序，而不是按发生概率排序。
风险等级后果对策
SDK 发布后破坏性变更 高 集成方升级即坏，信任成本高于修复成本 0.x 允许破坏但提前公告；CI 契约测试跑 mock + 8096 真栈；v1 只增不删
A 期与 native 双轨漂移 高 对外事件和内部事件语义各走各的 事件 = native 稳定子集 + 映射表 + 契约测试；只投影不复制引擎
文档双份漂移 中 in-app 页与文档站说法不一致 单一真源（openapi.json + guides）；in-app 页嵌入同一构建产物
私网客户拉不到公网包 中 SDK 发布了但客户装不上 同版本 tgz / wheel + 内网 registry 配置指引；升级路径写进文档
承诺面 ×3 维护 中 三套形态各自回归，长期拖慢迭代 只正式承诺 L0 / L2；L1 实验性；L0 只做 iframe 封装，不重写 UI
自助 Key 面失控 中 普通用户自助签发后对外面扩大，审计困难 scope 默认最小；签发审计；是否加租户级总开关见 D3
v1 chat 流式被误解 低 集成方以为拿到的是逐 token 增量 文档显式标注"收集型单块"；真增量明确指向 runs/events

验收清单、边界与待拍板

验收只认证据：干净容器、8096 验证栈、真实接收器。写"应该可以"不算完成。

B 期

干净环境装包：npm / pip 安装后只改 baseUrl 与 Key 跑通 quickstart
文档链路：从首页按选型页走到第一个成功响应，人工计时并记录真实耗时
三个样例：backend-node / backend-python / frontend-proxy 三命令跑通
自检：/v1/me 返回 scope、代表账号、限额；缺 scope 报错能自解释
度量：Key 创建到首次成功调用的漏斗能出数，403 原因可拆分

A 期

全链路：token → 审批 → 产物 → done；插话与停止终态一致
断线续传：5 分钟后 Last-Event-ID 续传，seq 连续无重复
webhook：HMAC 验签通过；重投不产生第二条业务记录
契约：事件 schema 进 openapi.json；文档站自动生成对应页
转正：L1 契约稳定两周后摘掉实验性标签

本期不做

能力面

  • 技能、子智能体、记忆分域的对外原语（A 之后的 A+ 再评估）。
  • <wenqu-chatbot> 自定义元素（先用 wenqu-embed.js）。
  • Java / Go SDK；计费与自助配额购买。

内部改造

  • 不强制把内部 UI 全量迁到 run 原语，A3 只做迁移成本评估。
  • 不改智能体引擎的执行语义；A 期只加投影与契约。
  • 不做 UI 的 API 全量镜像——只开放稳定、有复用价值的过程。

D1
L1 什么时候转正？
建议：A3，run 契约冻结并稳定两周后。过早转正等于把未稳定的事件语义写进承诺。

建议：默认无状态，显式传 sessionId 才持久；归属 Key 代表账号，保留期与会话策略一致。

建议：要，随 B4 一起做。现状只有 CORS 白名单，没有"整个租户关闭对外面"的总闸。
