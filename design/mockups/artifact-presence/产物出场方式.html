02

方案 A · 统一轻量交付卡

单件不再降级成灰条，而是复用交付卡的同一套骨架：类型徽标 + 人类可读标题 + 真实文件名 + 元信息 + 唯一主行动。 多件时这张卡自然长出清单，单件与多件从此是一家。

为什么不是把灰条修漂亮一点

灰条的根问题是它只表达「有个文件」，不表达「我交付了什么、下一步做什么」。 单件场景占比最高，恰恰最需要交付感；只调字号和间距，断层还在。

这张卡解决什么

  • 类型先说话：JSON / 网页 / 表格 / 图片各有颜色与图标，扫一眼就知道是什么。
  • 标题说人话：「录入申请人审批表」在前，form.json 作为副信息。
  • 主行动唯一：打开预览是主按钮，下载降为次按钮，不再让用户二选一。
  • 状态可见：「已交付」跟在元信息里，和目标的「已完成」用同一套状态语言。
  • 动作位置统一：单件与多件的操作都在卡片右上角，眼睛=预览、下载/ZIP=图标按钮，单件整卡约 104px。

05

入场动效 · 一次，120ms，不抢戏

「出场」不只是长什么样，也包括什么时候、以什么方式进入视线。动效只做一次：上移 7px 淡入，完成后不再重复。 流式回答期间不播，避免每来一段文字就抖一下。

06

取舍与推荐

A、B、C 全部收敛在前端：同一张卡、同一套产物数据，不需要新增后端接口，建议本轮一起做。

方案 改什么 用户得到什么 代价 / 风险 建议批次
A · 统一轻量交付卡 单件复用交付卡视觉，去掉灰条；多件沿用现有清单。 风格一致、主行动清晰、单件也有交付感。 动作并入元信息行后单件整卡约 104px；需回归分享页与 H5 的窄宽换行。 P0
B · 生成态到完成态 工具开始生成时占位，按已接收字节显示进度，完成原位替换。 不再突然出现，等待有反馈，位置不跳。 复用现有准备帧，无需后端；只对生成类工具生效，不画假百分比。 P0
C · 首屏所见即所得 单件卡左侧放首屏缩略：图片真图、网页 iframe、文本前几行；拿不到退回类型徽标。 不开预览就能判断内容，减少无效点击。 iframe 与文本拉取需限量、懒加载；H5 不跑 iframe，分享页退回类型徽标。 P0
D · 只做细节打磨 保持单行结构，仅统一图标、字号、按钮层级与入场。 观感略有提升。 断层仍在，收益最小。 可并入 A
RECOMMENDED

P0 = A + B + C + 120ms 入场，一轮做完

A 解决「看起来不像交付物」，B 解决「出现得太突然」，C 解决「不开预览不知道是什么」。 三者共用同一张卡与同一套产物数据：C 的网页缩略复用产物签名地址、文本缩略复用现有原文接口，不需要新增后端能力； 入场动效只是完成态的一个 class。代价是 iframe 与文本拉取必须限量、懒加载，H5 与分享页按能力降级。

单件也升为卡 生成态只报已接收字数 完成原位替换 缩略图限量 + 懒加载 分享页退回徽标 / H5 不跑 iframe 入场只播一次
