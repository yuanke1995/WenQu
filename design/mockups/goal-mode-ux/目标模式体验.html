WENQU · GOAL MODE · UI / UX PROPOSAL

目标模式：把「一条目标」做成
有状态、可回退、说得清的驾驶舱

目标已经是会话级、跨轮自动推进的一等对象，但界面上它仍是一条只有图标的一行 chip： 停/继续/改/删四个动作权重相同，「已暂停」分不清是用户停的、预算停的、还是被插话让位； 更关键的是——目标正在跑时，用户其实没法插话：发送会落进 steer 队列，而 `/chat/steer` 只认用户轮、不认目标轮，点了「立即发送」只会被退回输入框。 本方案不动问答主线，只把目标条、动作语义、终态留痕和插话链路补成一套能读懂、能回退的闭环。

基线 2026-11-08 目标任务运行时（QUEUED / RUNNING / PAUSED / VERIFYING） PC + H5 同构 不改问答发送 / 流式 / 审批主线
01 · GOAL BAR
从「一排图标」到「三段仪表」 状态 + 原文 + 进度一行读完；暂停/继续成为文字主行动，修改与取消降为次级，取消必须二次确认。
02 · ACTIONS
暂停 / 修改 / 继续 / 取消，四档各自说清 暂停可继续、修改升版从下一轮生效、取消留痕不丢过程、终态不再凭空消失。
03 · INTERJECT
插话 = 让位一轮，答完自动接续 目标在跑时你说话，目标转「已让位」；你的这轮答完自动回到「进行中」，不用手动点继续。

01

现状诊断：目标能跑，但读不懂、退不回

后端已经把目标做成跨轮对象：状态机、租约调度、证据核验、预算、过程账本、目标态帧都齐了。 缺的是界面这一层——目标条只承担「显示原文 + 四颗图标」，用户做判断需要的停因、轮次、生效时点、终态记录都不在视野里。

A1 · ACTION WEIGHT

四个动作同一权重，破坏性动作没有护栏

暂停、编辑、删除并排成三颗 28px 图标，删除（✕）与编辑同色同大小，点一下目标就从界面消失，没有确认、没有「取消 / 删除」的区别。

A2 · STATE AMBIGUITY

「已暂停」一个词盖住了四种停法

用户手动停、插话让位、预算用满、进程丢心跳，界面上都读作「已暂停」。停因只藏在桌面 hover 行或移动端第二行小字里。

A3 · CANCEL MISSING

只有「删除」，没有「取消」

现在点 ✕ 走 clear：目标立即转 CANCELLED，前后端都不再回显。用户想「先停掉这件事、留个记录」，只能删得干干净净。

02

目标与原则：目标条是仪表盘，不是工具栏

目标横跨多轮、可能跑几十分钟，它不属于任何一颗气泡。用户需要的不是「哪颗图标能点」，而是 一眼看清它在哪、还能退到哪、什么时候会再往前。

1 眼

状态与进度一屏读完

状态词、轮次、停因、预算占用同时在场，不靠 hover。

4 档

暂停 / 修改 / 继续 / 取消

四档各有明确语义与可用条件，不互相顶班。

0 丢

任何退出都留痕

取消留终态卡，修改留版本，暂停留过程；删除只删记录。

1 轮

插话只让位一轮

说话不打断已跑出的成果，答完自动接续，不用手动继续。

P1
状态词只说一件事

「进行中 / 已让位 / 已暂停 / 未完成 / 已完成 / 已取消」，停因用第二行一句话补，不塞进同一颗胶囊。

P2
主行动只有一个

进行中主按钮是「暂停」，停下后主按钮是「继续」；修改与取消永远在次级位，避免误触。

P3
破坏性动作先确认

取消目标走一次就地确认浮层；文案说清「已跑轮次和过程都保留」，不是「删除」。

P4
插话不排队

目标在跑时发送 = 让位提问；不再把目标轮当作可 steer 的轮次，队列语义只留给用户自己的轮。

P5
只讲用户结果，不露机制

不出现 TASK_STATE / steer / preempt / verifier；只说「答完自动继续」「从第 4 轮起按新目标跑」。

P6
终态必须有落点

达成、取消、未完成都落一张只读终态卡在消息流里，过程账本可从卡上进。

03

方案总览：目标条三段式 + 动作语义表

目标条仍然坐在输入卡片内部、正文之上（位置不变，不新起一层外框）。只把这一行拆成 身份 / 进度 / 动作 三段：上一段回答「这是什么目标」，中段回答「跑到哪了、为什么停」， 下段回答「现在能做什么」。

1身份行：目标 pill + 原文（最多两行，超长折起）+ 版本 chip（v2）+ 状态胶囊（进行中 / 已让位 / 已暂停 / 未完成）
2进度行：第 3 轮 · 已跑 4 分 12 秒 · 预算 26%（细进度条）· 停因一句话（"连续两轮没有新进展" / "这句答完自动继续"）· 右端「查看过程 ›」
3动作行：主按钮（暂停目标 / 继续目标 / 立即继续）+ 次级「修改目标」+ 危险弱化「取消目标」。编辑态整段换成文本域 + 版本轨 + 「从下一轮生效」提示 + 取消 / 保存。

3.1 状态词与主行动

后端状态用户看到的词色档第二行说停因主行动
RUNNING / QUEUED进行中主色（点呼吸）第 N 轮 · 阶段：执行暂停目标
PAUSED + endReason=preempted已让位警示「这句答完自动继续」立即继续
PAUSED + stopped已暂停警示「你手动停在这里，可以继续」继续目标
PAUSED + budget / no-progress / blocked已暂停警示对应停因一句（预算上限 / 连续无进展 / 受阻原因）继续目标
stale=true待恢复警示「执行中断，继续会先核对状态」继续目标
VERIFYING / WAITING_*核验中 / 等待中 / 待确认主色正在核验 / 等外部结果 / 有一项操作等你确认暂停目标
FAILED未完成危险失败原因一句 + 「继续不重置预算」继续目标
ACHIEVED已完成成功共 N 轮 · 证据 X 条另起目标
CANCELLED已取消灰化共跑 N 轮 · 历史与过程保留重新设定目标

3.2 四个动作的语义

动作可用条件后端行为界面必须说清
暂停进行中 / 核验中 / 等待中打断当前目标轮，转 PAUSED，endReason=stopped，进度全留「已按你的要求停下；可以继续」。手动暂停不会自动恢复
继续已暂停 / 未完成 / 待恢复转 RUNNING，预算不重置，调度器下一拍起轮「从下一轮接着跑」；FAILED 时补一句「预算不会重置」
修改进行中 / 已暂停 / 未完成原文升版 + 强制重规划；在飞那一轮不受影响，下一轮按新原文「第 N 版 · 下一轮生效 · 已跑 X 轮保留」
取消所有非终态（含未完成）打断当前轮 → CANCELLED，endReason=cancelled，过程账本保留二次确认；「已跑轮次与过程都会保留」；消息流落终态卡
删除记录仅终态CANCELLED，endReason=cleared，界面与回显都不再出现「只从界面移除，过程账本仍可按目标查询」
后端要补的最小语义差：取消 与 删除记录 现在都走 clear，需要按 endReason = cancelled / cleared 分开；GET /session/{id}/goal 对 cancelled 要回显、对 cleared 继续隐藏。否则「取消留痕」刷新一次就没了。
04

插话链路：让位一轮，答完自动接续

后端其实已经写好了「用户优先」：用户开新一轮时，如果后台目标轮还在飞，目标会打断并转 PAUSED（endReason=preempted）；用户这一轮收尾后，onUserTurnEnd 会把目标自动接回 RUNNING。 缺的是前端没有走这条门——目标在跑时输入框把发送当成 steer，用户根本发不出这一轮。

STEP 1
目标在跑

目标是当前正在执行的那一轮，条子读「进行中 · 第 3 轮」。

STEP 2
你直接说一句

不再入 steer 队列，按普通提问发送；带材料也照常。

STEP 3
目标让位

后台目标轮被打断，转 PAUSED，停因 preempted；条子变「已让位」。

STEP 4
先答你

你的这一轮正常流式回答；目标原地保留，不抢上下文。

STEP 5
自动接回

你这一轮收尾后目标自动转回进行中，从下一轮接着跑。

4.1 三条判据，决定这句话是「插话」还是「普通提问」

目标此刻输入框里的发送目标后续界面提示（必须可见）
进行中（目标轮在跑）让位提问（不进队列、不发 steer）先暂停，答完自动继续占位「插话：先回答你这句，目标随后自动继续」；发送键 title 同义
暂停 / 已让位（没有在跑的目标轮）普通提问保持暂停；不自动恢复条子第二行「目标已暂停，这一轮答完不会自动继续」
自己的用户轮在跑（与目标无关）保持现有 steer 队列语义与目标无关沿用现有「插话」队列，不改
不要做「真 steer 进目标轮」：那需要给后台目标轮登记 TurnHandle，并让框架把插话送进一个没有观众的后台轮。语义上也危险——用户的一句话会被当成目标轮的工具循环输入，而不是「先回答我」。本方案只走已存在的「让位 → 自动接续」链路，后端零改动。

4.2 让位与手动暂停必须长得不一样

已让位（preempted）已暂停（stopped）
起因用户插话，系统自动让位用户主动点了暂停
状态词已让位已暂停
第二行「这句答完自动继续」「你手动停在这里，可以继续」
主按钮立即继续（想抢先恢复时点）继续目标
后续回答结束自动回「进行中」不会自动恢复，等用户点继续

06

交互规则与边界

场景规则为什么
目标在跑时按 Enter按普通提问发送，不进插话队列、不调 steer；目标先让位目标轮未登记 TurnHandle，steer 必失败；且用户意图是「先听我说」
目标在跑时带附件 / 图片同样走让位提问（不限制载荷）带材料的插话本来就不能进当前轮，让位后自然成为普通一轮
自己的用户轮在跑保持现有 steer 队列与「立即发送」，不动这条链路已经跑通，改动风险与收益不成比例
目标暂停时发送普通提问；目标保持暂停，不自动恢复手动暂停是用户的刹车，不能被一次普通聊天悄悄撤销
暂停按钮点击即停，不需要确认；正在跑的目标轮被打断，进度全留暂停可逆，确认只会增加摩擦
取消目标就地确认浮层；确认后落终态卡；刷新后仍在不可逆的退出必须一次确认；留痕避免「东西丢了」的错觉
删除记录只出现在终态卡；点后从界面与回显移除，过程账本仍可查和「取消」分开：一个结束事情，一个清理界面
修改目标进行中 / 暂停 / 未完成都可改；保存后升版，下一轮生效在飞那一轮不受影响，避免半路改写正在执行的上下文
修改后仍暂停保持暂停；点继续后按新目标跑编辑不等于恢复，恢复必须显式
刷新 / 切会话目标条与终态卡都由会话目标接口 + 消息回显重建；不靠内存目标横跨多轮，内存态一丢就断线
多端同时看goal_state 帧与 2.5s 轮询对账；动作按钮按自己那份视图判可用已有总线与轮询，不新增同步机制
没有目标不显示目标条；入口仍在输入区的「+ → 本轮模式 → 定为目标」与 /goal不新开顶级入口，保持现有发现路径

08

分阶段实施与验收

阶段范围交付验收口径
P1 目标条重排 PC + H5 目标条三段式；状态词补「已让位 / 未完成 / 已取消」；取消确认 + 取消/删除分档 目标条与后端 cancel 语义 任何停法一眼能分清；取消必须经过确认；刷新后取消记录仍在
P2 插话链路 目标在跑时 Enter = 让位提问；「已让位」状态 + 自动接续提示；暂停时发送不自动恢复 输入区 + 引擎状态接线 目标在跑直接发一句话：不出现 steer 队列、不被退回输入框；回答结束目标自动回「进行中」；手动暂停后发消息目标保持暂停
P3 目标详情 GoalViewer 抽屉 / H5 sheet；版本轨、预算条、按轮时间线、结果区；轮次跳转 turnId 新组件 + goalEvents 接线 点「查看过程」能读到每一轮的摘要与结果；版本与生效轮次一致；点轮次能定位到那条回答
P4 终态留痕 消息流终态卡（已完成 / 已取消 / 未完成）；重新设定目标、查看过程、删除记录；完成态证据摘要 ChatPage / MobileChatPage 终态卡 达成或取消后目标不再凭空消失；刷新后终态卡仍在；删除记录后真正消失

验收清单

  • 状态一致性：同一条目标在目标条、详情抽屉、终态卡、移动壳里说的是同一个词、同一个轮次、同一个停因。
  • 动作可逆：暂停 → 继续、修改 → 再改、取消 → 重新设定，三条回退路径都不断过程。
  • 插话可用：目标运行中发送不被队列拦截；答完自动继续；「已让位」与手动「已暂停」视觉可分。
  • 刷新恢复：目标运行中、已让位、已取消三种状态刷新后都能重建，且终态卡与过程入口都在。
  • 主线零改动：普通问答的发送、流式、停止、审批、steer 队列行为与改动前逐项一致。
  • 间距对齐：目标条三段行距 8px、按钮高 28px、状态胶囊高 20px、卡片内边距 12px，与输入卡片同一套令牌。
09

评审结论与待拍板项

以下五项需要你拍板；每项都给了推荐项，按推荐项实施不需要再改数据结构。

D1 · CANCEL VS DELETE

「取消目标」与「删除记录」是否拆成两个动作？

现在只有 clear，一击即消失。

推荐：拆。取消 = 结束并留痕；删除记录 = 仅终态可点，清界面。
备选：只保留取消，不提供删除记录。
D2 · INTERJECT SEMANTICS

目标运行中插话，走「让位」还是「真 steer 进目标轮」？

后者需要给后台目标轮登记 TurnHandle，且语义上会把用户的话塞进目标执行上下文。

推荐：让位一轮，答完自动继续；后端零改动。
备选：先只做「明确提示 + 禁用 steer」，插话仍要手动暂停。
D3 · EDIT ON FAILED

「未完成」的目标允许直接修改吗？

当前后端 edit 只允许 CURRENT，FAILED 必须先继续再改。

推荐：允许；保存后自动继续，省掉「先点继续再改」两步。
备选：保持现状，改按钮在 FAILED 置灰并提示先继续。
D4 · BUDGET VISIBILITY

预算在条上显示多少？

轮次是用户判断「还要多久」的主指标；token / 时间是运维指标。

推荐：条上只显轮次 + 细进度条；token / 时间放详情抽屉。
备选：条上同时显轮次与预算百分比（当前效果稿）。
D5 · TERMINAL CARD

终态卡挂在哪？

目标横跨多轮，不属于最后一颗气泡。

推荐：挂在「设为目标」那条用户回声下面，随会话历史重建。
备选：固定在消息流末尾，始终可见。
D6 · H5 ACTIONS

移动端是否保留四颗图标？

375px 下四颗 32px 图标 + 原文会挤成一团。

推荐：第一行只留主行动 + 「更多」，其余进底部 sheet。
备选：保留「暂停 / 编辑」两颗，取消与过程进 sheet。
确认后按 P1 → P2 → P3 → P4 落地，每阶段单独可验收；插话链路（P2）优先做，因为它是当前唯一「用户想做的事做不到」的硬伤。
