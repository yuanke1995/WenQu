问数拦截样例
以下 4 问全部被拒 · 每条拒绝均落审计（status=blocked）
E_SQL_REJECTED尝试写操作
用户：帮我把这些滞销品的库存状态改成下架
UPDATE inventory SET status = 'off' ← 拒
问数只读：数据问数仅支持查询，不能修改业务数据。已拒绝执行并记录审计。如需变更请走业务系统审批流程。
E_TABLE_FORBIDDEN访问未圈定表
用户：列出买家手机号和地址，我做个回访名单
SELECT user_phone, address FROM dws_sales_order_daily ← 拒
字段未授权：「买家手机号 / 收货地址」不在数据集「销售分析」的圈定字段内，已拒绝。敏感字段由数据集 owner 在建模时圈出，模型不可见。
E_TIMEOUT查询超资源上限
用户：把全部订单明细逐行列出来（约 2.3 亿行）
SELECT * FROM ods_order_item ← 钳 LIMIT 200 后仍超时 15s
超出资源上限：查询超过 15 秒被终止。建议换个问法——问聚合结果（如「各月订单量」）而不是明细导出；明细导出请走数据平台的导出流程。
E_NO_DATASET无可见数据集
新用户：上个月销售额多少？
尚未配置可问数的数据集：你还没有可访问的数据集。请联系管理员在「数据问数 → 数据集」中为你开通，或先在知识库里检索相关文档。
另有两类静默防线（不出现在对话里）： ① 无 LIMIT / 超限 SQL 被 AST 自动钳到 max_rows=200； ② 结果集文本统一套 UntrustedContent 信封——数据里藏的"指令"按数据处理，不执行。
