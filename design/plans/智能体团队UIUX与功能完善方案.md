## 0 一句话讲清楚「智能体团队」

> **在一个会话里，主助手（`lead`）可以派出一群「有名有姓、可被叫名字、跑完不消失」的成员（成员会话），成员之间能互发消息、共享一块带依赖关系的任务板，用户可以随时旁观、追问、叫停。**

它解决的是「一个人干不完 / 需要分工 + 需要人盯」的场景：审计多个目录、并行调研、写+审+改流水线。区别于已有能力：

| 已经有 | 它是什么 | 和「智能体团队」的区别 |
|---|---|---|
| 普通对话 | 一个助手串行回答 | 团队是**多个成员并行**，且成员可被点名追加任务 |
| 子智能体委派（`agent_spawn`） | 临时支线，**跑完即删**，只回一份结果 | 团队成员的会话**持久、可恢复、可再次唤醒**，是「同事」不是「一次性外包」 |
| 工作流 | 编译期固定的节点图，一次运行 | 团队是**运行时**由模型边干边建的成员树与任务图，可中途改派、追问 |
| 定时任务 | 按时间触发一次运行 | 团队是**同轮协作**，任务板负责先后依赖 |

**开关是会话级的，不是平台开关、也不是智能体固有属性。** 关闭时全链路不挂 `team_*` 工具、不显示团队面板，行为和现在逐字一致（回滚即关开关）。

## 2 领域模型与不变量（给实现者和设计者的同一份事实）

- **会话种类**：`chat`（用户会话）/ `temp`（一次性，跑完即删）/ `team`（团队持久成员，不进普通侧栏）。
- **成员行关键列**（`V35`）：`team_enabled`（仅根会话有意义）、`root_session_id`、`parent_session_id`、`member_name`、`member_state`、`last_read_event_id`。
- **根名固定 `lead`**；成员名规则：1–32 位小写字母/数字/连字符、字母开头、同级唯一、不能叫 `lead`；模型侧优先 slash 全路径，短名与 sessionId 也接受（`resolveName` 三者兼容）。
- **任务状态机**：`PENDING →（前置全完成）READY →（claim）IN_PROGRESS → COMPLETED/FAILED`；`CANCELLED` 为显式终态；失败**不解锁**下游。
- **不变量**：
  1. 一棵树一个根；消息/中断要求发送者是目标祖先或根。
  2. 团队开关只写会话行，**不新增任何系统配置项**。
  3. 关闭团队 → `team_*` 全不挂、面板隐藏、分支回退 `temp` 语义。
  4. 事件信封 `{type,content,sessionId,seq,pos}` 不动，新字段进 `content`，老前端忽略。

## 3 关键流程（“用得顺”的口径）

1. **开启 → 委派 → 协作 → 收敛**
   顶栏胶囊或右栏开关开启团队 → 用户一句话要求分工 → `lead` 经 `agent_spawn` 派 `reviewer/writer/...`（各成 team 会话） → 成员干活，`lead` 用 `team_task_*` 拆任务/加依赖、用 `team_send` 追加要求 → 成员汇报回传 → `lead` 综合成正文 → 用户可「收起团队」结束。
2. **追问一位成员**
   正文成员汇报卡点「向它追问」→ 面板该成员下方就地展开输入 → 发送 → 成员（在线 steer / 离线唤醒）下一轮读到 → 回报进「成员消息」卡。
3. **叫停**
   成员卡「叫停」→ 只停该成员当前轮，排队消息保留，状态 `STOPPED`；根「全部停止」→ `drain` 整树。
4. **离线唤醒**
   成员离线时用户/其他成员发消息 → 落 `team_message` 事件 + `next_run_at` → 冷恢复时 `TurnPromptAssembler` 注入未读 → 起一轮。
5. **断线重连 / 换设备**
   成员树、任务图、成员消息以 `c_ai_session` / `c_ai_team_task` 为真源重建；前端 snapshot 分支补成员快照。

## 4 信息架构与入口

```
对话页（会话级团队）
├─ 顶栏：团队胶囊（成员数 · 在线状态点）——开关 + 打开面板
├─ 正文：成员汇报卡（卡脚：追问 / 查看成员会话 / 执行过程）
└─ 右栏 Tabs：过程 / 来源 / 文件 / 浏览 / 团队
      └─ 团队 Tab
            ├─ 团队成员（树：lead + 成员；状态/职责/叫停/回显/消息）
            ├─ 任务图（只读 DAG；点节点 → 时间线）        ← 折叠进面板的“小图”
            └─ 成员消息（聚合流 + 内联输入：文本/图片/文件）
成员会话整页（点成员进入）
├─ 左侧：会话 + 「团队·本次会话」分组（成员 + 状态点）
├─ 顶部：← 返回主会话 | 团队/成员 | 团队成员会话 chip | 状态 | 在主会话中查看 | 停止
└─ 正文：委派任务卡 + 成员回答（执行过程可展开）+ 结论/产物 + lead 追加消息 + 输入区
任务图全画布（点「展开画布」）
└─ 左：节点列表（按状态分组） 中：DAG 画布（节点染色+依赖箭头） 右：任务时间线
```

**为什么这么放**：团队是「这一轮协作的形态」，最自然的入口就在正在聊的这个会话旁边（右栏），不新开一级菜单；成员会话需要整页读长内容，所以给整页回显；任务图完整画布信息密度高，用「展开」进大图，而不是把右栏挤爆。

## 6 现状差距与完善动作（本方案核心）

> 按「影响体验×成本」排序。`文件/接口` 均指向当前代码。

**P1（先补，直接决定“能不能用”）**
1. **面板缺输入区**：`TeamPanel.vue` 只有叫停按钮，`sendTo()/toggleMsg()` 无对应模板。→ 成员卡展开内联输入（文本），复用 `api.sendTeamMessage`；发送后成员卡状态转「执行中」。
2. **面板消息/任务不实时**：3s 轮询。→ `useChatEngine` 订阅 `team_member/team_message/team_task`，面板 reactive 更新；轮询兜底 15s。
3. **任务图太粗**：平铺列表无依赖视觉。→ 抽 `TaskDagBoard.vue`（复用 `FlowEditor` 节点染色，只读），面板内嵌缩略图，「展开」进全屏画布。
4. **任务时间线没接**：`getTeamTaskEvents` 已存在未用。→ 任务详情抽屉展示事件序列 + owner + 结果 + 来源轮次。
5. **成员汇报卡动作**：正文卡脚加「向它追问 / 查看成员会话」，后者走 `ChatPage` 已有 `memberViewRoot`。

**P2（打磨，决定“好用/专业”）**
6. **顶栏团队胶囊**：成员数 + 在线点 + 一键开关/开面板；未开启时是弱「开启团队」。
7. **消息支持图片/文件**：输入区加「图片 / 文件」，走 `/chat/attachment`，唤醒成员时随轮带 `filed`/图片；消息卡渲染附件。
8. **未读与通知**：成员汇报给根时若用户不在，会话行未读徽标 + 通知中心一条；面板成员未读角标。
9. **状态词收口**：前端状态映射统一到一个 `teamStatus.js`，与 `member_state` 和任务 `state` 同源，不再各写一套。
10. **边界态**：空/加载/错误/全离线/全停止/窄屏 sheet/断连重连 banner 全部给到位。
11. **`drain` 二次确认** + 成员上限与超时的错误文案（随会话收口，不做系统配置）。

**P3（评估，不在本次）**
12. 跨副本成员寻址与消息一致性的压测；多用户协作（成员 ACL）；框架 teamsMode 迁移。

## 8 风险与回滚

| 风险 | 缓解 |
|---|---|
| 新增 `kind=team` 混进会话列表 | 所有 `kind != temp` 查询同步加 `!= team`，写测试枚举查询点 |
| 面板轮询变订阅后事件乱序/重复 | 每条 `team_message` 带 `msgId`，游标 + 事件 id 去重 |
| 状态词双轨（面板 vs 任务表） | 前端状态映射同源于 `member_state` / `c_ai_team_task.state` |
| 持久成员会话占存储 | 沿用现有会话保留/清理，成员数由根会话收口，不做系统参数 |
| 团队开启需重建会话 | 开关变更时 `evictSession` 重建；UI 提示“开启后会重建本次绑定” |

**回滚**：关闭会话级团队开关 → 不挂工具、隐藏面板、分支回 `temp`；新列/新表保留不删，避免历史引用断裂。
