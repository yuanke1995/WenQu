# MCP 外部工具升级 · 效果图制作计划

> 用户口径：「看下这个 MCP 的升级方案，出个效果图；不必按照方案上说的来出效果图，可以看看现状之后再出」。
> 范围已确认：**主页 + 试调用弹窗 + 统计抽屉** 三张，克制版、不加「新」角标。

## 1. 摘要

只做设计交付，不动业务代码。基于当前真实页面（`web/src/views/McpPanel.vue` + `AppLayout.vue` 外壳 + `app.css` token）制作 3 张 1600×1000 @2x 高清效果图，并保留一个可直接在浏览器打开的设计稿 HTML。设计目标是把方案里的功能点收敛成「平时看起来和现状几乎一样、需要时才展开」的安静界面。

| `docs/mcp-panel-upgrade/assets/mcp-panel-main.png` | 主页全景（6 卡，仅展开 1 张失败卡 + 1 张已连接卡） |

## 2. 现状分析（已读代码）

- 外壳：左侧 232px 白色侧栏（`AppLayout.vue:1616`，logo/新建对话/导航/搜索会话/工作区/会话列表/底部用户区）；主区为「智能体工作台」Tab 容器（`AgentsHubPage.vue`，`ant-tabs` 13px，nav 内边距 `4px 20px 0`）。
- 页面：`McpPanel.vue` 页头 = `共 N 个服务 · 已连接 N · 更新于 HH:mm:ss` + 说明文案 + 右侧 `搜索(200px) / 刷新图标 / 全部重连 / 添加服务 / 批量管理`；卡片 `.app-card mcp-card`，第一行状态点+名称+平台 pill+状态文字，第二行传输类型 pill+URL，右侧开关/重连/编辑/删除；已连接卡点击整行展开工具清单（工具名 code + 可选中文名 + 描述 + 改名/起中文名）。
- 现有问题：失败卡不可展开、错误原文截断直出 Java 文本；凭据键名后端已返回但界面不展示；工具只能改名、不能试调用；无调用统计；页头没有任何用量视图。
- 设计语言：`app.css` 的 `--app-*` token（底 `#f7f8fa`、面板 `#fff`、次级 `#fafbfc`、描边 `#e6e9ed`、主色 `#2e6be6`、成功 `#3b8f4e`、告警 `#c77c14`、危险 `#d4552e`、圆角 6/10/14、字号 11/12/13/15、阴影 `0 1px 2px rgba(16,24,40,.04)`）；按钮沿用 `.app-btn` / `.app-btn.ghost` / `.app-link-btn`。
- 工具链：`web/node_modules` 已含 `playwright`，`~/Library/Caches/ms-playwright/chromium-1252` 可用，可本地渲染 HTML → PNG。

## 3. 设计决策（与方案 §1.3 的差异）

1. **只出 3 张**（方案原定 5 张）：编辑弹窗与导出确认属既有/低风险面，不单独出图；把视觉预算集中在两个真正的新界面。
2. **卡片信息层级微调**：状态文字从第一行移到第二行行首（与传输类型、URL、凭据、用量同排），第一行只留「状态点 + 名称 + 平台 pill + 展开箭头」；名称不再和长状态文案抢宽。
3. **可展开性有明确箭头**：已连接/失败卡在信息区末尾加 12px 灰色 chevron，展开后旋转 180°；连接中、已停用卡不显示。
4. **页头只加两个克制的元素**：统计入口是灰色小字「近 7 天 128 次 · 成功率 96%」（用细分隔线与计数分开），导出是 ghost 小按钮（download 图标 + 「导出」）；不引入徽标/胶囊。
5. **失败卡展开**：一行人话原因（危险色文字，无底色横幅）→ 折叠项「错误原文与排查建议」（含等宽原文块 + 复制 + 2 条建议）→ 底部左侧灰色退避提示、右侧「重连 / 测试连接」两个 ghost 小钮。
6. **工具行**：每行右侧并列「试一下」与「改名」，都是 12px 灰色小字（hover 主色），不用按钮；避免每行出现两个彩色控件。
7. **试调用弹窗**：660px，左 1fr 入参 JSON / 右 216px 参数说明；结果区在虚线分隔下方，成功/失败用弱底小胶囊 + 耗时 + 复制。
8. **统计抽屉**：460px 右侧抽屉，三块并排汇总 + 「按服务」「按工具 Top 20」两张紧凑表；数字右对齐、等宽数字。
9. 不做暗色、窄屏、动效示意；不画「新」角标；不改任何现有文案的结构（页头说明文案保留）。
10. 画布统一 1600×1000、`deviceScaleFactor: 2`，保证中文字体清晰；主区宽度约 1368，可容纳 6 张卡 + 两处展开而不出现滚动条。

- 主区 Tab：`模型供应商 / 智能体 / 技能 Skills / MCP 外部工具（选中，蓝色下划线）/ 工作流 / 定时任务`。
- 页头（56px）：左 `共 6 个服务 · 已连接 3 · 更新于 14:26:08`，细竖线，灰色统计链 `近 7 天 128 次 · 成功率 96%`，说明文案 `接入外部 MCP 服务，它的工具自动注册给模型，与内置工具一样可被调用`；右 `搜索名称或地址(160px) / 刷新图标 / 全部重连 / 导出 / 添加服务(主色) / 批量管理`。

## 5. 实施步骤

1. 写 `docs/mcp-panel-upgrade/mcp-panel-upgrade.html`：内联全部 CSS（token 子集 + 三个场景样式），无外链、无图片，字体走 `-apple-system/PingFang SC`；每个场景是 1600×1000 的 `.scene` 方块，场景外只放一行标题 + 一句说明。
2. 渲染脚本临时写到 `/tmp/render-mcp-mockup.mjs`，用 `web/node_modules/playwright` 的 chromium，`deviceScaleFactor: 2`，分别对 `#scene-main`、`#scene-playground`、`#scene-stats` 截图到 `docs/mcp-panel-upgrade/assets/`。
3. 用 Read 逐张查看 PNG，修掉所有溢出/换行/重叠/滚动条；必要时调场景内边距或文案长度。
4. 用浏览器打开 HTML 自检（三个场景之间的说明文字不与场景抢视线）。

## 6. 验证

- 3 个 PNG 均为 3200×2000（@2x），`file` 确认 PNG 头正常。
- 主页无纵向滚动条；6 张卡全部在 1000px 高度内；展开箭头方向正确。
- 弹窗/抽屉遮罩覆盖整屏、内容不被裁切；中文字体不是宋体/方框。
- 对比 `--app-*` token：颜色、圆角、字号与真实页面一致；没有自造品牌色。
- 浏览器直接打开 HTML 可看到三个场景，滚动正常。
