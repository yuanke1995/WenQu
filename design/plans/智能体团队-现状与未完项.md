# 问渠「智能体团队」现状与未完项（ADR）

- 日期：2026-11-24
- 状态：**以本文为准（single source of truth）**。设计快照见同目录另外四份方案，凡与本文冲突者，按本文。
- 适用范围：会话级「智能体团队」——持久成员会话、成员消息、共享任务板 DAG、右栏团队面板、成员页、任务全画布。
- 关联代码：后端 `src/main/java/com/wenqu/ai/agent/team/**`、`src/main/java/com/wenqu/ai/agentx/team/**`、`TeamController`、`ChatController`；前端 `web/src/components/TeamPanel.vue`、`TeamPill.vue`、`TaskDagBoard.vue`、`web/src/chat/useChatEngine.js`。

## 0. 一句话现状

> 在一个会话里，主助手 `lead` 可经框架 `agent_spawn` 派出一群持久成员（`kind=team` 会话，跑完不删）；成员之间走框架邮箱互发消息、共享一块带依赖的任务板；用户在右栏「团队」面板看成员树/任务图/团队动态，点成员进整页会话，任务可展开全画布。**开关是会话级（`team_enabled`），不是系统配置；关闭即整树失去团队工具面，成员与任务保留。**

底层是 **AgentScope 原生 `teamsMode`**（`TeamsMiddleware` + `TeamTool` + `TeamClient/LocalTeamClient`），问渠只补了三个契约适配器（MySQL `BaseStore` / Redis `MessageBus` / 任务事件旁听）与一把 `team_task_depend` shim。

## 1. 概念边界（不变）

| 已经有 | 团队是什么 | 区别 |
|---|---|---|
| 普通对话 | 一个助手串行回答 | 团队**多成员并行**、可点名追加 |
| 子智能体委派 `agent_spawn` | 临时支线，跑完即删 | 团队成员**持久、可恢复、可再次唤醒** |
| 工作流 | 编译期固定节点图 | 团队运行时由模型边干边建树与任务图 |
| 定时任务 | 按时间触发 | 团队同轮协作，任务板管先后 |

不变量：
1. 一棵树一个根；根名固定 `lead`。
2. 团队开关只写会话行（`c_ai_session.team_enabled`），**不新增任何系统配置项**。
3. 关闭团队 → 不挂团队工具、面板隐藏、成员与任务保留；非团队轮 `NoopBusComponents` 不动、每轮零额外开销。
4. 成员权限不越过根会话（详见 §3）。
5. 事件信封 `{type,content,sessionId,seq,pos}` 不动；团队事件走 `team_member / team_message / team_task`。

## 2. 当前架构（team 会话）

```
根会话（team_enabled=1）
  HarnessAgent.builder
    .teamsMode(WenquTeamClient(LocalTeamClient), TeamContext(lead, 全名册, lead 动作), sessionId)
    .messageBus(WenquRedisMessageBus)                 // 仅团队会话换真总线
    .subagentFactory(...)                              // agent_spawn 派成员 → createTeamSession(kind=team)
模型面：agent_spawn / agent_send / agent_list（框架）+ team（框架 TeamTool）
        + team_task_depend（薄 shim：框架 TeamTool 不暴露 blockedBy 的唯一缺口）
持久层：WenquMysqlBaseStore（BaseStore，version CAS）→ LocalTeamClient（任务板/邮箱/名册全框架实现）
        c_ai_team_store（V37）
总线：WenquRedisMessageBus（inboxPush / enqueueWakeup / queue / log）
事件账本：c_ai_team_task_event（V39，WenquTeamClient 旁听投影）
```

关键文件：

| 关注点 | 落点 |
|---|---|
| teamsMode 装配 | `AgentscopeChatEngine.buildAgent`（`messageBus` + `teamsMode`） |
| 框架门面 | `WenquTeamGateway`（命名空间 / DTO / 成员补名册 / `addDependency`） |
| 持久 BaseStore | `WenquMysqlBaseStore`（`putIfVersion` 走 `version` CAS） |
| 消息总线 | `WenquRedisMessageBus`（`enqueueWakeup` 回调 `TeamWakeService`） |
| 成员生命周期 | `AgentTeamService`（树 / 在线态 / 叫停 / 整树 drain / 开关） |
| 控制器 | `TeamController`（开关 / 成员 / 消息 / 任务 / 事件时间线 / 历史） |
| 权限封顶 | `WenquAgentxTools.policyFor` + `capPolicy`（沙盒/审批取更严、deny 并集） |
| 成员树深度 | `dispatchAllowed` + `TEAM_MAX_DEPTH=2`（lead→成员→`reviewer/checker`） |

## 6. 多副本上线 checklist（当前单副本 `app` 通过，横向扩容前必须过）

> 触发点：`WenquTeamGateway` 注释已声明「`LocalTeamClient` 消息序号是实例内 `AtomicLong`，必须全应用单实例」。

- [ ] **消息序号冲突**：每个 JVM 各持一份 `LocalTeamClient`，`messageSeq` 进程内自增 → 多副本下消息 id 撞车。上线前二选一：① 单副本串行；② 把序号落到 `BaseStore`/Redis 单调序列（改 `WenquTeamClient` 或换 `TeamClient` 实现）；③ 按根会话一致性哈希把同一团队钉到一个副本。
- [ ] **跨副本唤醒**：`WenquRedisMessageBus.enqueueWakeup` 只回调**本进程** `wakeupHandler`；若成员活轮在另一副本，唤醒会落到发起副本或漏唤醒。需要 Redis pub/sub 把 wakeup 投到持有该会话的副本（`subscribe` 当前返回空流）。
- [ ] **重复起轮**：`TeamWakeService.wake` 用本地 `runtime.turnIdOf` 判活轮，跨副本看不到别的副本上的活轮 → 可能重复起轮。需分布式轮锁或 Redis 活轮注册表。
- [ ] **ChatRunBus.tap 仅进程内**：团队事件只在发布副本的订阅者可见；跨副本面板若走旁路订阅需跨副本广播。
- [ ] **BaseStore 压力**：任务/邮箱每次读走 `c_ai_team_store` 全命名空间 scan（`search`），成员/任务多时要看 `idx_team_store_ns` 命中与 SQL 延迟。
- [ ] **SSE 中间层**：若后续加常驻团队事件流，确认反代不缓冲 `text/event-stream`（参见 dev:prod 的 `/api` 反代缓冲坑）。
- [ ] **迁移**：V37/V39 均为新增，向后兼容；回滚总开关仍是 `team_enabled=0`。

## 7. 验收清单（对齐底座方案 §7 + UX 验收）

1. 开团队 → 派两人 → 面板显示两名在线成员、名字/路径正确。
2. 成员跑完不删、`IDLE`；再发消息能唤醒且上下文连续。
3. 任务 A→B 依赖：A 完成 B 可认领；**面板任务弹窗/DAG 右栏能看到「创建→登记依赖→认领→完成」时间线**。
4. 成员页发送消息：该轮挂团队工具、权限不越过根；面板「发给成员」走后端 `/team/send`。
5. 叫停只停当前轮、排队消息保留；根 `drain` 整树。
6. 团队事件到达时面板不刷新整页、去抖更新；无事件时 15s 兜底仍更新。
7. 关闭团队：整树失去团队工具面，任务与成员保留；普通问答零回归。
8. 普通用户看不到他人团队；guest/API Key 不挂团队工具。
