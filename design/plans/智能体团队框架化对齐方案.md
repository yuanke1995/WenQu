# 智能体团队 · 对齐 DSH 的框架化改造方案

- 日期：2026-11-24
- 状态：**已落地主体（2026-11-24）**：① 框架底座三件套（`WenquMysqlBaseStore` V37 + `WenquRedisMessageBus` + `WenquTeamGateway`）② 团队会话接 `teamsMode` + Redis 总线 ③ 工具面收敛为框架 `agent_*` + `team` ④ 删除自研 `TeamTools/TeamTaskTools/TeamWaitTool/TeamToolProvider/TeamTaskService` 及其模型/mapper/表（V38）⑤ 成员生命周期 `AgentTeamService` 瘦身（仅留树/状态/叫停/开关）⑥ 关闭团队整树叫停+逐出 ⑦ 成员树支持嵌套到深度2（lead→reviewer→reviewer/checker，用框架原生深度，成员名带父路径） ⑧ 成员权限封顶：`WenquAgentxTools.policyFor` 把成员轮钳到根会话策略之下（沙盒/审批取更严、deny 并集），`capPolicy` 纯函数单测通过。剩余：真机联调（派成员/嵌套/邮箱唤醒/任务板/关闭全树）+ 前端 vite build。
- 背景：上一轮架构评审指出 6 处问题（两套工具面 / 成员树实为一层 / 权限模型与文档不符 / lead 寻址 / 唤醒准入与 team_wait 耦合 / 关闭团队在飞成员不生效），用户定调：**对齐 DSH 思路，能用框架用框架，别在自研**。
- 结论先行：把「智能体团队」的底座换成 **AgentScope 原生 `teamsMode`**（`TeamsMiddleware` + `TeamTool` + `TeamClient`/`LocalTeamClient`）；框架**没有**的三样用最小「契约适配器」补齐（MySQL `BaseStore`、Redis `MessageBus`、`WenquTeamClient extends LocalTeamClient`）。删除自研的 `AgentTeamService` / `TeamTools` / `TeamTaskTools` / `TeamWaitTool` / `TeamTaskService` / `TeamToolProvider`。

## 0 为什么这是「对齐 DSH」而不是又一次自研

DSH 的团队层很薄：`dsh-agent-team` 只加一块共享任务板，成员发现/消息/中断/等待全部复用 `dsh-subagent` 的 `list_agents / send_message / interrupt_agent / wait_agent`。

AgentScope harness 其实提供了同构的骨架，之前没用起来，是因为三处「框架没给现成实现」被误当成「框架不支持」：

| 框架已提供（直接用） | 位置（已核验 jar 源码） |
|---|---|
| `teamsMode(client, context, sessionId)`：自动挂 `TeamsMiddleware` + 注册角色裁剪的 `team` 工具 + 每轮注入团队提示与看板摘要 + 注册唤醒桥 | `HarnessAgent.java:1420-1450, 2792-2812` |
| `TeamClient` 全量契约：任务板（含 `blockedBy`）/ 邮箱 / 成员名册 / CAS | `agent/team/TeamClient.java` |
| `LocalTeamClient`：任务板 CAS、邮箱、名册、订阅唤醒，**只差一个 `BaseStore`** | `agent/team/LocalTeamClient.java` |
| `TeamTool`：单个 `team` 工具，`action` 覆盖 listTasks/createTask/claim/complete/sendMessage/listMembers…，按角色裁剪 | `agent/tool/TeamTool.java` |
| `TeamContext.availableActions()`：lead 与 worker 的能力差异由框架裁剪 | `agent/team/TeamContext.java` |
| `SubagentDeclaration.inheritParentPermissions`：子代权限继承 | `agent/subagent/SubagentDeclaration.java` |
| `agent_spawn` 原生嵌套上限 `MAX_SPAWN_DEPTH = 3` | `agent/tool/AgentSpawnTool.java:111,343` |

框架**没有**、只能最小补齐的三样（这是「适配器」，不是领域重写）：

1. **持久 `BaseStore`**：框架只带 `InMemoryStore`，`LocalTeamClient` 因此不能跨副本/重启。→ 实现 `WenquMysqlBaseStore implements BaseStore`（`putIfVersion` 走 `version` 列 CAS）。
2. **真实 `MessageBus`**：框架只有 `WorkspaceMessageBus`（走沙盒文件系统）。问渠现在用 `NoopBusComponents.MESSAGE_BUS` 顶成恒空，因此 `TeamsMiddleware` 的唤醒会静默失效。→ 实现 `WenquRedisMessageBus implements MessageBus`（`inboxPush`/`enqueueWakeup`/queue/log）。
3. **`spawnMember`/`shutdownMember`/`blockedBy`**：`LocalTeamClient.spawnMember` 直接抛“requires control-plane”；`TeamTool.createTask` 把 `blockedBy` 写死成 `List.of()`。→ `WenquTeamClient extends LocalTeamClient` 覆写 `spawnMember/shutdownMember` 接到问渠成员生命周期；再补一把极薄的 `team_task_depend`（只是把 `TeamClient.createTask(..., blockedBy)` 暴露给模型，不新造引擎）。

## 1 现状与框架的差距（逐条对应评审 6 处）

| 评审项 | 现状自研落点 | 框架化后的落点 |
|---|---|---|
| P0-1 两套工具面 | 框架 `agent_spawn/send/list` + 自研 `team_list/send/wait` + `team_task_*` 并存 | 模型面只剩：`agent_spawn/agent_send/agent_list`（框架）+ 框架 `team` 工具 + 一把 `team_task_depend` shim |
| P0-2 成员树实为一层 | `dispatchAllowed` 对 `branchTurn()` 直接 false | team 模式放开 `branchTurn` 派遣；用框架 `agent_spawn` 原生深度（≤3）；成员名走全路径 slug |
| P0-3 权限与文档不符 | 成员是真实 uid 会话，拥有用户全权 | spawn 时快照根 `ExecutionPolicy` 作为委派上限，成员轮取交集；同时启用框架 `inheritParentPermissions` |
| P1-4 lead 寻址 | `resolveName` 只认 `lead`、`sendMessage` 拒绝 root | 寻址交给框架名册（`lead`/全路径/session id），删掉 `resolveName` |
| P1-5 唤醒准入 + wait 耦合 | `CompletableFuture.runAsync` 自起整轮；`team_wait` 借 HITL pending | 唤醒走框架 `TeamWakeups` → `MessageBus`；等待走框架 `wait_async_results`/inbox，不再碰审批 pending |
| P2-6 关闭不彻底 | evict 只重建根，成员实例仍挂 team 工具 | 工具面中间件每步读 live root 团队态，关闭即在全树隐藏团队工具，任务/成员保留 |

## 2 目标架构

```
根会话（team_enabled=1）
  HarnessAgent.builder
    .teamsMode(WenquTeamClient, TeamContext(lead, 全名册, lead 动作), sessionId)
    .messageBus(WenquRedisMessageBus)        // team 会话才换真总线；非 team 仍 Noop
    .subagentFactory(...)                     // 成员经 agent_spawn 派出
        └─ agent_spawn(team 模式) → SubAgentBranchRuntime
              createTeamSession(kind=team, memberName=全路径 slug, policyCeiling=根快照)
              roster: WenquTeamClient.createTeam 种子/追加成员
              HarnessAgent.builder.teamsMode(WenquTeamClient, TeamContext(role, worker 动作), memberSessionId)

模型面（team 会话）：
  agent_spawn / agent_send / agent_list        （框架 subagent 工具，管人）
  team（框架 TeamTool，单工具 action）          （框架任务板 + 邮箱 + 名册）
  team_task_depend（薄 shim，只为暴露 blockedBy） （框架 TeamClient.createTask 的缺口）

持久层：
  WenquMysqlBaseStore（BaseStore，version CAS）→ LocalTeamClient（任务/邮箱/名册全部框架实现）
Redis：WenquRedisMessageBus（inboxPush / enqueueWakeup / queue / log）
```

## 3 六处修复的具体做法

### P0-1 单一工具面
- 删除 `TeamTools`、`TeamTaskTools`、`TeamWaitTool`、`TeamToolProvider` 的挂载。
- team 会话的模型面 = 框架 `agent_*` 三把（已有）+ 框架 `team` 工具（`teamsMode` 自动注册）+ 一把 `team_task_depend` shim。
- `AgentxToolSurfaceFilter` 的 `SUBAGENT_TOOLS` 逻辑保留；team 关闭时连同 `team` 工具一起隐藏。
- 前端工具卡展示名：`team` 工具与 `team_task_depend` 在 `FrameworkToolLabels` / `ToolDescriptor` 里补中文名；删除 `team_list/send/wait/task_*` 的标签。

### P0-2 真·成员树
- `dispatchAllowed`：`if (cmd.branchTurn() && !cmd.isTeamMode()) return false;`（非团队的子轮仍不许派，防乘数扇出；团队子轮允许，受深度上限约束）。
- 深度：沿用 `subagentDepth`，到 `TEAM_MAX_DEPTH`（默认 2，框架硬上限 3）即由 `dispatchAllowed` 拒绝；提示词同步一句“到顶不再派”。
- 命名：成员 `memberName = parentPath + "/" + slug(agentName)`（根的子代为 `reviewer`，孙代为 `reviewer/checker`）；`slug` 规则 1–32 小写字母/数字/连字符、以字母开头、同级唯一、不能是 `lead`。名册由 `WenquTeamClient`（LocalTeamClient 的 `memberNs`）承载，天然全树唯一。
- 这解决了文档 §3.2/§10 与实现不符的问题：要么树真能长，要么文档不说；本方案选“真能长”。

### P0-3 委派权限上限（不再宣称“成员拥有用户全权”）
- 新增成员会话列（或一张 `c_ai_team_member`）：`policy_ceiling`（root spawn 时 `ExecutionPolicy` 的 `preset/sandboxMode/approvalMode/deny` 快照）、`root_owner_uid`。
- 成员轮构建 `ExecutionPolicy` 时取 `intersect(用户当前策略, policy_ceiling)`：档位取更严的、审批取更严的、deny 取并集；**成员无法在会话内扩大**（上限来自根 spawn 时刻，子轮读不到“更宽”的用户设置）。
- 框架侧 `SubagentDeclaration.inheritParentPermissions=true`，让工具面继承也一致。
- 文档 §4.4/§10 改用词：不再写“对齐 `subagent:delegation`（子代无父权限）”，改成“成员以用户身份运行，但能力被 spawn 时刻的策略快照封顶”。

### P1-4 寻址
- 删 `AgentTeamService.resolveName`；`team_send` 不再自造，改用框架 `team(action=sendMessage, to_member=...)`，`to_member` 取框架名册里的 `lead`/全路径/session id。
- 允许发给 `lead`：`LocalTeamClient.sendMessage` 本身不拒绝 root（只拒绝发给自己）；自研的 `if (target.equals(rootId)) return false` 删除。
- `list_agents` 输出名册全路径；`team(action=listMembers)` 输出名册。

### P1-5 唤醒准入 + wait 解耦
- 删除 `AgentTeamService.sendMessage` 里的 `CompletableFuture.runAsync(... turnRunner.run ...)`。
- 唤醒统一走框架：`LocalTeamClient.sendMessage` → `TeamWakeups.wake(teamName, to, content)` → `TeamsMiddleware.wakeupTeamMember` → `MessageBus.enqueueWakeup` → 目标会话起/续一轮（`InboxMiddleware` 在下一模型步注入）。
- 准入：`MessageBus` 侧按会话串行 + `maxActiveSubagents`（框架 `SubagentMiddleware` 已支持每树 8）；空闲成员收到消息只起一轮、并发消息合并。
- `team_wait` 删除；成员等消息用框架 `wait_async_results`（它明确“任务变化不结束等待、只等自己 inbox”），与审批 pending 彻底分开。

### P2-6 关闭团队全树生效
- `AgentxToolSurfaceFilter` 增加 `teamActive()`：每步读 live root（`sessionService.isTeamEnabled(rootOf(session))`），false 时隐藏 `team` 工具与 `agent_*` 三把。
- 成员实例不重建也能在下一模型步“看不见”团队工具；任务板与成员会话保留（对齐 DSH“关掉只隐藏工具与引导，保留任务与子智能体”）。
- 根关闭时不再 `evictSession` 成员；`drain` 只停当前轮。

## 6 验收

1. team 会话模型面**只有一套**：`agent_spawn/agent_send/agent_list` + `team` + `team_task_depend`；截图工具表无 `team_list/send/wait`。
2. 根派 `reviewer`，`reviewer` 再派 `checker` → 名册出现 `reviewer/checker`，深度到顶被拒。
3. `team(action=createTask, ... + blockedBy)` 建依赖；前置完成后继从 `pending` 变可认领；`team_task_depend` 能补边。
4. 成员 `sendMessage(to_member=lead)` 成功；lead 收到并在下一步上下文看到。
5. 空闲成员收到消息被真实唤醒一轮（MessageBus），并发两条不重复起轮。
6. 关 `team_enabled`：成员下一步工具面即无 `team`/`agent_*`，任务与成员仍在。
7. 权限：成员 `ExecutionPolicy` 不超过 spawn 时根快照（构造用例断言）。
8. 全量 `mvn -o -DskipTests compile` + 定向测试 + 前端 `npx vite build` 通过。
