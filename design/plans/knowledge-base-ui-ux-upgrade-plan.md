### 1.3 用户现在回答不了的四个问题

1. **哪个库真的在被用？** 没有命中次数、没有最近使用，库与库之间无法比较。
2. **哪个库坏了？** 解析失败、排队积压、未绑定向量模型、混合权限，都要逐个点进去才发现。
3. **检索效果好不好？** 没有语义试检索、没有分数与命中判定，描述/分块/参数调了也不知道有没有变好。

## 2. 设计目标与原则

1. **首屏先给结论**：进入页面 3 秒内看到「6 个库 · 128 文档 · 3,842 知识块 · 90 天命中 1,206 · 2 个需关注」，每个数字可点击下钻成筛选。
2. **每张卡是一份体检报告**：文档/知识块/命中三列数据 + 状态分段条（已入库/解析中/失败/弃用）+ 向量模型与参数覆盖 + 被引用智能体数。
3. **操作分级**：卡面只留「打开」与「试检索」；编辑/图谱/导出/复制/归档收进 ⋯，删除退到二级并展示影响面。
4. **危险操作先给退路**：新增「归档」中间态（保留文档与向量、从检索与智能体绑定中摘除，可恢复），删除仍二次确认。
5. **从「管文档」到「验检索」**：任意库可开试检索，看到 topK 分数拆解与命中判定；未命中问题自动沉淀，可一键加入评测集。
6. **异步任务必须可见**：解析队列、导入、图谱构建都有独立进度与失败重试，不靠 toast 碰运气。
7. **沿用现有设计语言**：只用 `app.css` 令牌与 `.app-card / .app-btn / .app-pill` 类，不引入新视觉体系；暗色主题自动继承。

## 3. 信息架构与交互重构

### 3.1 库列表页（场景 1）

```
页头：知识库 · 副标题一句话        [搜索库]  [卡片/表格]  [导入文档包] [新建知识库]
统计条：[6 个库] [128 文档] [3,842 知识块] [90天命中1,206] [需关注 2 ⚠]   ← 每项可点击=筛选
筛选行：归属分段（全部/我的/官方/共享） · 健康 chips（全部/需关注/正在解析/未绑定模型） · 排序（最近使用/文档数/名称）
卡片：图标 + 名称 + 状态徽标（默认/官方/共享） + ⋯
      描述 2 行（hover 全文）
      数据行：5 文档 · 128 知识块 · 90天命中 96
      健康条：已入库 4 ███ | 解析中 1 █ | 失败 0 | 弃用 1 █
      元信息：BAAI/bge-m3 · 检索/解析已自定义 · 更新于 2 天前 · 被 3 个智能体使用
      底部：[打开] [试检索]                      [⋯]
```

- 点击卡片主体 = 打开「库概览抽屉」；「打开」= 进入文档管理页。
- 「需关注」= 有解析失败 ∪ 有作废任务 ∪ 未绑定向量模型 ∪ 混合可见范围，作为默认警示入口。
- 官方库/共享库保留差异，但组标题降级为筛选维度，不再把网格切碎。
- 空态给「新建知识库 / 导入文档包 / 从模板开始」三个入口，而不是一行灰字。

### 3.2 库概览抽屉（场景 2）

右侧 780px 抽屉，头部常驻：图标 + 名称 + 状态 + [试检索] [文档管理] [⋯]。五个 Tab：

| Tab | 内容 | 数据来源 |
|---|---|---|
| 概览 | 4 个指标（文档/知识块/90 天命中/覆盖提问）+ 文档健康分布 + 30 天检索趋势 + Top 命中文档 + 最近活动 | **新增聚合接口** |
| 文档 | 复用文档管理页列表（带筛选与批量） | 现有 `/document/list` |
| 图谱 | 实体/三元组数量、构建状态、入口（一期跳全屏图谱层） | 现有 GraphRAG 聚合 |
| 设置 | 向量模型 / 检索参数 / 解析参数 / 图谱开关（复用编辑弹窗） | 现有 `/kb/{id}` |
| 未命中 | 该库近 30 天「检索为空或低分」的问题列表，可加入评测集 | **新增聚合 + 现有评测接口** |

### 3.3 试检索（场景 3）

从卡片或抽屉打开 1080px 面板，**只走向量/关键词/重排链路，不调 LLM**：

- 输入问题 → 返回 topK 块，每块显示：融合分、向量分、关键词分、重排名次、来源文档、章节路径、内容片段。
- 右侧「检索诊断」：召回数、重排数、耗时、阈值、命中判定（命中/低分/无结果）。
- 「结果可用吗？」两键反馈 → 不可用直接进入「未命中问题」，可一键「加入评测集」（复用现有 `addEvalCase`）。
- 支持「仅本库 / 全部库」切换，用来判断问题该归到哪个库。

### 3.4 新建知识库向导（场景 4）

三步收敛：

1. **选场景模板**：法规制度 / 产品手册 / 合同协议 / 客服 FAQ / 研发文档 / 个人笔记 / 空白。模板只预置「解析参数 + 分块 + 是否开图谱 + 示例问题」，不预置内容。
2. **基础信息**：名称 / 图标 / 描述 / 向量模型（带「推荐」与兼容性提示）/ 可见范围。
3. **导入资料**：拖拽 zip 或文件 → 清单预览（文档数、同名冲突）→ 冲突策略（替换 / 跳过 / 保留两份）→ 逐文件进度 → 结果报告（失败原因 + 重试）。

模板的价值不是「换个名字」，而是把 K5 的 16 项参数翻译成 6 种常见场景的合理默认值；高级参数仍可展开手改。

### 3.5 文档管理页升级（场景 5）

- **页头降噪**：面包屑 + 库切换下拉 + 「试检索 / 图谱 / 上传 / 更多」；状态概览从标题旁的小字升级为一行可点击的状态 chip。
- **概览条**：已入库 / 解析中 / 失败 / 弃用 / 回收站 + 队列与作废任务，点击即筛选。
- **表格精简**：9 列 → 7 列（文件名含标签 / 状态 / 知识块 / 命中 / 大小 / 更新时间 / 操作）；「知识库」列移除（本页已限定单库），「片段」与「命中」合并为可排序数字。
- **行内展开**：点击行展开预览（章节路径 / token / 图片 / 全文），不再叠二级弹窗。
- **上传队列浮层**：逐文件进度、失败原因、重试与取消；批量栏吸底，不挤压表格。

### 3.6 图谱工作台（场景 6）

一期仍用全屏层（不改路由），但把「浏览」与「写操作」分开：

- 顶部：实体数 / 三元组数 / 最后构建时间 / 构建任务进度；「构建 / 清空」收进 ⋯ 并二次确认。
- 左栏：实体搜索、类型筛选、最近构建记录。
- 中间：力导向图（复用现有 ECharts 实现）。
- 右栏：实体详情 + 完整三元组 + 源知识块溯源（现状能力平移）。
- 图谱构建变成后台任务：可离开页面，进度与失败在库卡片与概览抽屉持续可见。

### 3.7 对话引用回流（P2，随场景 3 一起验收）

- 回答中的引用 chip 显示「法律库 · 3 块」，点击打开引用侧栏（分数、源文档、原文）。
- 每条引用可「有用 / 没用」；没用的问题回流到该库的「未命中问题」。
- 这样「文档 → 检索 → 回答 → 反馈 → 评测」形成闭环，而不是止于文档管理。

## 5. 后端最小改动集（确认后实施）

1. **`GET /api/ai/kb/overview`**
   在现有 `listWithCounts()` 基础上补：`chunkTotal`、`statusCounts{ok,parsing,failed,disabled}`、`recycleCount`、`hit90d`、`lastUsedAt`、`agentRefCount`、`graph{entities,triples,builtAt}`。
   实现：知识块数与状态分布走现有 document/knowledge 表聚合；`hit90d` 复用 `statsHitCounts()`（`hit_doc_ids` 按近 90 天聚合）再按文档归属库求和；`agentRefCount` 扫智能体的 `knowledgeBaseIds` 字段。

2. **`GET /api/ai/kb/{id}/insights?days=30`**
   返回 30 天检索趋势（命中/低分/无结果）、Top 命中文档、最近活动（解析失败、模型变更、导入完成）。趋势优先从问答日志的命中文档反推；若日志缺库维度，则按文档 ID → 库映射聚合，不新增宽表。

3. **`GET /api/ai/kb/{id}/agents`**
   返回绑定该库的智能体（含子智能体）名称、图标、启用状态，用于删除确认与卡片「被 N 个智能体使用」。

4. **`POST /api/ai/kb/{id}/probe`**
   入参：`query / topK / mode / rerank`；出参：每块 `score / vectorScore / keywordScore / rerankRank / doc / titlePath / content`，以及 `recallCount / latencyMs / verdict`。**只走检索链路，不调用聊天模型**，避免试检索产生回答费用。

5. **导入清单与冲突策略**
   `POST /api/ai/kb/{id}/import/preview` 解析 zip 的 `manifest.json`，返回文档清单与同名冲突；导入请求增加 `conflictStrategy=replace|skip|keepBoth`；导入结果沿用现有 `results[]`，前端逐文件展示。

6. **归档（P2）**
   `knowledge_base` 增加 `status`（1 正常 / 0 归档）；归档库不参与检索、不出现在智能体可绑列表，但文档与向量保留，可恢复。删除仍走现有级联。

> 说明：`hit90d` 依赖「问答日志的命中文档 → 所属库」映射；若历史日志里文档已被删除，按未归属处理，不影响总量口径。是否新增库维度日志由实施前确认。

验收：低质问题能沉淀成评测用例；误删有可逆路径；图谱构建可后台跑完。
