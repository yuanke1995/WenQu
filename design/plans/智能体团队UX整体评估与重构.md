# 智能体团队 · UX 整体评估与重构建议

- 日期：2026-11-23
- 目的：跳出「点一个改一个」，整体审视智能体团队的用户体验，给出方向、问题清单、目标结构、待拍板项与分期
- 现状：后端底座（会话树 / 成员消息 / 任务板）已落地；前端为「顶栏团队胶囊 + 右栏团队面板 + 成员页复用普通聊天页」

---

## 0 结论先行

团队 UX 的根问题**不是按钮多少，而是没有给用户一个统一的「团队」心智空间**：现在它散在「顶栏胶囊 + 右栏三段卡 + 每个成员各自的会话页」三处，用户既看不懂“现在谁在干嘛”，也不知道“我该在哪说话”。因此体验像**开发者后台**，不像“我指挥一个小队”。

方向（四句话）：
1. **一个概念一个入口**：团队只在右栏一个分段里，胶囊/卡片不各再造入口。
2. **身份不可变**：成员是谁就是谁——成员页不能换助手、改权限、换模型。
3. **默认安静、按需展开**：任务图、成员间消息默认收起，需要时再展开。
4. **补一条“团队动态”**：用一句话回答“谁在干嘛、有没有要我拍板的”，这是现在最缺的骨架。

---

## 1 用户心智模型 vs 当前实现

用户对“团队”的期待（来自现实协作）：**lead 牵头 → 几个人分头做 → 我随时看到进度、能对某人补一句话、能叫停、最后拿到汇总。**

当前实现是“多会话管理”的开发者视角：成员=独立 session、任务=DAG、消息=账本事件。**能力齐全，但没有翻译成用户语言**。结果：
- 用户看到的是“一堆卡 + 一堆状态词”，而不是“这活分给了谁、进展如何”。
- 用户不知道团队什么时候该开、开了之后“我现在处在团队里的哪一层”。

---

## 2 信息架构问题

1. **入口重复且不稳定**：顶栏胶囊、右栏「团队」Tab、正文成员汇报卡——三个入口指向同一批内容；而团队没开时胶囊又消失，入口到底在哪不稳定。
2. **开关语义错位**：团队是“这一轮协作的形态”，开关却像设置项藏在面板顶部；用户不知道“什么时候、在哪开”。
3. **右栏层级过平**：过程 / 来源 / 文件 / 浏览 / 团队 五个一级分段，团队内部又竖排三张卡（成员 / 任务 / 消息），信息密度在 360px 里过载。
4. **成员页=普通会话页**：进了成员页，换助手、权限档、模型选择、分享、搜索、右栏全在——语义全错位（“这还是我的工作台，只是里面坐着某个成员”），且标题写“新对话”。
5. **没有统一的团队时间线**：团队信息分散在 lead 会话正文的子对话卡 + 每个成员会话 + 面板消息卡，用户拼不出“团队刚刚发生了什么”。

---

## 3 关键旅程走查（含断点）

| 旅程 | 现在怎么走 | 断点 |
|---|---|---|
| **1 开启团队** | 胶囊（关时隐藏）或右栏团队 Tab 空态里的「开启」按钮 | 入口不稳；用户不知道何时该开 |
| **2 委派成员** | 用户说“分三个人做”→ lead 自动派 → 只在右栏成员树看到 | 派遣过程不可见（正文只有零散子卡） |
| **3 观察进度** | 右栏状态点 + 3s 轮询；正文散落成员汇报卡 | 没有“现在谁在做什么”的一句话总览 |
| **4 追问成员** | 点成员进它整页会话发消息 | 进成员页后失去团队上下文；回来要重新找 |
| **5 叫停** | 成员行/成员页「停止」 | 基本可用 |
| **6 收尾** | lead 汇总；成员状态残留 | 团队何时结束、成员会话如何归置不清晰 |
| **异常** | 离线唤醒 / 断线重连 / 失败 / 超上限 / guest | 多数无明确提示 |

## 4 问题清单（按严重度）

### P0 · 影响“看得懂 / 用得了”
1. **入口重复/不稳定**（胶囊 vs Tab vs 卡片）→ 收敛为一个主入口。
2. **成员页身份错位**：不能换助手（已在做）、不能改权限、不应换模型；标题“新对话”应改成成员名。
3. **发消息位置错误**：不在窄栏内联发（已改：进成员页发）。
4. **缺“团队动态”总览**：一句话说清谁在干嘛、有没有要我拍板的。

### P1 · 影响“顺手 / 专业”
5. 右栏三卡竖排过载 → 改**子分段（成员 / 任务 / 动态）**，默认“成员”。
6. 任务图对简单场景过重 → **默认收起为一行摘要**，有任务才出现、点开才看画布。
7. 未读 / 需要拍板的事情不上浮 → 面板与顶栏给未读/待办徽标。
8. 实时靠 3s 轮询 → 订阅 `team_member/message/task` 事件。
9. 成员页与主会话来回切换，浏览上下文丢失 → 返回主会话保留原右栏分段。

### P2 · 打磨
10. 空 / 加载 / 离线 / 停止 / 断线 / 窄屏 sheet 全状态补齐。
11. 任务图只读（能否拖拽/改派，后续评估）。
12. 关闭团队时 UI 逐字恢复原样（回滚口径）。

## 5 目标信息架构

### 5.1 根会话页
```
顶栏：不放团队（去掉重复）      ← 或仅在开启时放一个只读状态胶囊，二选一
正文：正常回答 + 成员汇报卡（保留：结论 / 追问 / 查看会话）
右栏 Tabs：过程 / 来源 / 文件 / 浏览 / 团队
  └ 团队（唯一团队入口）
       ├ 子分段① 成员：一行一人（头像 · 名字 · 状态点 · 当前一句话）→ 点进成员页
       ├ 子分段② 任务：默认一行摘要「5 任务 · 3 进行中」，点开 = DAG 画布 + 时间线
       └ 子分段③ 动态：成员间消息 + “需要你拍板”的事情上浮
```

### 5.2 成员页（专注但不销毁工作台）
```
顶部身份条：← 返回主会话 ｜ 团队 / 成员名 ｜ 状态 ｜ 停止
正文：与这位成员的对话 + 附件（宽输入框，可发图/文件）
隐藏：换助手、权限档、模型切换、右栏「团队」分段
右栏：可保留「过程 / 来源 / 文件」（属于这位成员这次运行），默认收起
```

## 6 设计原则

1. **一个概念一个入口**：团队只有一个家（右栏）。
2. **身份不可变**：成员是谁就谁，成员页只读身份。
3. **默认安静、按需展开**：能一行说清就别先铺开。
4. **状态单一真源、就地反馈**：状态词同源，操作就地给结果。
5. **可回退、不静默**：失败/关闭都有明确落点与恢复原样。

---

## 7 需要你拍板的点

1. **团队入口**：A 顶栏胶囊为主 + 右栏详情（推荐）｜ B 只留右栏 Tab，顶栏不放。
2. **面板结构**：A 子分段 Tab：成员 / 任务 / 动态（推荐）｜ B 维持三卡竖排。
3. **任务图**：A 默认收起、有任务才出现（推荐）｜ B 常驻展示。
4. **成员页模型**：A 锁定只读（推荐）｜ B 允许切换。
5. **团队动态**：A 做一条统一动态时间线（推荐，作为团队核心视图）｜ B 暂不做。
6. **未读/通知**：A 本期做｜ B 下一期。

---

## 8 分期建议

| 期 | 内容 | 见效 |
|---|---|---|
| **P1 去重与身份** | 入口二选一、成员页锁身份（助手/权限/模型/标题）、面板去噪 | 立刻可感知 |
| **P2 面板重构** | 右栏团队改子分段、任务按需、团队动态 | 从“后台”变“小队指挥台” |
| **P3 实时与提醒** | 事件订阅、未读/待办徽标、边界态 | 专业度 |

## 9 UX 验收

1. 新用户不看文档，10 秒内能答：有没有开团队、几个成员、谁在跑。
2. 想给某个成员补一句话，≤2 次点击到达输入框。
3. 任何时刻能一键回主会话，且不丢当前浏览。
4. 关闭团队后，界面逐字恢复原样。
