# 问数能力立项方案（自然语言问业务数据 / Text2SQL）

> **一句话主张**：把「知识库能问文档」补齐为「数据集能问业务数据」——在**人工圈定的数据集 + 语义层**之上做受控 Text2SQL，只读、行级可控、结果带图表、全程留痕；不做「把库丢给大模型随便写 SQL」的裸奔版。
>
> - 日期：2026-11-21
> - 状态：**方案待拍板**（§11 八项）；§3 技术选型已按推荐默认给出
> - 范围：数据源接入 → 数据集/指标语义 → 问数工具（智能体能力）→ 结果可视化 → 审计计量；工作流节点、开放 API、MCP 暴露放在刀二/刀三
> - 原则：能复用的底座一律复用（加密/租户/计量/调度/通知/图表），不新造平行体系；安全默认 fail-closed，不做「先跑通再说」的裸奔版

## 0 结论先行

| 项 | 结论 |
|---|---|
| **产品定位** | 知识库是「第二大脑」，问数是「业务眼睛」：问文档→问数→出图表/报表，是智能体工作台从「会答」走向「会分析」的关键一跳 |
| **技术路线** | **语义层 + 受控 Text2SQL**（方案 B），不引入 Vanna/DB-GPT 一类重型开源 NL2SQL 平台，不微调专用模型 |
| **SQL 校验** | 复用已在依赖里的 **JSqlParser** 做 AST 白名单（仅 SELECT/WITH）、禁 DML/DDL/多语句/文件读写、强制补 LIMIT；再用**只读账号 + 只读会话 + 超时 + 限行**兜底 |
| **执行底座** | 每个数据源一个独立 **HikariDataSource**（与主库隔离），`allowMultiQueries=false`、`readOnly=true`、statement/socket 双超时 |
| **凭据** | 复用 **ConfigCryptoService**（JWE）加密落库、出参脱敏、明文只在建连瞬间使用 |
| **模型** | **不新增模型类型**：复用聊天模型（temperature=0/关思考/短输出），数据集可绑定「问数模型」覆盖（留空跟随默认）；辅助调用照 [FollowUpQueryRewriter](src/main/java/com/wenqu/ai/service/FollowUpQueryRewriter.java) 的硬超时+降级+计量范式 |
| **可视化** | 一期复用正文里现成的 **echarts 代码块原位渲染**（零新前端组件）；二期做专用「数据卡」 |
| **权限** | 数据源/数据集沿用知识库的可见性机制（个人/指定部门/指定用户/全局）+ 租户行级；行级/列级过滤在刀二用 **AST 表虚拟化** 落地 |
| **默认开关** | 平台开关 `dataQa.enabled` **默认关**（数据比联网更敏感，口径同 `webSearch.enabled`/`tool.sandbox.enabled`） |

## 1 目标与非目标

### 1.1 目标

1. **管理员/数据 owner 能登记数据源**（一期 MySQL）：主机、库、只读账号（JWE 加密）、方言、可见范围、连通性探测。
2. **数据集（Dataset）= 授权的表/视图 + 字段语义 + 指标口径 + 同义词 + 行过滤**，是问数的唯一合法作用域；模型只能看到、只能查数据集里圈定的对象。
3. **问数工具**：用户用自然语言提问，模型在数据集语义范围内生成 SQL → 校验 → 执行 → 返回「表格 + 结论 + 图表建议」，并附带可展开的 SQL 供人核对口径。
4. **安全 fail-closed**：任何越界（非 SELECT、多语句、非圈定表、文件函数、超时、超行、行级越权）一律拒绝并显式告知，不静默降级成"查了个大概"。
5. **可运营**：每次问数落 `c_ai_data_query_log`（问题/SQL/命中行数/耗时/成败）；模型调用走现有用量台账（`kind=data_qa`）；接入现有配额与限流。
6. **可扩展**：同一套能力以「工具族」暴露给智能体，后续同一实现可挂为工作流节点、开放 v1 API、MCP 工具。

### 1.2 非目标（明确不做）

- **不做**通用 BI 平台（拖拽建模、看板编排、自助取数）；报告系统是另一条产品线（`dynamic-form`），本案不碰。
- **不做**让用户直接手写/执行任意 SQL（一期）：只允许「自然语言 → 受控 SQL」与「管理员调试预览」。
- **不做**写操作（INSERT/UPDATE/DELETE/DDL）；问数恒只读。
- **不做**跨数据源联邦查询/数据同步入湖（二期视需求另立）。
- **不做**问数专用微调模型（成本高、中文业务术语泛化差、私有化交付重）。

## 3 技术选型（本方案核心）

### 3.1 总体原则

1. **口径优先于聪明**：先让「指标/字段/口径」由人定义清楚（语义层），再让模型写 SQL；没有语义层的裸 Text2SQL 在企业里答得快、错得也快。
2. **受控而不是放任**：模型生成的每一条 SQL 都当作不可信输入，过 AST 白名单 + 只读账号 + 超时/限行三道闸。
3. **少依赖、可私有化**：不引入需要 GPU、需要外网、需要额外服务的 NL2SQL 平台；全部跑在问渠进程内。
4. **结果即不可信数据**：查询结果集里的文本可能藏注入指令，返回给模型时一律套 `UntrustedContent` 信封（复用现有工具输出信封机制）。

### 3.2 NL2SQL 路线对比

| 方案 | 代表 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 纯 Prompt Text2SQL（自研，schema 全塞） | — | 零新依赖、私有化、可控 | 大 schema 泛化差、字段幻觉多 | 作**降级路径**（小数据集可直出） |
| B **语义层 + 受控 Prompt**（自研） | — | 口径统一、准确率高、可审计、可治理 | 需人工维护数据集语义 | ✅ **主力路线** |
| C 开源 NL2SQL 平台集成 | Vanna / WrenAI / DB-GPT / SuperSonic(Chat2DB) | 开箱 UI、检索式训练 | 私有化重依赖、二次开发成本、供应链与合规风险、版本耦合 | ❌ 不引入（可借鉴其「schema 向量召回」思路） |
| D 专用微调模型 | sqlcoder / nsql 系 | 离线可控、单点强 | 训练/标注成本、中文业务术语泛化弱、交付重 | ❌ 不做 |
| E Agentic 多步（生成→执行→读错→再生成） | 自研编排 | 成功率最高 | 时延与 token 翻倍 | 一期做**1 次纠错重试**，二期再评估多步 |

> 选型结论：**B 为主 + A 降级 + E 的单次纠错**。C/D 在方案里明确不引入，避免「为了问数背一个重型平台」。

### 3.3 SQL 生成（模型侧）

- **模型**：复用平台聊天模型；`OpenAiChatOptions` 固定 `temperature=0.0`、`reasoningOffBody`（能关思考就关，避免预算花在推理上正文空，同 `FollowUpQueryRewriter` 的坑）、`maxTokens≈1024`。
- **问数模型可覆盖**：数据集可选「问数模型引用」（`model_ref`，留空跟随平台默认聊天模型），与知识库「库级稀疏覆盖」同构；不新增 `ModelRegistryService.TYPES` 类型。
- **Prompt 契约**（严格 JSON，便于解析与降级）：

```json
{
  "sql": "SELECT ... （单条 SELECT，不含分号）",
  "explain": "用一句话说明口径：查了什么、按什么聚合、时间范围",
  "chart": {"type": "bar|line|pie|table", "x": "列名", "y": ["度量列"], "series": "可选分系列列"},
  "assumptions": ["口径假设，如『销售额=订单金额-退款』"]
}
```

- **上下文装配**：只喂该数据集圈定的表/字段（中文名+类型+示例值）、指标定义（名称/口径 SQL 片段/同义词）、当前日期、方言、行过滤说明。表数量可控时全量注入（一期）；大库走 §3.6 schema 召回（二期）。
- **解析健壮性**：先按 JSON 解析；失败则回退「抓 ```sql 代码块」；再无则判失败并让模型重试一次。
- **元数据边界**：模型提示中只出现中文语义名与授权字段，不暴露未圈定表名，降低越界与幻觉。

### 3.4 SQL 校验（JSqlParser AST 白名单）

对每条生成 SQL，**先解析再执行**，以下任一不满足即拒绝（fail-closed）：

| 检查 | 规则 |
|---|---|
| 语句数量 | `parseStatements` 结果必须**恰好 1 条**，禁多语句/分号拼接 |
| 语句类型 | 只允许 `Select`（含 `WITH ... SELECT`）；其余 DML/DDL/DCL/事务/`SET`/`CALL`/`USE`/`LOCK` 全拒 |
| 表范围 | 所有引用表必须 ∈ 数据集 `allowed_tables`（含子查询、CTE、JOIN）；未授权表/系统库（`mysql.*`、`information_schema` 仅允许建模时内省用）拒绝 |
| 危险函数 | 拒 `LOAD_FILE` / `INTO OUTFILE` / `INTO DUMPFILE` / `SLEEP` / `BENCHMARK` 等 |
| 行数上限 | 无 `LIMIT` 或 `LIMIT` 超过 `dataset.max_rows` 时，AST 改写补/钳到上限 |
| 权限滤波 | 刀二：按数据集 `row_filter` 做 **AST 表虚拟化**（把每张表替换为 `(SELECT * FROM t WHERE <filter>) t`），防止模型绕过 WHERE |

> 解析器：`net.sf.jsqlparser`（已在 classpath）。校验器抽成**纯函数** `SqlGuard.validate(ast, dataset) → {ok, sql, rejectReason}`，便于单测（对齐 `RetrievalGate` 的收口思路）。

### 3.5 执行与连接（只读、隔离、有界）

- **连接池**：每个数据源一个懒创建的 `HikariDataSource`（`maximumPoolSize` 小、`connectionTimeout` 短），与主库 Hikari **完全隔离**；数据源删除/改配即关闭重建。
- **连接参数强制**：`readOnly=true`、**`allowMultiQueries=false`**、`useSSL` 按配置、`socketTimeout` 与 `queryTimeout` 双超时；执行前 `Connection.setReadOnly(true)`。
- **账号要求**：**必须只读账号**（连接探测时校验：只能 SELECT，且无写权限优先校验失败即拒用）；生产建议指向只读从库。
- **结果有界**：`Statement.setMaxRows(dataset.max_rows)`、`setQueryTimeout(dataset.timeout_ms)`、结果字节上限（如 5MB），超限截断并标 `truncated=true`。
- **方言**：一期 MySQL（`mysql-connector-j` 已在依赖）；刀二按需引入 PostgreSQL/ClickHouse JDBC 驱动（新增依赖，方言走 `dialect` 字段）。
- **试运行**：可选先 `EXPLAIN` 干跑（部分方言/复杂 SQL 不支持则跳过），用于捕获语法/权限错再喂回模型纠正。

### 3.6 Schema 召回（大库，二期）

- 一期：数据集人工圈定表，语义直接全量进 prompt。
- 二期：复用**现有向量模型 + Redis 向量索引**（与知识库同一套基础设施），把「表名/字段名/字段中文名/示例值/指标描述」建成索引，按问题召回 Top-N 表/字段再拼 prompt；不引入新向量库。

### 3.7 可视化

- 一期：工具返回结构化结果 + `chart` 建议；由模型在正文输出 **echarts 代码块**，复用 [AnswerBody](web/src/components/AnswerBody.vue) 已有的 echarts 原位渲染（零新前端组件）。
- 二期：专用「数据卡」组件（表格 + 图表 + SQL 折叠 + 下载 CSV），更接近 BI 呈现。

### 3.8 依赖清单

| 类别 | 新增 | 复用 |
|---|---|---|
| 依赖 | 无（一期）；刀二加 PG/ClickHouse JDBC 驱动 | JSqlParser（已在）、Hikari（已在）、mysql-connector-j（已在） |
| 安全 | — | ConfigCryptoService（JWE）、UntrustedContent 信封、SsrfGuard（若需主机白名单） |
| 权限/租户 | — | 资源可见性（同知识库）、WenquTenantLineHandler 行级 |
| 计算/计量 | `UsageAttr kind=data_qa` | MeteredModel/UsageLedgerService、RateLimitService、配额 |
| 调度/通知 | 数据刷新/报表订阅 | ScheduleCenter、Notification、MailDispatchService |
| 前端 | 数据源页、数据集设计器、数据卡（二期） | echarts、antd、现有设置/表单组件 |

## 4 核心设计

### 4.1 三类对象

```
数据源 DataSource ──1:N── 数据集 Dataset ──包含── 表/字段语义 + 指标 Metrics + 同义词 + 行过滤
                                   │
                                   └── 被智能体（能力开关）/ 工作流节点 / 开放 API 引用
```

- **为什么有「数据集」这一层而不是直接连库**：它是**授权的边界**（哪些表可查）、**语义的载体**（字段中文名、指标口径）、**权限的抓手**（行级/列级）、**复用的单位**（一个数据集可被多个智能体引用）。这正是「受控」与「裸奔」的分水岭。
- **指标（Metric）**：名称 + 口径（SQL 片段或表达式，如 `SUM(order_amount) - SUM(refund_amount)`）+ 同义词 + 单位 + 默认聚合粒度。指标是**单一真源**，模型不再每次自己"估"口径。

### 4.2 问数链路（一次调用的完整步骤）

```
用户提问
  │（智能体已挂 DATA_QA 工具、并选定/允许的数据集）
  ▼
① 解析意图 + 选数据集（多数据集时先 list/describe，或按智能体绑定收敛）
② 装配上下文：圈定表字段语义 + 指标 + 同义词 + 当前日期 + 方言 + 行过滤规则
③ 模型生成 {sql, explain, chart, assumptions}（temperature=0，硬超时）
④ SqlGuard：AST 白名单校验 + 补/钳 LIMIT +（刀二）行过滤虚拟化
⑤ EXPLAIN 干跑（可选）→ 报错则把错误回喂模型**纠错重试 ≤1 次**
⑥ 只读执行（超时 + maxRows + 字节上限）
⑦ 结果套 UntrustedContent 信封，回给模型：columns/rows/row_count/truncated/sql/chart/explain
⑧ 模型据此作答 + 出图表；落 c_ai_data_query_log；模型 token 落用量台账
```

失败分层文案（不静默）：
- 无可见数据集 → 「尚未配置可问数的数据集，请联系管理员」；
- 校验拒绝 → 「该问题需要访问未授权的数据，已拒绝」；
- 执行超时/超行 → 「查询超出资源上限，已缩小范围/请换个问法」；
- 模型没生成合法 SQL → 重试一次后「没能理解这个问题，请补充口径（如时间范围、指标）」。

### 4.3 行级/列级权限（刀二，AST 表虚拟化）

- 数据集配置 `row_filters`：按租户/部门/角色给谓词模板，如 `{"byDept": "dept_id = ${deptId}"}`，`${uid}/${deptId}/${tenantId}` 由 `TenantContext` + 当前用户解析。
- 执行前用 JSqlParser 把 SQL 里每张受控表 `t` 改写为 `(SELECT * FROM t WHERE <filter>) t`——**在表层收紧**，模型无论怎么写 WHERE/JOIN 都绕不过；这是比"在外层加 WHERE"更可靠的安全屏障。
- 列级脱敏（刀三）：数据集标 `sensitive_fields`，结果集按角色掩码（如手机号 `138****0000`）。

### 4.4 与知识库/智能体协同

- **术语联动**：数据集的指标/字段中文名可作为「术语解释」进知识库或作为检索同义词，用户问「上个月 GMV」时问数用指标口径、知识库答定义，二者互补。
- **智能体能力开关**：智能体「能力开关 → 数据问数」三态（跟随系统/开/关/指定数据集），与知识库范围同构；未指定时用「全部可见数据集」或「不使用」。
- **兜底**：问数失败（无数据/口径不清）时可提示改用知识库检索（若智能体同时挂了 KNOWLEDGE）。

## 5 数据模型（V34 迁移）

> 三张表带 `tenant_id`，**不进** `GLOBAL_TABLES`，由租户行级过滤自动兜住（同 `c_ai_tenant_invite`）。

```sql
-- 数据源：一条连接 + 凭据（JWE 密文），归属人可见 + 共享范围
CREATE TABLE IF NOT EXISTS `c_ai_data_source` (
    `tenant_id`     VARCHAR(32)  NOT NULL DEFAULT 'default' COMMENT '租户ID',
    `id`            VARCHAR(64)  NOT NULL COMMENT '主键（ds- 前缀）',
    `uid`           VARCHAR(64)  NOT NULL COMMENT '归属用户（c_ai_user.uid）',

## 6 接入形态

1. **工具族 `DATA_QA`（一期，主入口）**：新增 `ToolFamily.DATA_QA("data_qa","数据问数")` + `DataQaToolProvider implements ToolFamilyProvider`；工具（`SideEffect.READ`，只读档可用，游客默认不可见）：

| 工具名 | 说明 |
|---|---|
| `data_list_datasets` | 列出当前用户可见数据集（名称+说明+可问范围摘要） |
| `data_describe_dataset` | 返回某数据集的表/字段/指标/同义词语义（供模型精确提问） |
| `data_query` | 主工具：`{datasetId, question}` → 生成→校验→执行→返回 `{sql, columns, rows, row_count, truncated, chart, explain}` |

- 平台开关 `dataQa.enabled` 默认关；智能体「数据问数」三态；`ToolDescriptor.requiresApproval=false`（只读），`guestAllowed=false`（数据敏感，二期按分享显式开放）。

2. **工作流节点 `数据问数`（刀二，第 14 类节点）**：输入数据集 + 问题（变量可插值），输出结果集/图表到下游节点；复用同一 `DataQueryService`。

3. **开放 API `POST /api/ai/v1/data/{datasetId}/query`（刀三）**：走 `@OpenApi` + scope `data.read`，OpenAI SDK/MCP 均可对接。

4. **市场官方模板（刀三）**：内置「数据分析助手」应用模板（挂 DATA_QA + 可视化），管理员可分享数据集模板。

## 7 端点清单（管理面）

| 端点 | 权限 | 说明 |
|---|---|---|
| `GET/POST/PUT/DELETE /api/ai/data/sources` | 数据管理员/owner | 数据源 CRUD（密码入参只写、出参掩码） |
| `POST /api/ai/data/sources/{id}/probe` | 同上 | 连通性探测 + 只读账号校验 |

## 8 计量 / 配额 / 审计

- **模型 token**：每次生成/纠错调用照 `UsageAttr.of(uid, sessionId, null, "data_qa")` 计量，走 `UsageLedgerService` 既有台账，用途分项里单列「数据问数」。
- **数据库资源**：按用户限流（复用 `RateLimitService`）——问数次/分钟、并发查询数；单查询超时/限行/结果字节上限三闸。
- **配额**：纳入现有推理配额体系（问数 token 计入用户配额）；数据库查询次数如需要可按租户配。
- **审计**：`c_ai_data_query_log` 记全部问数；数据源 CRUD 进统一审计链；错误码统一（`E_SQL_REJECTED/ E_TABLE_FORBIDDEN / E_TIMEOUT / E_TOO_MANY_ROWS / E_NO_DATASET`）。

## 9 分期与验收

### 刀一 · MVP 闭环（约 2–3 周，可本地/单库验证）

范围：MySQL 数据源 + 数据集（选表/字段中文名/指标/同义词）+ `DATA_QA` 工具族 + JSqlParser 校验 + 只读账号 + 超时/限行 + echarts 结果 + 查询日志 + 可见性（沿用知识库共享）+ 平台开关 + 计量。

**验收**：
- [ ] 真实业务只读库上跑通 20 条自然语言问题，执行成功率达标（初设 ≥80%，逐条看口径正确性）；
- [ ] 安全用例全 fail-closed：DML/DDL、多语句、非授权表、`LOAD_FILE`/`INTO OUTFILE`、超时、超行、无 LIMIT 被钳制——每条都有单测/脚本证据；
- [ ] 密码入库为 JWE 密文、接口出参掩码、明文不外泄；
- [ ] 模型 token 落台账 `kind=data_qa`；查询日志可查问题/SQL/行数/耗时；
- [ ] 平台开关默认关，未开时工具不挂、提示去开启；无数据集时明确引导。

### 刀二 · 质量与治理（约 2–3 周）

范围：schema 向量召回（大库）、错误纠错重试、SQL 预览+人工改写（管理员）、**AST 行级/列级权限**、PostgreSQL/ClickHouse、工作流节点、定时报表订阅（复用 ScheduleCenter+邮件）、结果语义缓存、NL2SQL 评估集（准确率基线）。

**验收**：行级过滤在有/无权限用户下结果正确且不可绕过；多方言连通；工作流节点真机跑通；评估集给出准确率与回归基线。

### 刀三 · 协同与开放（约 2–3 周）

范围：v1 数据 API + MCP 暴露、数据集市场模板、多轮追问上下文、业务术语与知识库联动、成本与准确率看板、列级脱敏。

**验收**：API Key 调通、MCP 客户端可问数、市场模板安装即用、看板可看每数据集准确率与费用。

## 10 风险与回滚

| 风险 | 缓解 |
|---|---|
| 模型幻觉字段/错 SQL | 语义层圈定 + AST 白名单 + EXPLAIN 干跑 + 1 次纠错 + SQL 可见可核对 |
| 越权读数据 | 只读账号 + 数据集可见性 + 租户行级 + 刀二 AST 表虚拟化行过滤 |
| 大表拖垮业务库 | 强制 LIMIT + queryTimeout + socketTimeout + 独立小连接池 + 建议只读从库 |
| 凭据泄露 | JWE 加密 + 出参掩码 + 明文仅建连瞬间 + 不进日志 |
| 提示词注入（结果集/样例值里藏指令） | 结果与字段样例统一套 `UntrustedContent` 信封，按数据不按指令处理 |
| 跨租户串数 | 三表带 `tenant_id` 走行级过滤；连接按数据源归属校验 |
| 供应链/私有化 | 不引入外部 NL2SQL 平台；仅用已在 classpath 的 JSqlParser + Hikari；新驱动按需且可离线 |

**回滚**：能力整体受 `dataQa.enabled` 平台开关控制，默认关即完全不影响存量；V34 迁移只新增表/不动存量表，回滚只需关开关（表可保留不删）。数据源删除即关闭其连接池。

## 12 与既有方案的关系

- **知识库**：问数是知识库之后的第二类数据资产；共享可见性、向量召回（刀二）、术语解释与知识库互补，不替代文档 RAG。
- **智能体工具族**：作为新 `ToolFamily.DATA_QA` 接入既有 `ToolFamilyProvider` 收口，不散写问答侧 if 链；三态开关与知识库范围同构。
- **工作流**：刀二新增 `数据问数` 节点（第 14 类），复用同一 `DataQueryService`。
- **开放能力**：刀三通过 `@OpenApi` 接 v1 + MCP，与 OpenAI 兼容端点、API Key scope、SDK 一致。
- **企业级升级**：[企业级升级与建设方案.md](design/plans/企业级升级与建设方案.md) 的运行态外置/多副本是前提债——问数连接池与查询属**有状态资源**，多副本时按数据源在各副本独立建池即可，无需共享；但配额/限流跨副本一致性依赖该方案 Phase 0 的 Redis 化。
- **报表系统**：`dynamic-form` 报表后台是另一产品线，本案不接；如需「问数结果直接生成报表页」，刀三再评估对接。
