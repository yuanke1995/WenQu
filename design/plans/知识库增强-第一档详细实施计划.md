## 2. S1-1 复杂问句分解

### 2.1 目标与非目标

**目标**：模型单轮只发一次 `search_knowledge`、但 query 覆盖多个问题时，在工具内部拆成多路召回，提升复合问句的召回覆盖。

**非目标**（写死边界，验收时逐条核）：
- 不改 `HybridRetrievalService.search` / `searchMulti` 本身——工作流节点、`/api/ai/v1/retrieval`、`KbInsightsService`、评估服务等共用方零变化。
- 不改用户消息、不改引擎 prompt、不改工具清单/plan/trace、不改工具返回形状（仍是 String，引用编号仍由注册器统一分配）。
- 模型不调 `search_knowledge` 的轮次（闲聊、写作、编码、联网搜索）零触发。

### 2.2 前置真机检查（D1 上午，先做再写码）

**判据**：按轮统计 `toolCalls` 中 `name=search_knowledge` 的条数，或 `searchQueries` 大小。数据落在 `AgentxTurnRecording.java:282`（每次 `tool/requested` 记一条 query）、`Message.java:66`、`TraceService.java:163-177`。代码事实：单轮多次调用**已存在且允许**（`WenquSourcePool.java:118` 注明"模型一次可发多个 search_knowledge"，`ChatRunRuntime.java:128` 有同轮 4 路实例），`AgentxRepeatGuard` 只拦连续第 3 次同参调用，不同 query 不拦。

**执行**：取近 20 轮真实日志，数"单轮一次检索且 query 含多问标记"的占比。
- **占比 ≥ 门槛（建议 20%）** → 走实施路径。
- **占比不足** → 降级：只补 `subQueries` 诊断字段（1d），不实施分解。理由：模型已自行逐问检索，分解冗余。

## 5. S2-1 表格知识结构化

### 5.1 代码事实

- `ExcelParser.java:65-107`：xlsx 逐 sheet 把单元格用 `" | "` 拼成行、行间 `\n`，`buf.length()+line.length()>maxSize` 切块；块标题 `sheet名（前N行）` **只是命名，不是只取前 N 行**。表头无特殊处理、无行号、无每块表头重复。
- CSV 走 `TextParser.parseCsv:115-137`：首行作 `表头: ...`，切块时重复表头——**这个模式可直接复用到 xlsx**。
- 存储无通用 metadata JSON：`Knowledge.java:28-53` 只有 title/content/images/chunkIndex/titlePath/contentHash；向量侧临时 Map 在 `DocumentParsePipeline.java:199-213`，Redis 可能丢、以 MySQL 兜底（`HybridRetrievalService.java:1260-1281`）。
- 引用定位到**块级**，无 sheet/行/列坐标（`TurnSourceRegistry.java:281-302`）。

### 5.2 改动清单

1. **`ExcelParser.java:65-107` 改行级块**：
   - 表头随行冗余（复用 `TextParser.parseCsv` 模式）。
   - 每块携带 `sheet / 行号 / 列名` 坐标——**承载在 `titlePath`**（零 schema 改动、前端引用已支持展示章节路径），不要为此新增 metadata 字段。
   - 数值列加「列名: 值」文本模板，使逐行值可被词面命中。
   - 切块按**行边界**切，不把一行劈成两半。
2. **`DocumentParsePipeline.java:119-127`**：`maxChunks` 全局截断对大表的影响——当前大表被前 N 块截断，需为大表调整策略（如提高表格类上限或按 sheet 分片），验收要检查块数分布。
3. **引用定位**：`titlePath` 带行号后引用面板自动显示「sheet / 第 N 行」，前端无需大改。
4. **contentHash 口径变化** → 存量表格必须重解析才生效（衔接 S2-2），帮助中心写明。

### 5.3 能力边界（如实设定验收，避免对不上）

「第几行某列」可答；「数值聚合」只能做到**数值列文本化 + 行级召回**，模型仍靠自己算，**不是真 SQL 聚合**——没有单元格类型与聚合算子入口。排期里"数值聚合"的验收措辞建议改为「数值列可被逐行召回且模型能据以计算，抽样核对正确率」。

### 5.4 验收

- [ ] 100+ 行 Excel 可问「第 N 行某列」并命中正确块。
- [ ] 引用定位到行（`titlePath` 显示 sheet / 行号）。
- [ ] 大表不再被前 N 行截断：检查块数分布与末行可达性。
- [ ] 数值列抽样问「X 列的值」，逐行召回正确率达标。
- [ ] 非表格文档（docx/pdf/txt）解析结果零变化。

2. **进度**：复用 `/document/queue/stats`，前端加「表格重解析」进度与失败清单，不新建任务表。
3. **CSV 说明**：csv 走 TextParser、表头冗余本就有，重解析改善有限；帮助中心写明"表格结构化收益主要针对 xlsx"。
