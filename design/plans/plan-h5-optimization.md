# 问渠 H5 整体优化方案

> 状态：效果图待确认（2026-11-09 立项，同日出效果图）
> 范围：`/m/chat` 移动壳 + `mobileShell` 下可用的窄屏页面（`/profile`、`/help`、`/artifacts`、`/knowledge`、`/project`）
> 边界：PC 端行为不变；以 `preferMobileShell()` / `/m/` 为界，改哪端只影响哪端

## 1. 结论

H5 的 M0~P6 已完成（`web/src/h5/README.md`），功能面基本齐，本轮**不是重做**，而是四条线收口：

1. **减重**：H5 首访要下约 550KB gzip（其中 antd 344KB），且是阻塞依赖；
2. **补手感**：输入草稿、图片缩放、拍照入口、PWA 更新提示四个高频缺口；
3. **补覆盖**：顶栏信息密度、横屏形态、状态来源信息层级、白名单页面窄屏复核；
4. **立回归**：设备矩阵 + 性能预算进构建校验，防止后续改动把 H5 改烂。

UI 类改动（第 2 批）按既有规矩：**先出效果图，确认后再动代码**。

## 3. 问题清单

### P0 —— 真实痛点，低风险，可独立回滚

| 编号 | 问题 | 现状证据 | 影响 | 方案 |
|---|---|---|---|---|
| H5-01 | 输入框草稿不持久 | `h5/` 无草稿存储；引擎只恢复「插话队列」里未发出的 deferred 草稿 | 刷新/切后台/系统回收页面后，打了一半的字全丢，手机上最高频 | 按 `wq_draft:<uid>:<sid>` 存纯文本，300ms 防抖；发送成功/手动清空/删除会话/退出登录时删除；切会话先 flush 再载入；**不存附件与图片**（体积与隐私） |
| H5-02 | 图片查看不能缩放、不能滑动 | `.m-lightbox-img` 只有 `max-width/max-height`，无 transform 与手势；切图靠左右按钮 | 截图、表格、长图在手机上看不清；多图只能点小按钮 | Pointer Events 实现双指缩放 1–4x、双击 1x↔2x、放大态单指拖动、1x 态左右滑切换（阈值 60px）、下滑关闭；继续走既有 sheetStack 返回键结算（Z 1300） |
| H5-03 | 不能直接拍照 | `MobileAttachSheet.vue` 只有「选择图片」`accept=image/...`，无 `capture` | 拍白板、拍文档是最常见输入方式，现在要先退出到系统相机再选图 | 拆分「拍照」与「从相册选」两个入口，拍照 input 加 `capture="environment"`，复用既有 canvas 压缩通道；iOS 不支持时回退相册 |
| H5-04 | 首屏 550KB gz，antd 阻塞 | `main.js` 顶层 `import { message } from 'ant-design-vue'`，`manualChunks` 把全部 antd 打成一块并被入口预加载 | 4G 弱网首访白屏时间长；H5 主路径实际只用极少数 antd 能力 | 先用 bundle 分析确认入口静态依赖链（分析工具临时用，不入库）；再切断入口→antd 全量：全局提示改轻量实现或按需子路径导入，antd 依赖的 PC/管理页走动态 import；目标 H5 首屏只含 vue-vendor + entry + MobileChatPage chunk |
| H5-05 | 部署后老页面无更新提示 | `sw.js` `skipWaiting + clients.claim`；HTML 不缓存 | 用户长期停在旧版本，遇到已修 bug 复现 | 注册处监听 `updatefound` → `installed` 且已有 controller 时提示「新版本已就绪 · 刷新」；**不自动刷新**（避免打断生成中）；同一版本只提示一次 |

## 5. 关键实现要点与取舍

- **草稿只存文本**：附件是 base64/dataURL，存本地既撑爆 5MB 配额也有隐私风险；恢复时若与引擎既有 deferred 草稿重叠，以「输入框文本优先、队列条目不动」为规则，先证机制再写。
- **图片手势零依赖**：不引第三方手势库（首屏体积预算）；`touch-action: none` 只加在 lightbox 容器，页面其余滚动不受影响；返回键在放大态先复位再退出。
- **首屏减重先证明再动手**：不盲目改 `manualChunks`。先出依赖图，确认 `message` 是否拖入整包；再选择「轻量 toast / 子路径导入 / 动态 import」中最小的改动。
- **PWA 更新不自动 reload**：生成中的一轮不能被刷新打断；提示条只在移动壳与 PC 均可出现，文案不承诺时间。
- **横屏不改触屏热区口径**：40px 需拍板；若维持 44px，则通过收掉工具行与副文案腾高度。
- **状态 sheet 只改呈现**：锚点与折叠吃现有分段，不新增取数、不改动作，避免第二真相源。

## 6. 明确不做

- 第二个 `index.html` 入口（README 已拍板不做，antd 会打两份）。
- 消息列表虚拟化（实测 1235 节点、无 >50ms 长任务，不是瓶颈）。
- 管理页全量移动化（按需单页评估）。
- 引第三方 UI 框架/手势库/动画库。
- 改动 PC 端行为（含鼠标拖窄窗口）。
- 全仓机械替换硬编码字号。

## 8. 风险与回滚

| 风险 | 处置 |
|---|---|
| antd 拆分影响 PC 首屏 | 单独提交 + 双端体积对比；不达标整笔回滚 |
| 草稿涉及共享设备隐私 | 按用户 + 会话隔离、退出登录清空、不存附件；不提供跨设备同步 |
| 图片手势与 sheet 返回键冲突 | lightbox 自己登记一层；放大态返回键只复位，不退出；真机三端验 |
| 顶栏收敛改变肌肉记忆 | 效果图先定；上线后保留一版可回退实现 |
| 横屏压缩触屏热区 | 40px 需拍板；默认维持 44px，只收内容不缩热区 |
