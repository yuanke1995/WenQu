### 1.3 用户现在回答不了的五个问题

1. **今天还要跑什么？** 只能逐张卡看「下次」，没有跨任务的时间视图。
2. **最近稳不稳？** 只有「最后一次」状态，没有成功率和连续失败。
3. **为什么失败？** 要进执行历史模态再逐条找，错误原文直接截断，没有建议。
4. **会不会漏跑 / 撞车？** 「上一轮仍在执行就跳过」这条规则只在执行记录里体现，列表上看不到「运行中」。
5. **怎么快速建一条？** 必须理解 5 段 cron；没有模板，也没有「这样写下次是什么时候」的确认。

## 2. 设计目标与原则

1. **周期说人话**：默认看到「工作日 09:00（北京时间）」，原始 cron 退到编辑器的「高级」里；高级用户仍可切回 cron，双向同步。
2. **列表先给结论**：页头一行回答「共几个 / 启用几个 / 今日已跑待跑 / 近 7 天成功率 / 几个需关注」，每个数字可点击变成筛选。
3. **异步必须有活着的感觉**：运行中的任务 10 秒内出现在卡面，显示已运行时长与实时入口；跑完自动转成功/失败，不需要手动刷新。
4. **危险操作降权且可撤销**：日常操作只留「立即执行 / 执行历史 / 编辑」，删除收进 ⋯ 二级菜单；批量删除二次确认 + 8 秒撤销。
5. **创建从模板开始**：「知识库早报 / 周报汇总 / 数据核对 / 空白」四个入口；编辑器右侧实时预览「卡片长什么样 + 接下来 3 次」。
6. **不改底层语义**：个人资产、一人一任务隔离、5 段 cron、单实例 `runningJobs` 防重、归档联动都保持现状；本次只把已有能力露出来 + 补轻量读接口。

## 3. 信息架构与交互重构

### 3.1 列表页（场景 1）

**页头（56px）**

- 左：`共 6 个任务 · 启用 5 · 今日已跑 3 / 待跑 1 · 近 7 天成功率 90%`
- 需关注时追加一枚可点击的弱告警 chip：`1 个需关注`（点击 = 筛选到失败/连续失败任务）
- 说明文案：`到点自动执行，结果写进任务专属会话；停用或归档不会补跑`
- 右：`搜索`（名称/指令/智能体）、刷新图标、`新建任务`（主色）、`批量管理`

**筛选行（40px，列表上方）**

- 分段 chip：`全部 6` / `启用 5` / `停用 1` / `需关注 1` / `运行中 1`
- 右侧排序：`按下次运行` / `按最近执行` / `按创建时间`

**「接下来」时间条（42px）**

- 横向列出最近 3 次即将运行：`今天 14:30 竞品动态扫描（4 分钟后）` · `明天 09:00 知识库早报` · `周五 18:00 周报汇总`
- 目的是把「下次」从单卡信息提升为跨任务的时间感；没有启用任务时整条隐藏。

**卡片解剖（4 行）**

| 行 | 左侧 | 右侧 |
|---|---|---|
| 1 | 状态点 + 任务名（14px 中等）+ `运行中` / `需关注` / `已停用` 标签 + 智能体 chip + 工作区 chip | 启停开关 + `⋯` 菜单（复制任务 / 跳过下一次 / 删除） |
| 2 | 时钟图标 + **人话周期**「工作日 09:00」+ 时区弱文本 + 原始 cron（11px 等宽、text3，可关） | `下次 明天 09:00（15 小时后）`；停用时显示「已停用 · 启用后从下一个周期开始」 |
| 3 | 指令单行预览（超出省略，点击展开全文） | `智能体 问渠` · `模型 跟随个人` · `深度思考 关` |
| 4 | 上次运行结果（成功绿 / 失败红 / 跳过橙）+ 耗时 + `查看结果 →` + 最近 7 次小圆点 + `5/5` | `立即执行` / `执行历史` / `编辑` 三个 ghost 小钮 |

**五种卡片状态**

- **启用正常**：绿点，行 4 显示最近一次成功与健康点阵。
- **运行中**：蓝点呼吸 + `运行中 00:18` 标签；行 2 右侧改为「本轮 14:30 开始 · 已运行 18 秒」；`立即执行` 置灰为「执行中…」，另有「查看实时 →」跳到结果会话。
- **需关注**：红点 + `需关注` 标签；行 4 上方插入一行弱底提示：`上次失败：模型调用超时（3600 秒）· 已连续 2 次` + `查看原因` / `重试`。
- **已停用**：灰点、整卡降饱和度（不透明度 0.72）；开关关闭；`下次` 位置显示停用说明；`立即执行` 仍可用（手动执行不受停用影响）。
- **归档联动停用**：额外一枚 `工作区已归档` 灰标签，启用按钮 hover 提示「恢复工作区后才能启用」。

**空状态**

- 标题「还没有定时任务」+ 一句示例 + 四个模板卡（知识库早报 / 周报汇总 / 数据核对 / 自定义），点模板直接打开预填好的新建弹窗。

### 3.2 执行历史抽屉（场景 2）

从「执行历史」或整卡点击打开，右侧 560px 抽屉（不再用居中模态），不打断列表上下文。

- **抽屉头**：任务名 + 状态标签 + 启停开关；右上「编辑」。
- **概览三格**：近 7 天运行次数 / 成功率 / 平均耗时（数字等宽、右对齐）。
- **下次运行卡**：`下次 明天 09:00 · 15 小时后` + `跳过下一次`（P0 轻接口）+ `立即执行`。
- **页签**：`执行记录`（默认）/ `运行配置`（周期、智能体、模型、工作区、通知、重试；P1 字段落地后出现）。
- **记录列表**：按「今天 / 昨天 / 更早」分组；每行 `状态图标 + 时间 + 定时/手动 + 耗时 + 查看会话 → + 重跑`。
  - 运行中行置顶，显示 spinner 与实时已运行时长。
  - 失败行默认展开：一句人话原因 + 2 条排查建议 + 可复制的错误原文 + `重跑`；原始错误超过两行折叠。
  - 成功行显示回答摘录两行，`展开全文` 就地展开，不跳页。
  - 跳过行用橙色，说明原因（`上一轮仍在执行` / `工作区已归档` / `线程池繁忙`）。
- **底部**：`执行记录保留最近 100 条 / 90 天；完整回答在结果会话里`。

### 3.3 新建 / 编辑（场景 3）

760px 弹窗，左表单 + 右实时预览（240px）。新建时顶部先出现模板条，选中后预填名称/指令/周期，仍可全改。

**左栏**

1. **名称**：输入框 + 工作区选择（可空 = 不属于任何工作区；后端 `projectId` 已支持）。
2. **执行内容**：智能体选择（含「默认智能体」）+ 指令 textarea + `插入模板`。
3. **执行周期**：分段控件 `每天 / 每周 / 每月 / 间隔 / 高级`
   - 每天：时间 `09:00`
   - 每周：星期 chips（一~日）+ 时间
   - 每月：几号 + 时间
   - 间隔：每 N 小时/分钟 + 起始时间
   - 高级：cron 文本 + 常用写法提示（唯一出现 cron 的地方）
   - 时区：默认 `Asia/Shanghai（北京）`，可搜索全量时区，不再只有 4 个选项。
4. **人话总结**（主色弱底一行）：`每周一至周五 09:00 运行（北京时间）`
5. **运行设置（默认折叠，P1）**：模型、深度思考、失败重试（0/1/2 次，间隔 5 分钟）、单轮超时、通知（完成和失败 / 仅失败 / 不通知）。
6. **底部**：取消 / 保存 / 保存并启用；校验错误就地红字，不弹 toast。

**右栏**

- 「卡片预览」：按最终卡片样式渲染（4 行结构），所见即所得。
- 「接下来 3 次」：由后端 `preview` 接口按同一套 `CronExpression` 计算，列出具体日期与星期，避免前端自算与调度器口径不一致。
- 底部小字：`北京时间；保存后按实际触发时刻重新计算`.

### 3.4 批量管理（场景 4）

- 进入批量后，卡片左侧出现勾选框，页头切换为 `已选择 3 个任务` + `全选`；退出清空选择。
- 底部浮动操作条（居中、白底、阴影）：`已选 3 个` · `启用` · `停用` · `删除` · `取消`。
- 删除确认列出将删除的任务名与影响（不再触发；记录与会话保留），确认后 toast：`已删除 3 个任务 · 撤销`。
- 撤销走软删恢复接口：恢复后任务回到**停用**状态，由用户决定是否重新启用，避免误删后又自动开跑。

### 3.5 运行状态实时化

- 列表在存在 `running` 任务时每 10 秒轮询一次，全部空闲时 60 秒；页面隐藏（`visibilitychange`）暂停轮询，回前台立即刷一次。
- 「正在运行」由后端 `runningJobs` 透出，不靠前端猜；完成事件由下一轮轮询捕获（不引入 SSE，定时任务是后台链路，没有浏览器连接）。
- 「下次」倒计时用本地秒级刷新（1 分钟粒度），不额外请求。

## 4. 功能升级清单

### 4.1 P0（一期：纯 UI + 轻接口，不动表）

| 编号 | 能力 | 前端 | 后端 |
|---|---|---|---|
| F1 | 人话周期 + 接下来 3 次 | 周期构建器、总结句、预览 | `GET /api/ai/scheduled/preview?cron=&timezone=&count=3`（复用 `CronExpression`） |
| F2 | 列表总览与筛选 | 页头统计、筛选 chip、搜索、排序 | `GET /api/ai/scheduled/overview`；列表 DTO 补 `running`、`health{runs7d,failed7d,successRate7d,consecutiveFailures}`、`projectName` |
| F3 | 卡片重排与操作分级 | 4 行卡片、⋯ 二级菜单、复制任务（前端 create） | 无 |
| F4 | 执行历史抽屉 | 分组、筛选、展开全文、失败详情与建议、重跑 | 重跑复用 `POST /{id}/run`；详情复用 `GET /{id}/runs`（后端上限已是 100，前端按需传 limit） |
| F5 | 批量操作条 + 撤销删除 | 底部浮动条、选中计数、撤销 toast | `POST /api/ai/scheduled/{id}/restore`（`deleted=0`、`enabled=0`、`next_run_at=null`）。**必须按 id 直更**：`deleted` 是逻辑删除字段，`selectById` 查不到已删行，不能先查后改 |
| F6 | 跳过下一次 | 卡片 ⋯ 与抽屉按钮 | `POST /api/ai/scheduled/{id}/skip-next`（以 `max(now, next_run_at)` 为基准推进到再下一次；已到期时不先补跑） |
| F7 | 编辑器补全 | 全量时区、工作区绑定、校验就地提示 | 无（`projectId` 已支持） |
| F8 | 模板库 | 4 个静态模板 + 空状态入口 | 无 |
| F9 | 执行记录保留 | 抽屉底部说明 | 按 `scheduled.runRetentionDays`（默认 90 天）+ 每任务保留最近 100 条清理；沿用现有 cleanup 模式 |

**P0 权限**：`overview` / `preview` / `runs` 走 `scheduled:read`；`skip-next` 走 `scheduled:write`；`restore` 走 `scheduled:delete`。均先做 `mustOwn` 归属校验。

**P0 对 DTO 的增量**

```json
{
  "running": true,
  "projectName": "问渠",
  "health": { "runs7d": 5, "failed7d": 0, "successRate7d": 100, "consecutiveFailures": 0 }
}
```

`health` 由 `c_ai_scheduled_run` 按 `job_id + create_time >= now-7d` 聚合；一次 `GROUP BY` 查询，避免每张卡 N+1。**成功率口径**：分母只算有终态的运行（`succeeded + failed`），`skipped` 与 `running` 不计入；连续失败次数从最近一条往回数到第一个非失败终态为止。

### 4.2 P1（二期：任务级运行配置，需迁移）

| 编号 | 能力 | 表/字段 | 说明 |
|---|---|---|---|
| F10 | 通知偏好 | `notify_on VARCHAR(16) DEFAULT 'all'` | `all` / `failure` / `none`；`notifyRunOutcome` 按此过滤 |
| F11 | 失败重试 | `max_retries INT DEFAULT 0`、`retry_interval_sec INT DEFAULT 60` | 失败后在独立延迟任务里重跑；**同一任务串行**，重试轮在结果会话里标明「第 2 次尝试」 |

| F13 | 任务到期 | `end_at DATETIME NULL` | 到期后自动停用并落一条 skipped 记录，通知归属人 |
| F14 | 运行配置页签 | 无新表 | 抽屉第二个页签读写上述字段 |
| F15 | 从对话创建 | 无新表 | 会话菜单「设为定时任务」→ `/agents?tab=scheduled&fromSession=…` 预填指令与智能体 |
| F16 | 执行耗时入库 | `c_ai_scheduled_run.duration_ms INT` | 概览平均耗时 / 排序不再靠前端算 |

**P1 注意**：重试必须复用 `runningJobs` 防重；重试轮不重复发「完成」通知（只在最终终态发一次）；`end_at` 与归档联动同时生效时，以先到者为准。

### 4.3 P2（三期：可选）

| 编号 | 能力 | 说明 |
|---|---|---|
| F17 | 周视图 | 列表/周视图切换，按时间轴铺一周运行计划；任务少时价值有限，等任务量上来再做 |

- 不把 5 段 cron 改成 6 段或引入 Quartz。

## 7. 实施计划与验收

### 7.1 一次落地（2026-11-13 已完成）

| 模块 | 已实现 |
|---|---|
| 表结构 | `V6__scheduled_job_run_config.sql`：通知偏好、失败重试、重试间隔、单任务超时、到期时间、执行耗时、尝试次数；执行记录补 `create_time` 索引 |
| 后端接口 | `GET /overview`、`GET /preview`、`POST /{id}/skip-next`、`POST /{id}/restore`；列表 DTO 补 `running`、`health`、`projectName` 与新配置字段 |
| 运行语义 | 失败重试（同任务串行、延迟队列、只发终态通知）、到期自动停用并记 skipped、通知偏好过滤、单任务超时覆盖、执行记录保留清理 |
| 前端 | 列表总览/筛选/搜索/排序/「接下来」时间条、4 行卡片、运行中轮询、执行历史抽屉（分组/失败建议/重跑/展开全文/运行配置）、周期构建器 + 模板 + 下次 3 次预览、批量操作条、删除撤销 |
| 对话闭环 | 回答「更多」菜单新增「设为定时任务」，带本轮提问与智能体跳转并预填新建弹窗 |

P2 可选扩展（周视图、变量占位符、告警渠道、并发策略、任务依赖）保持方案里的「不做/单独立项」判断，本次未动。

### 7.2 验收标准

1. **不写 cron 能建任务**：每天 / 每周 / 每月 / 间隔四种周期都可完成创建，保存前能看到「接下来 3 次」。
2. **周期可逆**：高级 cron → 切回每周，控件能还原；保存后卡片显示与预览一致。
3. **运行可见**：手动触发后 10 秒内卡片出现「运行中 + 已运行时长」，结束后自动转成功/失败。
4. **失败可处理**：列表能筛出需关注任务，抽屉里一眼看到原因与建议，并能一键重跑。
5. **误删可恢复**：单删与批量删都能在 8 秒内撤销，恢复后为停用态。
6. **批量部分失败**：逐条列出失败任务名与原因，不静默吞。
7. **不回归**：归档联动停用、跨用户 403、停用不补跑、单任务串行等既有语义不变。
8. **窄屏**：1440×900 与 1280×800 下不出现横向滚动；页头统计在空间不足时优先隐藏说明文案。

### 7.3 风险与取舍

- **preview 与调度口径**：必须走后端同一套 `CronExpression`，前端不引 cron 库自算，避免「预览 09:00、实际 09:01」。
- **轮询成本**：只在有运行中任务时 10 秒轮询；列表规模是个人资产（默认上限 20），成本可控。
- **撤销删除**：`restore` 只恢复为停用态；若用户已用同名新建，不合并、不覆盖。
- **失败重试**：重试会向同一结果会话追加一轮，需在会话里标明「重试」，否则用户会误以为重复回答；这是重试语义最大的风险。
- **记录保留**：清理会删除旧执行记录，但结果会话保留；默认 90 天 + 每任务最近 100 条，需在抽屉底部明示。
