# 重排退役平台层、下放库级——方案与落地记录

日期：2026-11-14（当日拍板当日落地）

## 拍板结论

知识库级已可选重排模型（`query_params.rerank.model`，一轮按命中库收敛），平台层重排配置整体退役：

1. **平台「启用重排」开关退役**（`rerank.enabled` 全局层）：重排 = 命中库绑了重排模型才执行，选了就重排。
2. **三层默认模型链退役**：平台默认（`rerank.platformRef`）、个人默认（`rerank.model` personalOnly）、遗留 `rerank.baseUrl` 直连回落。重排模型唯一来源 = 库级绑定 → 供应商网关。
3. **`rerank.minHits` / `rerank.maxHits` 下放库级**：跟收敛出重排模型的那个库走；缺省回落 `ConfigDefaults` 常量（6/15）。
4. **智能体级保留「强制关」**：`rerank.enabled` 只认显式 `"false"`；`"true"`/缺省 = 跟随（存量 true 无迁移，读取视为跟随）。
5. 归属论定：**重排属于知识库**（检索侧模型归库：KB 必绑向量/重排/视觉），智能体只能强制关、不能开。

保留：隐藏键 `rerank.timeoutMillis` / `rerank.failCooldownMs`（冷却机制照旧）；rerank 模型类型本身；评测/探针的请求级重排开关（变「对比关」语义）。

## 关键机制变化

- **门控**：`RerankService.enabled()`（`getBoolean` 缺键返回 false，会把重排全杀）改为 `forcedOff()`——仅显式 `"false"` 生效。
- **路由**：`ModelRegistryService.rerankRoute()` 只认线程覆盖层的 `rerank.model`（库收敛写入）；无绑定返回 null = 不可用。
- **轮级收敛登记**：检索工具跑在独立线程，线程覆盖随调用结束撤除；咨询来源并入、MCP 来源评分凭 `TurnSourceRegistry.roundRerankModel`（`SourceRegistrar.registerRoundRerankModel` 回调登记）复用同一模型。
- **按路由隔离状态**：`RerankService` 原全局单 client/探测/冷却在「路由随轮收敛」后跨轮串线（A 轮的请求可能走 B 轮的网关），改 `ConcurrentHashMap<fingerprint, RouteState>`（指纹含超时），失败冷却按路由隔离。
- **窗口下发**：`KbRetrievalParamService.withRerankModel` 一次收敛「模型 + 该库 minHits/maxHits」三个线程覆盖，重排执行端 `getInt(key, ConfigDefaults.*)` 覆盖优先。
- **tips 断链修补**：`ConfigSchemaService.tipsByKey` 对不在设置页字段面的键回落 `editable`（keyDescriptions）同源说明——库级新键的问号文案不因键不在设置页而断。
