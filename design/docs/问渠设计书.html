执行摘要

Executive Summary

企业 AI 的瓶颈早已不在模型本身，而在最后一公里：知识是否可信、工具是否可用、权限是否收得住、过程是否可审计、结果是否能交付。

问渠把这条“最后一公里”做成产品：以对话为入口、以智能体为组织单位、以知识为事实源、以产物为交付物、以治理为底座。它不是又一个聊天框，而是一套可以放进企业内网、交给真实业务使用的智能体工作台。

判断一

长任务必须可控

计划模式与目标模式把“一句话交给 AI”拆成可确认、可插话、可暂停、可核验的过程，并用四项硬预算防止失控。

判断二

答案必须可溯源

知识库、联网搜索与外部工具共用一套引用编号，低置信结果显式标注而不是伪装成确定答案。

判断三

开放必须可治理

MCP 双向、OpenAI 兼容端点、工作流 API 与 Webhook 都能对外，但统一受租户、配额、审批与审计约束。

文档结构 第一部分从产品视角说明定位、角色、能力与体验原则；第二部分从工程视角说明分层、双引擎、检索管线、长任务、数据与安全；第三部分给出可直接用于汇报的整页架构图；第四部分为演进方向、术语与接口速查。
PART I

产品设计书

Product Design
1.1

定位与价值主张

问渠是一款以智能体为核心的 AI 工作台，面向私有化部署。它把大模型、知识库与工具统一组织与编排，覆盖“智能对话 → 知识检索 → 工具执行 → 产物交付 → 对外能力开放”的完整链路。

PRODUCT FORM

智能体优先

以智能体（人设 / 知识范围 / 工具集）为能力组织单位，而不是以单次问答为中心。

  • 会话级不锁定，随时切换
  • 按需委派给职责对口的助手
  • 可发布为分享页与 MCP 端点
WORK MODEL

长任务可控

计划卡只放目标与前三步，完整计划与版本轨进右侧抽屉；目标模式自动续跑并逐条核验证据。

  • 执行中可带意见调整
  • 插话让位后自动接续
  • 四项硬预算兜住边界
TRUST

答案可溯源

混合检索、引用溯源与位置级原图展示，让每个结论都能回到源头。

  • 知识 / 搜索 / 工具共用编号
  • 低分全灭保留最相关块并标注
  • 父子分块与 GraphRAG 扩展
ECOSYSTEM

开放互联

既能接入外部工具，也能把自己发布为别人可调用的能力。

  • MCP 双向：Client + Server
  • OpenAI 兼容 Chat / Responses
  • 工作流 API、Webhook、轮终回调
GOVERNANCE

生产就绪

多租户、企业身份、RBAC、配额、内容安全、审计链与巡检，构成可用可管的底座。

  • OIDC / SAML / SCIM / LDAP
  • 密钥加密与哈希签发
  • 哈希链审计与合规导出
DELIVERY

产物即交付

回答不止于文字：文件、网页、图表、数据集以交付卡聚合，可预览、下载与归档。

  • 交付包 ZIP 一键下载
  • 网页多视口预览
  • 产物页统一管理与移动
一句话定位 问渠不是“接入大模型的聊天页面”，而是把模型能力变成企业可管理、可审计、可复用的生产力资产的工作台。
1.2

角色与典型场景

产品围绕五类角色设计。每类角色只看到与自身职责相关的入口与数据，权限与租户边界在服务端强制生效。

角色核心关注典型场景产品回应
平台管理员 部署、租户、安全、成本 开通租户、接入企业身份、控制模型与工具开关、处理安全事件 多租户生命周期、认证源、RBAC、推理配额、内容安全、巡检与审计
知识运营 知识资产的质量与覆盖 导入文档、修正分块、处理无命中问题、评估检索效果 多格式解析、GraphRAG、知识块编辑、检索评估、缺口回流
业务用户 快速得到可信答案与可用交付物 问制度、查资料、写方案、做数据分析并导出结果 对话与引用、计划 / 目标模式、工具执行、产物交付卡
智能体开发者 搭建、调试、发布与迭代 配置人设与工具、编排工作流、跑评测、发布到市场 智能体配置与版本回滚、可视化工作流、评测门禁、市场分发
外部系统 低摩擦集成与稳定契约 把问答能力嵌进业务系统，或把外部工具接进问渠 OpenAI 兼容端点、MCP 双向、工作流 API / Webhook
1.3

能力全景

五个能力域共同构成产品主体。它们共享同一套身份、权限、计量与审计，而不是五个彼此割裂的模块。

01 · CONVERSATION

对话与长任务

  • 流式与续接：SSE 逐段下发，停止留痕，断线后可接回同一轮
  • 运行中插话：下一次模型调用前生效，未赶上则本轮结束补发
  • 引用溯源：句末角标回到知识块全文与关联截图
  • 深度思考：五档强度，思考与工具统一收进过程块
  • 上下文管理：容量圆环、用量去向、自动 / 手动压缩
  • 多模态：图片理解、文档正文抽取、粘贴与拖拽
  • 计划 / 目标模式：先规划后执行，或一句话自动续跑
  • 人在回路：工具审批、智能体提问、计划确认三类卡片
02 · KNOWLEDGE

知识与检索

  • 多格式解析：docx / pdf / xlsx / ppt / txt / md / csv，扫描件 OCR
  • 网页导入：批量 URL、正文提取、定时自动刷新
  • 混合检索：向量召回 + 中文分词词面，双路融合
  • 质量闸门：融合门与重排门；低分全灭保留 Top-1 并标注低置信
  • GraphRAG：三元组抽取与一跳图扩展，实体可溯源
  • 文档治理：版本回滚、增量重解析、回收站、跨库移动
  • 知识块：切片列表与结构导图，单块编辑即重向量化
  • 引擎可切换：默认零依赖，亦可切换中文分词关键词引擎
03 · AGENTS

智能体与工具

  • 可配置：人设、知识范围、能力开关、权限档位、记忆域
  • 按需委派：跨主题问题派给职责对口的助手，两种执行形态
  • 工具生态：MCP、OpenAPI 导入的 HTTP 工具、工作流工具、技能
  • 三级记忆：用户级 / 专属 / 叠加
  • 发布：免登录分享页、iframe 嵌入、MCP 端点
  • 治理：配置版本与回滚、工具审批、轮终回调、评测门禁
  • 调度：cron 或固定间隔执行，同任务串行防重叠
  • 市场：技能、应用模板、工作流在团队内分发，安装即复制
04 · WORKFLOW

工作流与开放能力

  • DSL 唯一真源：画布只是编辑器，引擎只按 DSL 执行
  • 13 类节点：模型、检索、HTTP、代码、条件、审核、循环、技能、MCP 等
  • 可视化编排：拖拽、右键菜单、连线校验、节点级 Trace 回放
  • 版本：草稿、发布快照、回滚，运行锁定当时 DSL
  • 触发：手动、定时、API、Webhook、知识事件、chatflow
  • 开放：OpenAI 兼容端点、工作流 API、终态回调
  • 游客放行：只读节点集可对分享页开放，其余一律拒绝
  • 治理：超时、图步数、并发、排队、保留期均可配
05 · GOVERNANCE

治理与运维

  • 多租户：开通、启停、归档恢复、邀请注册、首登引导
  • 企业身份：OIDC / SAML / SCIM / LDAP，组到角色映射
  • 权限：菜单与接口两级 RBAC，后端默认拒绝
  • 密钥：模型 Key、工具凭据、认证源密钥加密入库
  • 配额：平台 / 部门 / 成员三档，按日或按月
  • 内容安全：输入与输出双闸，拦截或告警
  • 审计：哈希链、合规导出、链校验
  • 运维：系统巡检、公告、会话治理、费用看板
06 · QUALITY

运营与质控闭环

  • 看板：问答量、无命中率、引用率、满意率
  • Trace：按对话或工作流筛选并回放执行过程
  • 采样池：差评必采，待标注样本回流评测集
  • 检索评估：多参数组异步实验，recall@k / MRR 对比
  • 智能体评测：套件、回归、基线、A/B 对比
  • 发布门禁：五态结论，保存前检查
  • 答案质量：忠实度与相关性评分
  • 费用：按用户与按模型的区间费用视图
1.4

核心用户旅程

所有能力最终收敛到一条主旅程：用户提出意图，系统理解并规划，检索与调用工具，完成推理与执行，交付可核验的结果，并沉淀为可复用的资产。

SCENARIO 01

可信问答

“这份制度里试用期是多久？”系统命中多个知识块，答案句末给出编号角标，点开即可看到原文与截图；若命中分偏低，会明确标注低置信。

SCENARIO 02

长任务交付

“把这三份报表合并并生成分析网页。”目标模式自动续跑，过程中需要审批时弹出卡片，完成后逐条核验产物与命令退出码。

SCENARIO 03

对外能力开放

把智能体发布为 MCP 端点，或通过 OpenAI 兼容接口接入业务系统；所有调用受 API Key、租户、配额与审计统一约束。

1.5

体验设计原则

面对“AI 给出的结果是否可信”这一根本问题，问渠用四条体验原则约束设计，而不是靠提示词或文案修饰。

PRINCIPLE 01

过程可见

思考、工具、产物分段呈现，完成后折叠为一行总览，展开是逐步骤执行清单。

PRINCIPLE 02

结果可核

引用编号统一，来源可回到原文；低置信、降级与未过滤都明确说出来。

PRINCIPLE 03

任务可控

长任务可暂停、继续、取消与插话；关键副作用执行前必须确认。

PRINCIPLE 04

权限可收

会话级权限档位、平台上限、工具黑名单与租户边界层层收口。

在信息层级上采用渐进披露：计划卡只放目标与前三步，完整计划进抽屉；技能先给清单，需要时才读正文；工具大输出整份留存，卡上只给摘要。用户先看到结论，再按需下钻。

1.6

终端形态与交付方式

同一套业务契约支撑多种终端与对外形态。界面可以不同，引用、审批、权限与审计的口径保持一致。

形态入口适合场景边界与约束
电脑端工作台/chat、/project/{id}日常问答、长任务、工作区文件处理完整功能；工作区文件由用户电脑上的执行器读写
移动端/m/chat触屏窄屏、随时随地提问与审批三张人在回路卡片与 PC 同契约；状态与来源收进 sheet
免登录分享页/s/{token}、/shared/{token}对外演示、客户试用、只读会话分享游客额度闸；只读工作流白名单；超限返回 429
嵌入式页面iframe把问答嵌进业务系统或门户分享级权限；不暴露管理能力
MCP 端点/ai/mcp/{token}、/ai/mcp接入 Claude Desktop、Cursor 等客户端令牌即凭据；平台入口需 API Key 且开启 MCP
OpenAI 兼容/api/ai/v1/chat/completions、/responses业务系统按标准协议接入真增量流式；只读工具映射；权限固定为问答链路
工作流 API/api/ai/v1/workflows/{id}/run把编排好的流程作为服务调用只跑已发布版本；含人工审核节点一律拒绝
Webhook 回调智能体轮终 / 工作流终态结果回写宿主系统HMAC 签名、持久重试、耗尽告警
1.7

产品边界

明确“不做什么”与“做什么”同样重要。以下边界是产品设计的一部分，不是临时限制。

NOT DOING

刻意不做

  • 不训练基座模型：专注模型之上的编排、知识与工具链路
  • 不做通用网盘：工作区文件留在用户电脑，服务端不存副本
  • 不提供租户物理删除：以下线与归档代替，避免误删整租户数据
  • 不承诺无人值守：高副作用动作保留确认与审批
  • 显式降级：可替换组件不可用时明确标注降级，关键能力不可用时直接失败，不伪装成正常结果
DOING

坚持做

  • 私有化优先：数据、索引、会话状态都可留在企业内网
  • 单一事实源：工作流 DSL、配置 schema、权限树都只有一份权威定义
  • 显式失败：配置缺失、工具不可用、检索无结果都给出可行动的说明
  • 可回滚：智能体配置、工作流版本、文档版本都保留历史
  • 可计量：每一轮 token、费用与工具调用都可追溯
PART II

技术架构设计书

Technical Architecture
2.1

目标与设计原则

架构围绕六个质量属性展开：可私有化、可扩展、可审计、可降级、可移植、可运维。原则不是口号，每一条都对应明确的实现约束。

原则含义落地约束
单一事实源同一语义只有一个权威定义工作流以 JSON DSL 为唯一真源；配置以 schema 为唯一来源；权限树菜单与接口同源
显式失败不可用就说不可用，不静默猜测关键密钥缺失启动失败；模型引用无效拒绝发问；工具不可用明确报错
边界收口能力开放，但权限与配额始终生效所有对外入口共用 API Key、租户、限流、审计；副作用工具默认需审批
状态分层无状态应用 + 外置会话与索引应用可水平扩展；会话状态、向量索引、分布式锁放 Redis；业务数据放 MySQL
可回滚变更必须能退回上一稳定态工作流按版本快照运行；智能体配置有版本轨；文档支持版本回滚
可观测关键链路都留下证据运行 Trace、用量台账、审计链、巡检报告、通知与告警
2.2

系统分层架构

系统分为接入、编排、领域、基础设施与运行支撑五层。安全、租户、审计与配额作为横向能力贯穿所有层，而不是某一个模块的附属功能。

2.3

技术选型与取舍

选型遵循“成熟、可私有化、可替换”三个标准。每一项选择都伴随明确的权衡，而不是追求最新。

维度选择理由权衡
后端运行时Java 17 + Spring Boot 3.5企业内网成熟、生态完整、长期可维护启动与内存开销高于轻量语言
智能体引擎AgentScope Harness 会话引擎推理循环、工具派发、上下文压缩、续跑由框架统一接管领域能力需经适配层注入，存在学习成本
工作流引擎Spring AI Alibaba Graph（StateGraph）显式图执行、条件边、检查点与续跑能力完整与智能体会话引擎互相独立，需明确边界
向量存储Redis Stack（RediSearch）向量、会话状态、锁与限频一套基础设施解决硬依赖 Redis；容量规划需单独评估
关键词检索默认 MySQL，可选 Meilisearch零依赖开箱可用；规模上来后可切换中文分词引擎两套引擎需保持索引一致与可回退
关系数据库MySQL 8 协议兼容库部署普遍、运维熟悉、无数据库专有逻辑复杂检索能力有限，需应用层补足
前端Vue 3 + Vite + Ant Design Vue + Vue Flow组件成熟、画布生态可用、按页分包重交互页面需自绘组件保证一致性
文档解析POI / PDFBox / jsoup / 中文分词覆盖主流办公格式与网页正文，可离线运行扫描件依赖 OCR 服务，质量受源文件影响
部署Docker Compose / 容器编排私有化交付简单，依赖版本可控大规模集群需额外接入编排与监控体系
2.4

双引擎编排：会话与工作流各司其职

问渠内部有两套执行引擎：会话引擎负责长会话中的推理、工具与人在回路；工作流引擎负责显式图的确定性执行。两者共享能力，但不共享状态。

SESSION ENGINE

会话引擎适合什么

需求边界不清、需要多轮澄清、工具选择依赖模型判断、随时可能插入人工意见的长任务。

  • 日常问答与知识检索
  • 计划 / 目标模式的长任务
  • 子智能体按需委派
  • 断线续接与运行中插话
WORKFLOW ENGINE

工作流引擎适合什么

步骤固定、需要审核、需要精确回放与版本管理的业务流程，或需要被外部系统稳定触发的自动化。

  • 多步骤数据加工与报表
  • 带人工审核的审批流
  • 定时任务与事件触发
  • 对外提供稳定 API
2.5

问答与检索管线

一次问答不是“把问题丢给模型”，而是一条有明确质量闸门的管线：召回、融合、重排、组装、生成、工具执行、出口检查与计量。

关键机制WHY IT MATTERS

  • 统一引用编号：知识库、联网搜索与外部工具返回共用一套 [N] 编号，避免多来源各说各话。
  • 双门控制：融合门 0.5 与重排门 0.6 分别作用于不同阶段；重排执行过后，未经重排的候选不得经融合阈值进入上下文。
  • 低置信保底：低分全灭时保留唯一最高分块并显式标注，避免“隐性问答”被绝对阈值全部误杀；重排链路异常时不做保底。
  • 档位分流：聊天档不启沙盒，工作区档对接本机执行器，分享档只读；同一套管线按场景裁剪工具面。
  • 出口压尾：内容安全在流式生成时压住尾部若干字符再放行，命中拦截即截断并追加提示。
性能基线 简单问答在云上真实模型环境的整轮耗时实测约 1.4–1.6 秒；同一会话的后续轮次通常在 1 秒以内。长任务耗时主要取决于工具与人工审批，而非模型首包。
2.6

长任务执行模型

长任务被建模为两种可控模式：计划模式先出计划再执行，目标模式用一句话入队并自动续跑。两者都不是“让模型一直跑到结束”，而是有状态、有预算、有介入点的过程。

机制计划模式目标模式
启动方式本轮显式开启输入一句话目标即入队
推进方式用户确认后执行系统自动续跑
用户介入提意见升版、取消、执行中插话暂停、继续、修改原文、取消、插话让位
完成判定步骤执行完提交证据并逐条核验通过
失败处理保留当前卡与已执行记录转“已暂停”并写明原因
留痕版本轨、步骤级 diff、产物终态卡、轮次记录、证据清单
2.7

工作流引擎

工作流的核心不是画布，而是DSL 作为唯一事实源：画布负责编辑，校验器负责拦截，编译器负责翻译，引擎只按已发布的 DSL 快照执行。

NODE SAFETY

节点级安全约束

  • HTTP 请求：逐跳公网校验，读取上限 2MB
  • 代码执行：Python / Node 走隔离沙盒，非 0 退出码失败
  • 条件分支：受限表达式求值，禁用类型引用与构造器
  • 人工审核：挂起 → 裁决 → 按检查点续跑，已完成节点短路回放
  • 循环：最大圈数在编译期与运行期双重约束
  • 游客：只读节点集白名单，其余节点一律拒绝
RUN GOVERNANCE

运行治理

  • 单次运行超时与最大图步数可配
  • 并发上限与排队容量可配
  • 运行记录保留期可配
  • 终态回调带 HMAC 签名，不指向内网
  • 运行历史支持节点级 Trace 与甘特时间轴
  • 批量发布、下线、导出、删除与模板复用

2.9

安全与多租户架构

安全不是一道门，而是五层纵深：身份 → 授权 → 数据 → 运行 → 审计。任何一层单独失效，都不足以让越权发生。

层控制点实现要点
身份本地账号、OIDC、SAML 2.0、SCIM 2.0、LDAP、服务账号密码 PBKDF2 + 失败锁定；(provider, sub) 复合唯一防账号漂移；认证源密钥加密入库
授权角色-菜单 + 角色-接口两级 RBAC后端默认拒绝；未授权接口数量直接告警；资源按创建者与租户行级隔离
数据密钥、令牌、签名 URL模型 Key / 工具凭据 / 认证源密钥 RSA 加密；对外令牌只存 SHA-256；图片与产物走 HMAC 签名 URL
运行限流、配额、内容安全、沙盒、审批固定窗口限流超限 429；推理配额三档；输入输出双闸；隔离容器执行；副作用工具可设确认
审计统一事件与哈希链登录、配置、租户、成员、密钥、内容安全、运维动作全量记录；CSV 合规导出与链校验
TENANCY

租户隔离

租户键贯穿数据行、RBAC 快照、配额、限流、审计与备份。租户管理员只能看到自己一行，平台级动作仅平台管理员可执行。

SESSION

会话治理

强制下线通过会话代数 +1 实现，已签发令牌当场失效；改密、重置密码与离职踢出走同一机制。

SANDBOX

执行隔离

命令与文件读写发生在隔离容器；路径逐段校验并按真实路径比对前缀；越界写入直接拒绝。

4.1

演进路线

问渠的演进遵循“先把链路做通，再把质量做稳，最后把生态做开”的顺序。以下为对外可披露的能力方向，不构成交付承诺。

已交付 · 能力基线

完整链路与治理底座

对话与长任务、知识库与混合检索、智能体与工具、工作流与开放接入、多租户与企业身份、RBAC 与审计、评测与发布门禁均已落地。

近期

质量与开放深化

检索与评测闭环继续打磨；开放端点补齐更完整的工具调用能力；工作流模板与市场分发扩展；多副本部署与容量治理完善。

中期

协作与知识治理

智能体协作与工作区能力完整化；知识治理与图谱进一步结合；成本、配额与部门级运营视图精细化。

长期

企业级智能体平台

从“个人助手”走向“组织级智能体网络”：能力可组合、可复用、可度量，并在统一治理下持续演进。
