## 三种形态，一种凭据边界

| 层 | 谁持凭据 | 形态 | 承诺 | 什么时候用 |
|---|---|---|---|---|
| **L0** 零代码嵌入 | 分享 token（浏览器不持 Key） | `wenqu-embed.js` / iframe | **正式** | 官网 / 帮助中心 / 客服台放一个问答入口 |
| **L1** 前端深度集成 | 业务后端代理，浏览器零凭据 | `client.native` 事件协议（A 期后走 run 事件） | **实验性** | 自家前端要展示审批卡、产物、插话、计划 |
| **L2** 后端集成 | API Key / 服务账号（只在服务端） | v1 REST + webhook + MCP | **正式** | 业务后端、自动化流程、批处理 |

**凭据边界一句话**：API Key 只在服务端，浏览器零凭据。L1 + L2 可以共用同一个业务后端，Key 仍然不进浏览器。

## 选型问四句

1. 只想在自己页面上放一个问答入口？ → **L0**（分享 token，零代码）
2. 要嵌进自家前端，而且要展示审批、产物、计划过程？ → **L1**（业务后端代理，浏览器零凭据）
3. 由业务系统后端调用，或要把结果通过回调送回业务？ → **L2**（API Key + webhook）
4. 既要前端体验又要后端事件？ → **L1 + L2**，两者共用同一个后端，Key 仍然只在服务端。

## 承诺分级

- **正式** = 只增不删 + 变更日志 + 至少两个 minor 的废弃期。删端点、改 HTTP 方法、改 scope、
  改 `keyAccessible` 都算破坏性变更，CI 会挡下来。
- **实验性** = 字段可改，接口变更提前在本站公告。L1 先挂这个标签，run 契约冻结并稳定两周后转正。

为什么只正式承诺两层：三层全部正式会把维护面直接翻三倍，收益却在「少数要过程能力的前端」身上。

> 别把两种承诺混用：`chat/completions` 是**无状态、文本、收集型单块下发**的兼容面；
> 逐 token 真增量、长任务、人在回路**只在 run 原语上承诺**。

## 一张图看链路位置

```text
宿主页面（官网 / 门户 / 客服台）
  │  L0 嵌入  ·  L1 native
  ▼
业务后端（可选代理层，持 Key、注入登录态）
  │  L1 / L2
  ▼
问渠网关：API Key / 服务账号 / 分享 token
  · v1 注册表：未登记即拒绝 + scope
  · 限流桶 + 用量归因
  · v1 错误体统一 OpenAI 形状
  ▼
智能体引擎：技能 / MCP / HTTP / 工作流 / 知识库 / 审批 / 产物
```

## 每层的最小可跑样例

| 层 | 样例 | 跑起来看什么 |
|---|---|---|
| L0 | `samples/widget-static` | 一个 HTML 文件挂出浮窗，凭据只有分享 token |
| L1 | `samples/frontend-proxy` | 浏览器只与自家后端说话，转发 SSE，Key 不出服务端 |
| L2 | `samples/backend-node` | 建 run、订阅事件、验签收 `run.finished`、按 runId 幂等 |
| L2 | `samples/backend-python` | 混合检索 + 工作流触发 |
