# 工具说明（模型可见文案）写作口径

口径来源：DSH 的 `tool-design.md`（Desktop 安装包内
`app.asar/dsh/node_modules/@deepseek-ai/dsh-agent-preset/skills/dsh-doc/references/tool-design.md`），
按问渠的工具面结构落地为本文。

一句话：**工具说明是每一轮都要重付的固定上下文，写得长不等于教得会。**

## 五条口径

1. **首句 = 做什么 + 返回什么**。模型选工具时主要读这段，首句拎不清，后面写再多也白搭。
2. **边界跟行为写在一起**（同一句或紧随其后）：只读/有副作用/什么时候不该用。别指望模型读第三句。
3. **参数规则写在 `@ToolParam` 上**：默认值、范围、二选一、什么时候才设。说明里不重复这些。
4. **一条事实只说一次**：参数已交代的不在说明里复述；"这类活该用哪把工具"不进任何一把工具的说明。
5. **不写实现细节与呈现细节**：不写内部链路（怎么起客户端、怎么落凭据）、不写"界面会显示成卡片/红叉"、
   不写历史踩坑过程——那些属于代码注释。

## 问渠与 DSH 的结构差别（要紧）

DSH 每把工具可注册一段 system prompt section，工具本轮不在表里时那段自动为空，所以它的 description
能短到一句。问渠的系统提示词是**一整段固定人设**（`AgentService.BUILTIN_SYSTEM_PROMPT`），
没有 per-tool section，**说明是唯一通道**。因此：

- 边界、副作用、不适用场景必须留在 description 里（不能照抄 DSH 的一句话写法）；
- 例外只有一类：**跨工具/跨族的「该用谁」**，统一进 `ToolDiscipline.guidance(...)`，按本轮真挂上的
  工具名现拼，**绝不提本轮不存在的工具名**。当前覆盖五对：
  ①「本机」在 SSH 与桌面之间（含桌面族没挂时明说"不能操作"）；
  ②查什么走哪一路（知识 / 联网 / 历史正文 / 历史过程）；
  ③单件 vs `run_code` 批量；
  ④`askUser` 拍板 vs `writeTodo` 进度；
  ⑤`presentArtifact` 现写内容 vs `deliver_artifact` 已落盘文件。
  这些话**不要**写进任何一把工具的说明（一族的说明替另一族交代，只会两处都写、两处都漏）。

## 手段禁令：不要用"压缩说明"换 token

工具说明必须整段发给模型。压缩到首句会把边界切掉——只读工具会被当成"本机能力探针"来调用。

- 说明太长 → **在源头上写短**；
- 要省 token → 改提示词结构（分工段、按族收窄），**不要改模型看到的事实**；
- 任何"只改发出去的文本"的中间件，都要保证保序保量，并有测试钉住"模型看到的就是源码里写的"。

## 检查清单（加/改工具时逐条过）

- [ ] 首句 = 做什么 + 返回什么
- [ ] 边界（只读 / 副作用 / 不适用场景）在同一句
- [ ] 每个 `@ToolParam` 自带默认值、范围、二选一、何时设
- [ ] 没重复参数已说的事实；没写实现细节、UI 呈现细节
- [ ] 全文 ≤ 400 字（`ToolCopyDisciplineTest` 会拦；上限是护栏不是目标，当前最长 363）
- [ ] 没有「必须调用本工具 / 务必调用 / 凭记忆回答」这类元指令（同上单测会拦）
- [ ] 跨工具路由没写进来（要换工具，是 `ToolDiscipline` 或提示词的事）
- [ ] 改完回写账本 `references/roadmap.md`

## 相关落点

| 东西 | 位置 |
|---|---|
| 说明本体 | 各持有类的 `@Tool(description = …)`（`ToolRegistry` 反射核对名字，改名是破坏性变更） |
| 卡片展示名 / 悬停说明（**用户可见，不是模型可见**） | `ToolDescriptor` 的 `label` / `cardLabel` / `cardHint` |
| 跨族分工段 | `ToolDiscipline`（判据：`turnGroupedNames` ∪ 已激活的框架工具名；只读档/API Key 禁用沿用 `policy.deny`） |
| 机械护栏 | `ToolCopyDisciplineTest`（扫编译产物里的 `@Tool`，查非空 / ≤400 字 / 元指令）、`ToolDisciplineTest`、`SshChatToolTest` |
